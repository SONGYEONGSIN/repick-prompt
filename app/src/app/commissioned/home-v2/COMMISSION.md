## 기준 사이트 시각 언어 반영 (2026-08-16 2차)

1차 산출물은 **구조만 가져오고 시각 언어를 기존 것으로 뒀다** — 사용자가 기준 사이트를 다시 지목해 재작업했다.
`design-extractor.com` 을 히어로·카드 구역 두 지점에서 다시 촬영해 장치를 추출했다.

| 기준 사이트의 장치 | 우리 적용 |
|---|---|
| 전면 배경 격자선 | `home-v2.module.css` 의 `gridBg` (140px 셀). 전역 CSS 를 건드리지 않으려고 주문 폴더 안 모듈로 둠 |
| 헤드라인 위 필 배지 | `AI 초보자를 위한 프롬프트 빌더` 를 아이콘 + 필로 |
| 중앙 정렬 초대형 헤드라인 | 좌측 정렬 → 중앙, 자간 -0.03em |
| 알약형 입력창 + 원형 버튼 | 검색창을 필 형태로, 우측에 원형 액센트 버튼 |
| CTA 아래 카운터 필(`3/3 free this week`) | `34 라운드 진화 · AI 3심 블라인드 심사 · 0원` — 숫자는 볼트 실측값 |
| 카드 = 상단 시각 영역 + 구분선 + 라벨/제목/설명 | 동일 구조. **상단 시각 영역에 사진 대신 결과물 미리보기를 렌더** |
| 카테고리 라벨 앞 세로 막대 | 동일 |

**핵심 번역 지점**: 기준 사이트는 카드 상단에 추출 대상의 스크린샷을 넣는다. 우리는 이미지가 없다 —
그 자리에 **실제 심사 산출물(33종) 또는 출력 형식(나머지)** 을 작은 모노로 렌더해 문서 미리보기처럼 보이게 했다.
형태는 기준 사이트를 따르고 내용은 100% 우리 것이며, 감사에서 가장 어려웠던 Q3(텍스트뿐인 43종 구분)의 답이기도 하다.

히어로가 중앙 정렬로 길어지면서 카드가 fold 밖으로 밀려, 설명 문단을 덜어내고 여백을 줄여
1280×900 첫 화면에 **카드 미리보기와 분류 라벨까지** 들어오게 조정했다(제목은 바로 아래).

## 3차 — 라이트/다크 · 자체 헤더 · 미리보기 드로어 (2026-08-16)

**라이트/다크**: 앱의 `globals.css` 는 다크 토큰만 정의한다. 거기에 라이트를 더하면 주문 폴더 밖을 건드리므로,
토큰(`--bg`·`--fg`·`--mut`·`--acc`·`--panel`·`--line`)을 **모듈의 `.root` 래퍼에 다시 선언**했다.
Tailwind 의 `bg-bg` 는 `var(--color-bg)` → `var(--bg)` 로 use-site 에서 풀리므로 하위 전체가 래퍼 값을 따른다.
3상태를 모두 다룬다 — 시스템(속성 없음) / `[data-theme="light"]` / `[data-theme="dark"]`.

그래서 **공용 `SiteHeader` 를 쓰지 않는다.** 헤더가 래퍼 밖에 있으면 본문만 라이트가 되고 헤더는 다크로 남는다.
자체 헤더를 두니 기준 사이트의 헤더 구성(로고 좌 · 우측 링크 + 테마 토글)과도 오히려 가까워졌다.
토글은 시스템 → 라이트 → 다크 순환이고 현재 상태를 아이콘(Monitor/Sun/Moon)으로 드러낸다.

**카드 외의 방법 — 미리보기 드로어**: "카드에 결과물"만으로는 카드 안에 7줄밖에 못 넣는다.
카드 상단 미리보기는 그대로 두고(훑기용), 카드의 `결과물 미리보기` 버튼이 **드로어로 전문 발췌를 연다**(정독용).
분할 탐색(좌 목록 + 우 페인)도 후보였으나 기준 사이트의 그리드 구성을 깨서 채택하지 않았다.
드로어는 `role="dialog"` + `aria-modal` + `aria-labelledby`, Esc 로 닫히고, 진입 애니메이션은 `prefers-reduced-motion` 에서 없다.

카드의 주 동작을 둘로 나눴다 — **제목·`쓰기` 는 템플릿으로**, **`결과물 미리보기` 는 드로어로**. 카드 전체를 링크로 감싸면
드로어 버튼이 링크 안에 중첩돼 접근성이 깨지기 때문이다.

## 측정 도구 함정 (기록해 둘 것)

`--window-size=390` 으로 찍은 첫 스크린샷에서 화면이 잘려 390px 오버플로로 오판했다. 실제로는
macOS Chrome 이 창 최소 폭(~500px)을 강제해 **500px 레이아웃을 390px 로 잘라낸** 것이었다. 구형 헤드리스도 같다.
진짜 측정은 CDP `Emulation.setDeviceMetricsOverride` 로 뷰포트를 강제해야 나온다 — 스크린샷 폭을 뷰포트 폭으로
믿으면 안 된다.
