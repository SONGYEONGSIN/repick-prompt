# RE:PROMPT 진화 — `reprompt` 메타프롬프팅 스킬 설계 (스코프 A + B)

> 작성일: 2026-07-21 · 상태: 승인됨(설계) → 구현 계획 대기
> 브랜치: `feat/reprompt-meta-prompting`

## 배경

현재 RE:PROMPT는 **템플릿 공장 + 뷰어**다 — 진화 루프(`prompt-evolve`)가 검증된 빈칸형 템플릿을 생산하고, `vault/00-principles/prompt-principles.md`의 **프롬프트 DNA(v1.14)**로 품질을 관리한다.

목표 진화는 **메타프롬프팅 런타임**을 추가하는 것이다 — 사용자가 실시간 대화 맥락을 던지면, 그 자리에서 DNA 기준으로 맞춤 프롬프트를 깎아 파일로 산출하고, 그 프롬프트로 실제 작업까지 실행·점검한다. 4개 참조 이미지(핵심 3단계 / 질문 유도 / 성공조건 명시 / 실행환경 변환)의 흐름을 구현한다.

### 기존 설계 대조 (진화 이유)

| 개념(이미지) | 기존 설계 여부 | 격차 |
|---|---|---|
| 성공조건 명시(#4) | ✅ DNA 핵심(요구사항=검증가능 기준, anti-slop) | 재사용 |
| 질문 유도(#3) | △ 필드로 박제·"후속 질문형"은 R6·R7에서 은퇴 | 런타임 실시간 질문 재도입 |
| 실행환경 변환(#5) | △ 도메인별 부분(네거티브/추정표시) | Goal/Ultracode 미설계, 이미지·리서치 풀스펙 필요 |
| 핵심 3단계(#1) | △ 점검(AUTO-SCORE)만 제작자용 존재 | 컨텍스트 덤핑·맞춤 프롬프트 깎기 런타임 부재 |

## 스코프

- **포함(A+B)**: `reprompt` 스킬 — 컨텍스트 덤핑 → 질문 유도 → 프롬프트 깎기 → 실행환경 변환 → 게이트 → 실행 → 점검 → `.reprompt/` 폴더에 파일 산출.
- **제외(후속 spec)**:
  - **C. 플러그인 패키징** — 이 레포를 Claude Code 플러그인(manifest·marketplace)으로.
  - **D. 릴리즈 워크플로우** — semver·CHANGELOG·git tag 자동화.
  - 웹앱 UI(스코프 A의 웹 표면), 메타프롬프팅 세션의 DNA 자동 역류 학습.
- **빌드 순서**: A(+B) → C → D. 각 서브시스템은 자체 spec→plan→구현 사이클.

## 아키텍처 결정

**인라인 단계형(접근 1)** 채택. 스킬이 메인 에이전트를 6단계로 안내한다.

- 근거: 이미지 #3 "질문 유도"는 사용자와의 실시간 대화를 전제한다. 서브에이전트는 사용자에게 직접 질문할 수 없으므로, 덤핑·질문·게이트 단계는 인라인이라야 자연스럽다.
- 여지: 실행(4단계)이 무거우면 서브에이전트로 분리 가능하게 설계하되, v1 기본은 인라인.

## 호출 인터페이스

```
/reprompt <작업>
```

| 인자 | 의미 | 기본값 |
|---|---|---|
| `<작업>` | 타깃 작업. 생략 시 대화 맥락에서 추론 | (필수 또는 추론) |
| `--target general\|coding\|image\|research` | 실행환경 강제 | 작업에서 자동 감지 |
| `--auto` | HUMAN GATE 생략(가정 기록 후 진행) | off |
| `--out <dir>` | 산출 폴더 경로 | `.reprompt/<날짜>-<slug>/` |

## 6단계 파이프라인

### 0. 컨텍스트 덤핑 (이미지 #1-①)
- 대화 + `<작업>` 인자 + (레포 내 실행 시) 관련 파일을 수집해 **의도 브리프**로 정리: 목표 / 대상 / 제약 / 보유 실데이터·자료.
- **RETRIEVE**: DNA 전문(`prompt-principles.md`) + 가장 가까운 기존 참조(`templates.ts` 또는 `10-references`) 2~4개를 참조 앵커로 로드. 라이브러리는 **참조**로만 쓰고 맞춤으로 깎는다(복제 아님).

### 1. 질문 유도 (이미지 #3)
- 의도 브리프 ↔ DNA 필수 빈칸을 대조해 **빠진 것만** 한 배치(≤4)로 질문한다(과잉 심문 금지):
  타겟 사용자 / 핵심 목표·기능 / 톤·디자인 레퍼런스 / 완성도 수준 + 도메인이 요구하는 실데이터 빈칸(DNA "결과물 실데이터는 필수 빈칸").
- `--auto`: 질문을 건너뛰고 최선 추정 + **가정을 BRIEF.md에 명시 기록**.

### 2. 프롬프트 깎기 (이미지 #1-②·#4)
- DNA 4요소 뼈대(역할 / 맥락 / 요구사항 / 출력형식) 위에 조립.
- **성공조건 명시**: 모호한 목표를 검증 가능한 요구사항으로 변환. 형용사만 있는 요구("개쩌는 X") 차단.
- 도메인에 맞는 DNA 장치 배치: 프레임워크 내장 / 근거 요구 / 네거티브 조건 / 발산→수렴 / 행동 착지.

### 2b. 실행환경 변환 (이미지 #5, 스코프 B)
타깃별 오버레이. 타깃은 작업에서 자동 감지하되 `--target`으로 override.

| 타깃 | 오버레이 |
|---|---|
| `general` | DNA 4요소 그대로(글쓰기·기획·문서) |
| `coding` | **Goal Prompt = 중지 요건 명시**(완료/멈춤 조건) + **Ultracode = 제약 조건 명시**(범위 확장 금지, 건드릴 파일, 테스트 게이트) |
| `image` | 구도 / 피사체 / 스타일 / 조명 / 카메라 방향 + 네거티브 조건 |
| `research` | 출처 기준 / 조사 범위 / 검증 방식 + 추정 표시 |

### 3. HUMAN GATE (이미지 #1-③ 전반 — 프롬프트 검토)
- 깎은 프롬프트 + "왜 이렇게 깎았나"(DNA 근거 요약) + 세운 가정을 제시. 사용자 승인 / 수정 / 거부.
- `--auto`: 자동 승인하고 되돌릴 수 있음을 완료 보고에 명시.

### 4. 실행
- 승인된 프롬프트를 그대로 실행해 실제 결과물 생성. `OUTPUT.md`에 저장.

### 5. 점검 (이미지 #1-③ 후반)
- 결과물을 **깎은 프롬프트가 선언한 성공조건** + DNA anti-slop(형용사만·환각/과장·미충전 실데이터)으로 자가 점검. 체크리스트로 pass/격차 기록.
- 격차 발견 시 1회 정제(refine) 제안.

## 산출물 — `.reprompt/<YYYY-MM-DD>-<작업-slug>/`

| 파일 | 내용 |
|---|---|
| `BRIEF.md` | 의도 브리프(덤핑 + 질문 답변 + 가정) |
| `PROMPT.md` | ★ 깎아낸 즉시 사용 프롬프트 (핵심 산출물) |
| `RATIONALE.md` | DNA 매핑 — 어떤 장치를 왜 썼나(쓰면서 배우기) |
| `OUTPUT.md` | 실행 결과물 |
| `INSPECTION.md` | 성공조건 체크리스트 + 격차 |
| `meta.json` | `{작업, target, dna_version, created_at, files[]}` |

## 플러그인 이식성 (→ 스코프 C 다리)

- 스킬이 DNA 사본(`prompt-principles.md`)을 **번들**로 지녀 어느 레포에서도 동작한다.
- 단 이 레포(repick-prompt) 안에서 실행할 땐 살아있는 vault DNA(더 최신)를 우선 사용한다.
- 산출 경로 `.reprompt/`는 현재 작업 디렉토리 기준이라 vault 경로에 의존하지 않는다.

## 에러 처리 (프로젝트 규칙 준수)

- 작업·대화 모두 비면 → 추측 없이 작업을 되묻는다.
- DNA 필수 실데이터 부재 → `[확인 필요]`로 남기고 **창작 금지**(DNA raw 창작 금지 규칙).
- 쓰기 불가 디렉토리 → 스크래치 폴백 + 실제 경로 보고.
- 실행 실패 → 부분 저장 + `INSPECTION.md`에 실패 명시. **점검 없이 성공 주장 금지**(verification 규칙).

## 검증 계획 (spec 완료 후 실제 실행)

- **스모크**: `/reprompt "콜드 아웃리치 이메일"` → `.reprompt/...`에 6개 파일 생성, `PROMPT.md`가 4요소 구조 보유 확인.
- **레드 체크**: `/reprompt "개쩌는 랜딩 만들어줘"` → 질문 유도 발동 + `PROMPT.md`에 형용사 대신 검증 가능 요구사항 존재 확인.
- **타깃 변환 체크**: `--target coding` → `PROMPT.md`에 중지 요건 + 제약 조건 섹션 존재 확인.
- 결정적 파일 조작이 필요하면 `scripts/reprompt-*.mjs` 추가(기존 `scripts/` 패턴 계승). 판단 로직은 스킬 지시문에 둔다.

## 유닛 경계 (설계 명료성)

- **스킬 지시문**(`.claude/skills/reprompt/SKILL.md`): 6단계 흐름·질문·게이트·판정 — 판단이 필요한 부분.

- 각 유닛은 독립적으로 이해·테스트 가능해야 한다.

## 미해결/후속

- 스코프 C(플러그인 패키징), D(릴리즈)는 A 승인·구현 후 별도 spec.
- 메타프롬프팅 세션 로그가 향후 진화 루프의 학습 입력이 될 수 있으나 v1 제외(런타임/진화 루프 분리 유지).
