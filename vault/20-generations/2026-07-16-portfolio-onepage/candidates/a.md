## template

```
당신은 인터랙티브 원페이지 포트폴리오를 수없이 만들어온 프론트엔드 개발자이자 포트폴리오 에디터입니다. 당신의 유일한 목표는, 열람자가 스크롤을 멈추지 않고 끝까지 내려가 마지막 연락 버튼을 누르게 만드는 것입니다.

아래 정보를 바탕으로, 코드를 모르는 사람이 파일 하나만 열면 작동하는 인터랙티브 포트폴리오 원페이지를 만들어주세요.
- 이름과 한 줄 소개: {{owner_intro}}
- 이 페이지를 볼 사람과 바라는 행동: {{audience_goal}}
- 보여줄 작업물: {{projects}}
- 경력·강점: {{strengths}}
- 연락 방법: {{contact}}
- 화면 분위기: {{mood}}
- 넣고 싶지 않은 것: {{avoid}}

요구사항:
1. 모든 코드(HTML·CSS·JavaScript)를 외부 라이브러리·폰트·CDN 없이 바닐라로만 작성해 하나의 .html 파일에 담아주세요. 인터넷이 끊겨도 더블클릭만으로 작동해야, 코드를 모르는 사람이 받자마자 확인하고 그대로 전달할 수 있기 때문입니다.
2. 페이지는 첫 화면(이름과 한 줄 소개, 아래로 내려가도록 안내하는 표시) → 작업물 → 소개·강점 → 연락 순서의 한 흐름으로 만들어주세요. 포트폴리오의 종착지는 감상이 아니라 연락이므로, 마지막 섹션은 위 "바라는 행동"을 요청하는 큰 버튼 하나로 끝나야 합니다.
3. 스크롤을 내리면 각 섹션과 카드가 은은하게 떠오르듯 나타나게 해주세요(투명도와 위치가 0.5초 안팎으로 변하는 정도). 움직임은 시선을 다음 내용으로 끌어내리는 장치일 뿐, 효과가 화려하면 작업물 대신 효과만 기억에 남기 때문입니다. 운영체제의 '동작 줄이기' 설정을 켠 방문자에게는 애니메이션 없이 바로 보이게 해주세요.
4. 작업물은 카드 목록으로 보여주고, 카드를 클릭하면 그 자리에서 상세 내용(맡은 일 → 어떻게 했는지 → 결과)이 부드럽게 펼쳐졌다 다시 접히게 해주세요. 열람자는 전부 읽지 않고 훑다가 관심 가는 것만 깊게 보기 때문에, 목록은 가볍게 두고 상세는 클릭한 사람에게만 보여주는 구조가 열람자의 시간을 존중합니다.
5. 화면 상단에 얇은 고정 메뉴를 두고, 누르면 해당 섹션으로 부드럽게 이동하며 지금 보고 있는 섹션이 메뉴에 표시되게 해주세요. 긴 원페이지에서 내가 어디쯤 있는지 보이면 끝까지 내려갈 확률이 올라가기 때문입니다.
6. 마우스를 올렸을 때의 반응은 카드가 살짝 떠오르거나 버튼 색이 미세하게 진해지는 정도로 절제해주세요 — 호버는 "눌러도 된다"는 신호이지 구경거리가 아니기 때문입니다. 휴대폰에는 호버가 없으므로 모든 인터랙션(카드 펼침·메뉴 이동·연락 버튼)은 터치만으로 완전히 작동해야 하고, 눌러도 아무 일도 일어나지 않는 장식용 버튼은 하나도 만들지 마세요.
7. 외부 이미지 주소나 스톡사진은 넣지 마세요 — 존재하지 않는 주소는 깨진 그림으로 나타나 첫인상에서 신뢰를 깎기 때문입니다. 각 작업물 카드의 표지는 프로젝트 이름과 어울리는 색 블록과 타이포그래피로 만들고, 나중에 진짜 이미지로 바꿀 자리를 코드 주석 <!-- 여기에 실제 이미지 --> 로 표시해주세요.
8. 페이지의 모든 문구는 위에 적힌 내용만 재료로 써주세요. 적히지 않은 성과·수치·고객 후기·경력을 지어내면, 면접이나 미팅에서 본인이 답하지 못하는 페이지가 되기 때문입니다. 결과 숫자가 없는 작업물은 숫자 없이 한 일 자체로 담백하게 서술해주세요.
9. 완성한 뒤 출력하기 전에, 위 "이 페이지를 볼 사람"이 되어 처음부터 끝까지 스크롤해 보고 "연락을 망설이게 만드는 지점" 3가지를 찾아 고친 최종본만 출력해주세요 — 외부 피드백을 받기 전에 한 바퀴를 프롬프트 안에서 먼저 도는 것입니다. 단, 고치는 과정에서 위에 적히지 않은 새로운 사실이나 숫자를 추가하는 방식의 수정은 금지합니다.

출력 형식:
- 완성된 단일 HTML 파일의 전체 코드 (생략이나 "…이하 동일" 없이, 복사해서 붙여넣기만 하면 되는 완전한 코드)
- 파일 여는 법 3단계: 메모장(텍스트 편집기)에 붙여넣기 → "포트폴리오.html" 이름으로 저장 → 저장한 파일 더블클릭
- 진짜 이미지로 바꾸는 법: 표시해둔 주석 자리에 내 사진·화면 캡처를 넣는 방법을 코드를 몰라도 따라 할 수 있게 안내
- 공유 전 체크리스트 4개: 모든 카드를 눌러 펼쳐지는지, 연락 버튼이 실제로 연결되는지, 휴대폰에서 열어봤는지, 이름·연락처 오탈자는 없는지
- 검증 메모: 어떤 망설임 지점 3가지를 찾아 어떻게 고쳤는지 각 한 줄 (위 정보에 없는 새 주장·수치는 이 메모에도 쓰지 마세요)
- 수정 요청 예시 문장 3개 (예: "방금 그 파일에서 첫 화면 배경색만 남색으로 바꿔줘")
```

## anatomy

| part | quote | why |

| 역할 | "열람자가 스크롤을 멈추지 않고 끝까지 내려가 마지막 연락 버튼을 누르게 만드는 것입니다." | 역할에 직업만 주면 AI는 "예쁜 페이지"를 목표로 삼아 효과를 과시합니다. 목표를 "끝까지 내려가 연락 버튼을 누르게"로 고정하면, 리빌·카드 확장·앵커 같은 모든 인터랙션이 스크롤을 이어가게 하는 수단으로 정렬됩니다. |
| 맥락 | "이 페이지를 볼 사람과 바라는 행동: {{audience_goal}}" | 포트폴리오는 특정 대상 1인을 움직이는 문서입니다. 이 빈칸이 마지막 연락 버튼의 문구·페이지 말투를 그 사람에게 맞추고, 자기검증 루프(요구사항 9)의 조준경이 되어 "누구의 망설임을 찾을지"를 특정합니다 — 없으면 어디에나 보낼 법한 페이지가 됩니다. |
| 요구사항 | "스크롤을 내리면 … 떠오르듯 나타나게 / 카드를 클릭하면 그 자리에서 상세가 펼쳐졌다 접히게 / 고정 메뉴 … 부드럽게 이동 / 호버는 … 절제" | 이 후보의 정체성입니다. 인터랙티브 포트폴리오에서 검증된 인터랙션 문법 4가지를 빈칸으로 묻지 않고 요구사항 문장으로 내장했습니다. 초보자가 "인터랙티브하게"라고밖에 표현하지 못해도, 리빌·카드 확장·앵커·절제 호버가 입력 품질과 무관하게 구조적으로 보장됩니다. 각 줄의 이유("시선을 끌어내리는 장치", "열람자의 시간 존중")가 AI의 세부 판단까지 같은 방향으로 일반화시킵니다. |
| 출력 형식 | "파일 여는 법 3단계 → 진짜 이미지로 바꾸는 법 → 공유 전 체크리스트 4개 → 검증 메모 → 수정 요청 예시 3개" | 코드만 주면 초보자는 여는 법에서 멈추고, 색 블록 표지를 실제 이미지로 못 바꿔 미완성인 채 공유합니다. 여는 법·이미지 교체·점검·다음 수정 요청까지 한 세트로 받아야 "오늘 바로 보낼 수 있는" 착지가 완성됩니다. 검증 메모에는 새 주장 금지 단서를 달아, 메모가 과장의 온상이 되는 것을 봉쇄합니다. |

## tips

1. **작업물은 개수보다 '결과 한 줄'로 고르세요.** 결과가 흐릿한 카드 4개보다 "구독자 0→2,400명"처럼 결과가 선명한 카드 2개가 강합니다. 결과가 숫자가 아니어도 됩니다 — "클라이언트가 재계약했다", "이 글이 회사 공식 계정에 소개됐다" 같은 사실이면 충분하고, 기억나지 않는 숫자는 지어내지 말고 비워두세요.
2. **공유 전에 휴대폰으로 열어 모든 카드를 눌러보세요.** 채용 담당자와 클라이언트 다수는 폰으로 먼저 봅니다 — 카드가 안 펼쳐지면 그 작업물은 없는 것과 같습니다. 고칠 곳이 보이면 처음부터 다시 만들지 말고 "방금 그 파일에서 두 번째 카드 제목만 바꿔줘"처럼 한 곳씩 지목해 요청하세요. 잘 되던 부분까지 어긋나는 일을 막아줍니다.
