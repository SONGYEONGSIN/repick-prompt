## template

```
당신은 수백 개의 포트폴리오를 심사해본 크리에이티브 디렉터이자, 코드를 모르는 사람을 위해 단일 HTML 원페이지를 만드는 프론트엔드 개발자입니다. 당신의 유일한 목표는, 이 포트폴리오를 볼 단 한 사람이 첫 화면 3초 안에 "누구이고 무엇을 하는 사람인지" 이해하고, 끝까지 내려가 연락 버튼을 누르게 만드는 것입니다.

아래 정보를 바탕으로, 브라우저에서 바로 열리는 인터랙티브 원페이지 포트폴리오를 만들어주세요.
- 누구이고 무엇을 하는 사람인지: {{intro}}
- 이 포트폴리오를 볼 사람과 그가 확인하고 싶은 것: {{audience}}
- 대표 작업 (이름 / 내가 한 일 / 결과): {{projects}}
- 일하는 방식과 강점 (사례 포함): {{strengths}}
- 연락 방법과 유도할 행동: {{contact}}
- 경력·이력 사실: {{career_facts}}
- 페이지 분위기: {{mood}}
- 넣지 않았으면 하는 것: {{avoid}}

요구사항:
1. 첫 화면에는 이름과 "누구이고 무엇을 하는 사람인지" 한 문장, 그리고 아래 대표 작업으로 내려가게 하는 안내 하나만 두세요. 보는 사람은 수십 개의 포트폴리오를 연달아 열며 3초 안에 계속 볼지를 정하기 때문입니다.
2. 섹션은 첫 화면 → 대표 작업 → 일하는 방식과 강점 → 연락 순서로 배치하고, 번호나 구조 표시 없이 자연스럽게 이어지는 한 페이지로 만들어주세요. 이 순서가 "누군지 안다 → 실력을 확인한다 → 같이 일할 사람인지 본다 → 연락한다"라는 심사자의 판단 순서와 같기 때문입니다.
3. 대표 작업은 입력된 것만, 입력된 개수 그대로 실어주세요. 개수를 채우려고 가짜 프로젝트를 만들면 "이건 어떤 프로젝트였어요?"라는 확인 질문 한 번에 포트폴리오 전체의 신뢰가 무너지기 때문입니다.
4. 각 대표 작업의 설명은 위 "볼 사람이 확인하고 싶은 것"에 답하는 문장이 맨 앞에 오도록 써주세요. 어디에나 낼 수 있는 포트폴리오는 아무에게도 "나를 위해 온 사람"이라는 인상을 주지 못하기 때문입니다.
5. 인터랙션은 "더 알고 싶은 사람이 스스로 더 깊이 들어가는" 용도로만 넣어주세요 — 대표 작업 카드를 누르면 맡은 역할·과정·결과가 펼쳐지는 방식처럼요. 눌러도 새 정보가 없는 장식 효과나 시선을 뺏는 배경 애니메이션은 넣지 마세요. 인터랙션의 목적은 화려함이 아니라 바쁜 심사자가 원하는 깊이만큼만 확인하게 하는 것이기 때문입니다.
6. 입력에 없는 수치·고객사·수상·경력을 절대 만들어 넣지 마세요. 결과가 숫자로 입력되지 않은 작업은 그럴듯한 숫자로 메꾸지 말고 입력된 표현 그대로 담백하게 쓰세요. 포트폴리오의 과장 한 줄은 면접과 미팅에서 반드시 검증 질문으로 돌아오기 때문입니다.
7. 모든 코드(HTML·CSS·JavaScript)를 단일 .html 파일에 담아, 설치나 인터넷 연결 없이 더블클릭만으로 열리고 휴대폰 화면에서도 잘 보이게 만들어주세요. 코드를 모르는 사람이 이 파일을 그대로 보내고, 받은 사람이 그대로 열 수 있어야 하기 때문입니다.
8. 이미지 파일을 넣으라고 요구하지 말고, 색·타이포그래피·도형만으로 각 작업 카드가 완성되어 보이게 디자인해주세요. 파일 경로 연결은 코드를 모르는 사람이 가장 먼저 막히는 지점이라, 이미지가 필수면 이 포트폴리오는 영원히 미완성으로 남기 때문입니다.
9. 페이지가 완성되면 위 "볼 사람" 바로 그 1인이 되어 처음부터 끝까지 읽고, "왜 이 사람을 안 뽑을까 / 왜 이 사람에게 안 맡길까" 싶은 저항 지점 2곳을 찾아 고친 최종본만 출력하세요. 외부 피드백을 받기 전에 가장 아픈 질문을 미리 통과시키는 것이 이 페이지의 성패를 가르기 때문입니다. 단, 고칠 때 입력에 없는 새 사실이나 주장을 추가하지 말고 배치와 표현만 바꿔 해소하세요 — 저항을 없애려고 지어낸 한 줄이 새 저항이 되기 때문입니다.

출력 형식:
- 완성된 단일 HTML 파일의 전체 코드 (생략이나 "…이하 동일" 없이, 복사해 붙여넣기만 하면 되는 완전한 코드)
- 여는 법과 보내는 법: 코드를 몰라도 따라 할 수 있게 4단계로 (메모장·텍스트 편집기에 붙여넣기 → "포트폴리오.html"로 저장 → 더블클릭해 확인 → 이메일·메신저에 파일 첨부해 보내기)
- 자기검증 메모 (페이지 본문과 분리): 찾아 고친 저항 2곳을 "걸린 문구(원문 인용) → 볼 사람이 느꼈을 저항 → 어떻게 고쳤나"로 정리하되, 위 입력에 있는 표현만 인용하고 새 주장을 덧붙이지 마세요
- 나중에 실제 작업 사진을 넣고 싶을 때 AI에게 요청할 예시 문장 2개
- 보내기 전 셀프 체크 3개 (연락 버튼이 실제로 눌리는지, 휴대폰에서 깨지지 않는지, 오탈자는 없는지)
```

## tips

1. **"볼 사람" 칸을 바꿔가며 대상별 버전을 만드세요.** 같은 작업이라도 채용 담당자용과 클라이언트용은 강조할 첫 문장이 다릅니다. 지원처·거래처가 바뀔 때마다 {{audience}} 칸만 고쳐 다시 돌리고, 파일명을 "포트폴리오_○○용.html"처럼 대상별로 저장해두면 하나의 템플릿으로 과녁이 다른 여러 페이지를 운용할 수 있습니다.
2. **보내기 전에 '3초 테스트'를 하세요.** 주변 사람에게 첫 화면만 3초 보여주고 "이 사람 뭐 하는 사람 같아?"라고 물어보세요. 못 맞히면 다른 걸 고치기 전에 "누구이고 무엇을 하는 사람인가" 한 줄부터 다시 쓰세요 — 첫 화면에서 이해받지 못한 페이지는 아무리 인터랙션이 좋아도 스크롤되지 않습니다.
