- **재현 시도 결과 인용**: "시도 1: … 카드 소실 0회." / "시도 2: … 카드 소실 4회." / "시도 3: … 카드 소실 1회." / "시도 4: … 카드 소실 0회." / "시도 5: … 카드 소실 0회."
- **신뢰도 등급**: 중 (로그 전체 발생률과 재현 시도 수치는 원문 인용 가능하나, 신고자 본인의 실제 탭 사용 패턴은 원문·로그에 명시되어 있지 않아 "거의 매번"이 신고자 개인 기준으로 정확히 무엇을 뜻하는지는 특정되지 않음)
- **[추정/계산 표시]**: (계산: 52건/340건 ≈ 15.3%, 전체 드래그 이벤트 기준) (계산: 가장 소실률이 높았던 시도 2도 4회/10회 = 40%로, 시도한 어떤 조건에서도 10회 중 절반 이상 소실되지는 않음)
- **최종 판정**: 재현 안 됨 — 전체 이벤트 대비 발생률(계산: 약 15.3%)과 재현 시도 중 가장 높은 소실률(계산: 40%) 모두 "거의 매번"에 해당한다고 보기 어려움.

### 3. 새로고침해도 카드가 복구되지 않고 작업 내용이 통째로 날아감

- **신고 항목 인용**: "새로고침해도 카드가 다시 안 나타나서 작업 내용이 통째로 날아간 것 같다고 하시는 분도 있어요."
- **로그 근거 인용**: "52건 전부에 대해 서버 DB 조회 로그를 확인한 결과 카드 레코드는 52건 전부 정상 존재(status=200, 데이터 유실 없음) — 화면에서만 사라졌을 뿐 DB에는 남아있었다."
- **재현 시도 결과 인용**: "소실 직후 새로고침하면 카드가 다시 정상적으로 나타남 (DB 조회 결과 정상, 데이터 유실 아님)." (시도 2) / "새로고침 시 정상 복구." (시도 3)
- **신뢰도 등급**: 상
- **[추정/계산 표시]**: 해당 없음
- **최종 판정**: 재현 안 됨 — 로그와 재현 시도 모두 새로고침 시 카드가 정상 복구되고 DB상 데이터 유실이 없음을 일관되게 보여줌.

### 4. 모바일 앱에서도 동일한 문제가 발생함

- **신고 항목 인용**: "모바일 앱에서도 똑같은 문제가 있다고 하는 사용자가 한 명 있었습니다."
- **로그 근거 인용**: "모바일 앱(iOS/Android) 클라이언트에서 발생한 card_render_missing 이벤트는 지난 7일간 0건."
- **재현 시도 결과 인용**: "시도 5: Android 앱(삼성 갤럭시 S23), 탭 개념 없음(단일 앱 세션), 카드 10회 드래그 — 카드 소실 0회. iOS 실기기가 없어 iOS 앱은 시도하지 못함."
- **신뢰도 등급**: 중 (Android에 대해서는 로그·재현 시도 모두 원문 인용 가능한 근거가 있으나, iOS는 재현 시도 자체가 이루어지지 않아 신고 항목 전체를 뒷받침하거나 부정할 근거가 없음)
- **[추정/계산 표시]**: 해당 없음
- **최종 판정**: 판정 불가(추가 확인 필요) — Android에서는 로그(0건)와 재현 시도(10회 중 0회) 모두 재현되지 않았으나, 신고자가 언급한 사용자가 iOS와 Android 중 어느 쪽을 사용했는지 원문에 명시되어 있지 않고 iOS 실기기 재현 시도가 이루어지지 않아, iOS 케이스에 대해서는 판정할 근거가 없음.

## 재현 시도 환경

MacBook Pro(macOS), Safari 17.4 및 Chrome 124, 태스크플로우 웹앱 v3.8.2, 테스트 계정 2개(동일 워크스페이스). Android 실기기(삼성 갤럭시 S23) 1대. iOS 실기기는 보유하지 않음.

# 버그 재현 절차 보고서 — 칸반보드 카드 드래그 시 카드 사라짐 (card_render_missing)

조건 가설 4개 중 채택 2 · 기각 1 · 미확인 1 — **부분 재현**(특정 조건 조합에서만 재현되며, 서버 DB 데이터 유실은 없음)

## 조건 가설 목록 (판정 전, 후보)

1. 브라우저 종류(Safari 여부)가 재현을 가른다.
2. 동시 접속 탭(멀티탭) 수가 재현을 가른다 — 탭 2개 이상일 때만 재현된다.
3. 계정 조건 — 동일 계정으로 여러 탭을 열었는지 여부가 재현을 가른다.
4. 플랫폼(웹 vs 모바일 앱) 여부가 재현을 가른다 — 모바일 앱에서는 재현되지 않는다.

## 가설 검증 카드

### 1. 브라우저 종류(Safari 여부)가 재현을 가른다

- 뒷받침 시도: "시도 2: Safari 17.4, 같은 계정으로 탭 2개 동시에 열고 카드 10회 드래그 — 카드 소실 4회"는 "시도 3: Chrome 124, 같은 계정으로 탭 2개 동시에 열고 카드 10회 드래그 — 카드 소실 1회"보다 소실 횟수가 많아, Safari 쪽이 상대적으로 더 잘 재현되는 경향은 있음.
- 반박 시도: "시도 3: Chrome 124, 같은 계정으로 탭 2개 동시에 열고 카드 10회 드래그 — 카드 소실 1회. 새로고침 시 정상 복구" — Chrome에서도 동일 조건(탭 2개+동일 계정)에서 재현이 발생함. 즉 Safari가 아니어도 재현됨.
- 로그 상관관계: "User-Agent 분석: 52건 중 38건 Safari, 9건 Chrome, 5건 로그 누락." Safari 비중이 높지만 (계산: 38/52 ≈ 73.1%, Chrome 9/52 ≈ 17.3%), 이는 Safari 전용 재현을 뒷받침하는 근거가 아니라 두 브라우저 모두에서 발생했다는 근거이기도 함.
- [추정: 브라우저 종류는 재현 빈도(발생률) 차이에는 영향을 줄 수 있으나, raw 데이터만으로는 그 원인을 알 수 없음]
- 판정: **기각** — 두 브라우저 모두 동일 조건(탭 2개+동일 계정)에서 재현되었으므로, 브라우저 종류 자체는 재현 여부를 온/오프로 가르는 경계가 아님.

### 2. 동시 접속 탭(멀티탭) 수가 재현을 가른다 — 탭 2개 이상일 때만 재현된다

- 뒷받침 시도: "시도 1: Safari 17.4, 탭 1개만 열고 같은 계정으로 카드 10회 드래그 — 카드 소실 0회"와 "시도 2: Safari 17.4, 같은 계정으로 탭 2개 동시에 열고 카드 10회 드래그 — 카드 소실 4회"를 대조하면, 브라우저·계정 조건이 동일한 상태에서 탭 수만 1개→2개로 바뀌었을 때 소실이 0회→4회로 나타남. "시도 3: Chrome 124, 같은 계정으로 탭 2개 동시에 열고 카드 10회 드래그 — 카드 소실 1회"도 탭 2개 조건에서 재현됨.
- 반박 시도: "시도 4: Safari 17.4, 서로 다른 계정으로 탭 2개를 열고 카드 10회 드래그 — 카드 소실 0회" — 탭이 2개여도 재현되지 않은 사례가 있어, 탭 수만으로는 재현 여부를 완전히 설명하지 못함.
- 로그 상관관계: "52건의 세션 속성: 47건이 동일 사용자 세션에서 브라우저 탭 2개 이상이 태스크플로우에 동시 접속해 있었음(멀티탭 세션), 5건은 탭 정보 로그 누락으로 확인 불가." (계산: 47/52 ≈ 90.4%가 멀티탭 세션으로 확인됨)
- 판정: **채택** — 단, 시도 4의 반박 사례로 볼 때 탭 수 2개 이상은 재현의 필요조건이지 그 자체만으로 충분조건은 아님(가설 3과 결합해야 함).

### 3. 계정 조건 — 동일 계정으로 여러 탭을 열었는지 여부가 재현을 가른다

- 뒷받침 시도: "시도 2: Safari 17.4, 같은 계정으로 탭 2개 동시에 열고 카드 10회 드래그 — 카드 소실 4회"와 "시도 4: Safari 17.4, 서로 다른 계정으로 탭 2개를 열고 카드 10회 드래그 — 카드 소실 0회"를 대조하면, 브라우저와 탭 수(2개)가 동일한 상태에서 계정 조건만 "같은 계정"→"다른 계정"으로 바뀌었을 때 소실이 4회→0회로 나타남.
- 반박 시도: 이 가설을 직접 반박하는 시도는 없음.
- 로그 상관관계: 모니터링 로그의 "동일 사용자 세션에서 브라우저 탭 2개 이상이 동시 접속"이라는 지표 자체가 정의상 이미 동일 계정 하의 멀티탭을 의미하므로, 계정 조건을 별도로 구분해 집계한 수치는 raw 데이터에 없음(상관관계 인용 불가).
- [추정: 없음 — 시도 2와 시도 4의 직접 대조로 판정]
- 판정: **채택** — 브라우저·탭 수를 동일하게 고정한 대조 시도(시도 2 vs 시도 4)에서 계정 조건만 재현 여부를 갈랐음.

### 4. 플랫폼(웹 vs 모바일 앱) 여부가 재현을 가른다 — 모바일 앱에서는 재현되지 않는다

- 뒷받침 시도: 신고자 원문 "모바일 앱에서도 똑같은 문제가 있다고 하는 사용자가 한 명 있었습니다"(단, 사용자 1인의 진술이며 직접 재현 시도는 아님).
- 반박 시도: "시도 5: Android 앱(삼성 갤럭시 S23), 탭 개념 없음(단일 앱 세션), 카드 10회 드래그 — 카드 소실 0회. iOS 실기기가 없어 iOS 앱은 시도하지 못함."
- 로그 상관관계: "모바일 앱(iOS/Android) 클라이언트에서 발생한 card_render_missing 이벤트는 지난 7일간 0건."
- [추정: 모바일 앱은 구조상 다중 탭 개념이 없어 가설 2가 요구하는 조건(탭 2개 이상)을 애초에 충족할 수 없는 것일 수 있음 — 즉 Android 미재현이 "플랫폼 자체" 때문인지 "멀티탭 조건 미충족" 때문인지는 raw 데이터로 구분되지 않음]
- 판정: **미확인** — Android 실기기 및 로그는 모두 재현되지 않는 쪽을 가리키지만, 신고자가 지목한 iOS는 실기기가 없어 시도 자체가 이뤄지지 못했으므로 모바일 플랫폼 전체에 대한 결론은 아직 내릴 수 없음.

## 재현 조건 종합

**채택된 가설(가설 2, 가설 3)을 결합하면**: 동일 계정으로 태스크플로우에 로그인한 상태에서 브라우저 탭을 2개 이상 동시에 열어두고 그중 한 탭에서 카드를 드래그하면 카드가 화면에서 사라지며, 탭이 1개뿐이거나 서로 다른 계정으로 접속했다면(둘 중 하나라도 빠지면) 재현되지 않는다. 브라우저 종류(Safari/Chrome)는 이 경계에 영향을 주지 않는다.

- 가설 1(브라우저 종류)이 아닌 이유: Chrome에서도 동일 조건(탭 2개+동일 계정)에서 재현되었으므로(시도 3), 브라우저 종류 자체는 재현을 가르는 경계가 아님.
- 가설 4(플랫폼)가 아직 판정되지 않은 이유: Android 실기기에서는 재현되지 않았으나(시도 5), 신고자가 지목한 iOS 실기기 시도가 이뤄지지 않아 모바일 플랫폼 전체에 대한 결론은 아직 내릴 수 없음.

추가로, 재현된 모든 시도(시도 2, 시도 3)에서 소실 직후 새로고침하면 카드가 정상적으로 다시 나타났고 서버 DB 조회 결과 데이터 유실은 없었다 — 즉 이번 현상은 화면 렌더링에 한정되며, 신고자가 우려한 "작업 내용이 통째로 날아감"에 해당하는 서버 측 데이터 유실은 지금까지의 재현·로그 확인 범위 내에서는 확인되지 않았다.

## 재현 시도 환경

MacBook Pro(macOS), Safari 17.4 및 Chrome 124, 태스크플로우 웹앱 v3.8.2, 테스트 계정 2개(동일 워크스페이스). Android 실기기(삼성 갤럭시 S23) 1대. iOS 실기기는 보유하지 않음.
