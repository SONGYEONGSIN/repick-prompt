# DECISION — 버그 재현 절차 보고서 (R39)

## HUMAN GATE (`--auto`)

**승자: a (분리형 — 근거 강도 × 출처 정체성 별도 컬럼)** — 라틴 방진 3라운드 전부 1위, 108.5/120 (2위 b 101.5, 3위 c 87.5). `"auto":true`로 ledger에 기록. 사용자가 원하면 다음 대화에서 뒤집을 수 있음.

**탈락 사유**:
- b(합산형, 2위) — 목표 축(환각·과장억제)에서 a에 일관되게 뒤처졌고(27 vs 29/30, 3라운드 전부), 산출물에 문서 제목·작성자 헤더가 빠져 바로사용가능성에서도 밀림(단, 이 헤더 누락은 처치 변수와 무관한 실행 편차 — 아래 지식 정제 게이트 참고).
- c(조건 가설 소거형, 3위) — 조건 변수 중심 재구성이 분석적으로는 가장 정교했으나(브라우저/탭수/계정 페어 대조), 조건으로 환원되지 않는 신고 항목("거의 매번" 빈도)을 검토 없이 통째로 누락시켜 지시이행도·환각억제 양쪽에서 3라운드 전부 최하위.

## DOMAIN.md 예측 대조

DOMAIN.md는 "a·b 중 분리형(a)이 우세 예상, 종합 승자는 c일 가능성"이라 예측했다. **전반부(a>b)는 적중, 후반부(c 종합 승자)는 빗나감** — c는 시도-재시도 경계 좁히기 구조가 정교했음에도 신고 항목 커버리지 누락으로 종합 최하위. domain-fit named query 누적: 6승 12패(R37까지) → 이번 라운드는 부분 적중으로 집계.

## 지식 정제 게이트

**추출한 규칙**: "근거 강도와 출처 정체성을 별도 컬럼으로 분리하는 구조가, 하나로 합친 등급보다 환각·과장 억제에서 우세하다" — v1.36(R38)과 같은 축·같은 방향.

**판정: 강화 (조건부)**

- **같은 축·같은 방향**이므로 새 원칙을 추가하지 않고 v1.36에 근거 라운드만 덧붙인다.
- **재확인된 부분**: a가 b를 환각·과장억제 축에서 라틴 방진 3라운드 전부 앞섰다(29 vs 27/30) — 두 번째 도메인(버그 재현 절차 보고서)에서도 방향이 재현됨.
- **문자 그대로 재현되지 않은 부분**: backlog가 명시한 핵심 실패 시그니처("2차 정보가 1차 근거와 같은 등급으로 승격")를 3명의 심사자 중 누구도 b에서 구체적으로 지적하지 않았다. b는 카드마다 신고자/로그/재현자 3행을 그대로 유지한 채 등급 컬럼 하나만 추가했을 뿐이라, 행 단위 출처 구분 자체는 남아 있었다 — R38의 c(출처 구분 행 자체가 없어 오분류가 구조적으로 강제됨)와 구조가 달랐다. 이번 라운드는 "출처 구분 행 유무"가 아니라 "등급을 별도 컬럼으로 분리하는가, 압축된 단일 지표로 합치는가"만 통제했으므로, 검증한 변수 자체가 R38보다 좁다.
- **통제 한계(사람 리뷰 없이 자체 발견)**: b 산출물에만 문서 제목·작성자 헤더가 빠졌다 — 세 후보의 출력 형식 요구사항은 완전히 동일했으므로 이는 처치 변수(등급 분리 여부)가 아니라 산출물 생성 단계의 실행 편차다. 3명의 심사자 전원이 이를 바로사용가능성 감점 사유로 지목해, 종합 점수 격차(+7)의 상당 부분이 이 confound에서 왔을 수 있다. **목표 축(환각·과장억제, +2/30)만이 confound에서 자유로운 순수 신호이며, 그 격차는 R38(28 vs 16, +12/30)보다 뚜렷이 얇다.**

**결론**: v1.36을 "강화"로 갱신한다 — 새 항목을 추가하지 않고 두 번째 도메인 재현 근거를 추가하되, 이번 재현이 R38보다 신호가 약했고 confound가 있었음을 그대로 기록한다(과장하지 않는다). 세 번째 재현이 필요하다면 통제를 더 좁혀 "행 단위 출처 구분 유무"와 "등급 압축 여부"를 별도 변수로 분리할 것.

**정제 질문 없음** — 충돌 판정이 아니므로 backlog·PR에 별도 질문 섹션 불필요.

## 방법론 관찰 (DNA 미반영, 신규)

c(조건 가설 소거형)가 신고 항목을 조건 변수로 재구성하면서 조건으로 환원되지 않는 신고 항목(빈도·강도 같은 양적 주장)을 통째로 누락시킨 것은 이번이 첫 관찰이다 — 감별 도메인의 "후보 나열-판정 분리"(v1.30)를 원인·조건 단위로 적용할 때는 원래 신고 항목 목록과의 커버리지 대조를 별도로 강제해야 할 수 있다는 가설을 backlog에 재검 후보로 남긴다(신규 원칙 승격은 아직 이르다 — 단일 라운드 단일 관찰).
