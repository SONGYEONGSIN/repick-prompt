## 신고된 증상 목록 (판정 전, 신고자 원문 그대로)

아래는 신고자(고객지원팀 전달)가 말한 내용을 그대로 나열한 것이며, 이 단계에서는 재현 여부를 판단하지 않는다.

1. "'태스크플로우'에서 칸반보드 카드를 드래그해서 다른 컬럼으로 옮기면 카드가 사라져요."
2. "완전히 랜덤은 아니고 거의 매번 일어나는 것 같습니다."
3. "새로고침해도 카드가 다시 안 나타나서 작업 내용이 통째로 날아간 것 같다고 하시는 분도 있어요."
4. "모바일 앱에서도 똑같은 문제가 있다고 하는 사용자가 한 명 있었습니다."

## 검증 카드

### 검증 카드 1. 드래그 시 카드가 사라짐

**신고 항목(원문 인용):** "'태스크플로우'에서 칸반보드 카드를 드래그해서 다른 컬럼으로 옮기면 카드가 사라져요."

| 출처 | 원문 인용 | 근거 강도 | 출처 정체성 |
|---|---|---|---|
| 신고자 발화 | "칸반보드 카드를 드래그해서 다른 컬럼으로 옮기면 카드가 사라져요." | 인용 가능 | 신고자의 말 |
| 로그·계측 데이터 | "드래그 앤 드롭 이벤트 총 340건 기록. 그중 'card_render_missing' 에러 이벤트 52건 발생." | 인용 가능 | 로그·계측 데이터 |
| 재현 시도 | "시도 2: Safari 17.4, 같은 계정으로 탭 2개 동시에 열고 카드 10회 드래그 — 카드 소실 4회." / "시도 3: Chrome 124, 같은 계정으로 탭 2개 동시에 열고 카드 10회 드래그 — 카드 소실 1회." (반면 "시도 1: … 탭 1개만 열고 … 카드 소실 0회.", "시도 4: … 서로 다른 계정으로 탭 2개를 열고 … 카드 소실 0회.") | 인용 가능 | 재현자가 직접 확인한 결과 |

**최종 판정: 재현됨(조건부 포함)**
조건: 동일 계정으로 브라우저 탭 2개 이상을 동시에 접속한 상태(멀티탭)에서 드래그할 때 재현됨(시도 2, 시도 3). 탭 1개만 사용하거나(시도 1), 탭은 2개이나 서로 다른 계정으로 접속한 경우(시도 4)에는 재현되지 않음. 왜 멀티탭 조건에서 이 현상이 발생하는지에 대한 기술적 원인은 raw 데이터에 없으므로 본 카드에서 단정하지 않음(확인 요청 목록의 박현우 항목 참조).

### 검증 카드 2. 발생 빈도가 "거의 매번"에 해당하는가

**신고 항목(원문 인용):** "완전히 랜덤은 아니고 거의 매번 일어나는 것 같습니다."

| 출처 | 원문 인용 | 근거 강도 | 출처 정체성 |
|---|---|---|---|
| 신고자 발화 | "완전히 랜덤은 아니고 거의 매번 일어나는 것 같습니다." | 인용 가능 | 신고자의 말 |
| 로그·계측 데이터 | "드래그 앤 드롭 이벤트 총 340건 기록. 그중 'card_render_missing' 에러 이벤트 52건 발생." — (계산: 52/340 ≈ 15.3%, 원문에 이 비율 자체가 문장으로 명시되어 있지는 않음) / "47건이 동일 사용자 세션에서 브라우저 탭 2개 이상이 … 동시 접속해 있었음(멀티탭 세션)" — (계산: 47/52 ≈ 90.4%) | 인용 가능(단, 백분율은 계산값) | 로그·계측 데이터 |
| 재현 시도 | "시도 1: … 카드 소실 0회.", "시도 2: … 카드 소실 4회.", "시도 3: … 카드 소실 1회.", "시도 4: … 카드 소실 0회.", "시도 5: … 카드 소실 0회." — (계산: 멀티탭·동일계정 조건인 시도 2는 4/10 = 40%, 시도 3은 1/10 = 10%; 그 외 조건에서는 0/10) | 인용 가능(단, 백분율은 계산값) | 재현자가 직접 확인한 결과 |

**최종 판정: 재현 안 됨**
카드 1에서 확인했듯 카드 소실 자체는 특정 조건(동일 계정 멀티탭)에서 재현되지만, 신고자가 표현한 "거의 매번" 수준의 근접 100% 발생 빈도는 로그(52/340, 계산상 약 15.3%)와 재현 시도(조건 충족 시에도 40%·10%) 어느 쪽에서도 뒷받침되지 않는다.

### 검증 카드 3. 새로고침해도 복구되지 않아 작업 내용이 유실됨

**신고 항목(원문 인용):** "새로고침해도 카드가 다시 안 나타나서 작업 내용이 통째로 날아간 것 같다고 하시는 분도 있어요."

| 출처 | 원문 인용 | 근거 강도 | 출처 정체성 |
|---|---|---|---|
| 신고자 발화 | "새로고침해도 카드가 다시 안 나타나서 작업 내용이 통째로 날아간 것 같다고 하시는 분도 있어요." | 인용 가능 | 신고자의 말 |
| 로그·계측 데이터 | "52건 전부에 대해 서버 DB 조회 로그를 확인한 결과 카드 레코드는 52건 전부 정상 존재(status=200, 데이터 유실 없음) — 화면에서만 사라졌을 뿐 DB에는 남아있었다." | 인용 가능 | 로그·계측 데이터 |
| 재현 시도 | "소실 직후 새로고침하면 카드가 다시 정상적으로 나타남 (DB 조회 결과 정상, 데이터 유실 아님)."(시도 2) / "새로고침 시 정상 복구."(시도 3) | 인용 가능 | 재현자가 직접 확인한 결과 |

**최종 판정: 재현 안 됨**
로그(52건 전부 DB 정상 존재)와 재현 시도(새로고침 시 즉시 정상 복구, 시도 2·3) 모두 "새로고침해도 안 돌아온다"는 주장을 반박한다. 카드가 일시적으로 화면에서 사라지는 현상 자체는 카드 1에서 별도로 재현되었으나, 그것이 곧 "작업 내용이 통째로 날아간" 영구적 데이터 유실을 의미하지는 않는다.

**신고 항목(원문 인용):** "모바일 앱에서도 똑같은 문제가 있다고 하는 사용자가 한 명 있었습니다."

| 출처 | 원문 인용 | 근거 강도 | 출처 정체성 |
|---|---|---|---|
| 신고자 발화 | "모바일 앱에서도 똑같은 문제가 있다고 하는 사용자가 한 명 있었습니다." | 인용 가능 | 신고자의 말 |
| 로그·계측 데이터 | "모바일 앱(iOS/Android) 클라이언트에서 발생한 card_render_missing 이벤트는 지난 7일간 0건." | 인용 가능(단, iOS·Android가 통합 집계된 수치이며 iOS만 따로 분리된 값은 없음) | 로그·계측 데이터 |
| 재현 시도 | "Android 앱(삼성 갤럭시 S23), 탭 개념 없음(단일 앱 세션), 카드 10회 드래그 — 카드 소실 0회. iOS 실기기가 없어 iOS 앱은 시도하지 못함." | Android 부분은 인용 가능 / iOS 부분은 시도 자체가 없어 인용 불가 | 재현자가 직접 확인한 결과 |

**최종 판정: 판정 불가(추가 확인 필요)**
Android는 로그(0건)와 재현 시도(0/10) 결과가 일치하여 재현되지 않음을 뒷받침하지만, 신고자가 어떤 플랫폼(iOS/Android)을 지칭했는지는 원문에 특정되어 있지 않고, iOS는 실기기 미보유로 재현 시도 자체가 이루어지지 않았다. 로그의 모바일 수치도 iOS/Android가 합산되어 있어 iOS만 따로 확인할 수 없다. iOS 재현 결과 없이는 이 항목을 "재현 안 됨"으로 단정할 수 없다.
