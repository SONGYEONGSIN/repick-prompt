# 후보 c — 방법론 내장형: 핵심 플로우 1개·가짜 데이터·스코프 컷을 요구사항 문장으로 강제하는 프레임워크형

## fields
| key | label | type | optional | help | placeholder | options |
|-----|-------|------|----------|------|-------------|---------|
| service_idea | 만들려는 서비스 한 줄 소개 | text | no | 무엇을 하는 서비스인지 한 문장으로 적으세요. "누가 무엇을 하는" 형태면 AI가 화면을 정확히 그립니다. | 동네 반찬가게 사장님이 '오늘의 반찬'을 올리면 단골손님이 앱에서 골라 예약하는 서비스 | |
| target_user | 주로 쓸 사람 | text | no | 이 화면을 실제로 누를 사람입니다. 나이·상황을 적으면 글씨 크기와 버튼 배치가 그 사람에게 맞춰집니다. | 가게 근처에 사는 40~60대 단골손님, 스마트폰 앱에 익숙하지 않음 | |
| core_flow | 딱 하나 보여주고 싶은 행동 | textarea | no | 이번 프로토타입이 증명할 단 하나의 행동입니다. 모든 기능을 담지 마세요. "사용자가 ~을 하면 ~이 된다" 한 줄로, 가장 중요한 순간 하나만 고르세요. 나머지는 다음에 만들면 됩니다. | 손님이 오늘의 반찬 목록에서 하나를 고르고 '예약하기'를 누르면 예약 완료 화면이 나온다 | |
| sample_data | 화면에 미리 채워둘 예시 내용 | textarea | no | 프로토타입은 빈 화면이 아니라 이미 내용이 채워져 있어야 진짜처럼 보입니다. 화면에 보일 가짜 예시를 3~5개 적어주세요. | 제육볶음 5,000원, 계란말이 3,000원, 시금치나물 2,500원, 고등어조림 6,000원, 겉절이김치 4,000원 | |
| screens | 보여줄 화면 (1~3개) | textarea | yes | 비워두면 위 '딱 하나 보여줄 행동'에 맞춰 AI가 알아서 화면을 정합니다. 정해둔 게 있으면 적으세요. | 오늘의 반찬 목록 화면, 예약 완료 화면 | |
| mood | 화면 분위기 | select | yes | 고민되면 '깔끔한 미니멀'이 무난합니다. | 따뜻하고 친근한 | ["깔끔한 미니멀", "따뜻하고 친근한", "밝고 활기찬", "차분한 프리미엄"] |
| avoid | 이번엔 넣지 않았으면 하는 것 | text | yes | 굳이 없어도 되는 요소를 적으세요. 없으면 비워두세요. | 복잡한 메뉴바, 회원가입 절차, 광고 배너 | |

## template

```
당신은 코딩을 전혀 모르는 사람을 위해 '작동하는 프로토타입'을 만들어주는 프론트엔드 프로토타이퍼입니다. 완벽한 제품이 아니라, 아이디어를 눈으로 보고 손으로 클릭해볼 수 있게 만드는 것이 당신의 유일한 목표입니다.

아래 정보를 바탕으로, 브라우저에서 바로 열리는 프로토타입을 만들어주세요.
- 만들려는 서비스: {{service_idea}}
- 주로 쓸 사람: {{target_user}}
- 딱 하나 보여줄 행동(핵심 플로우): {{core_flow}}
- 화면에 미리 채워둘 예시 내용: {{sample_data}}
- 보여줄 화면: {{screens}}
- 화면 분위기: {{mood}}
- 이번엔 넣지 않았으면 하는 것: {{avoid}}

요구사항:
1. 핵심 플로우 하나만 만드세요. 위 "딱 하나 보여줄 행동"만 끝까지 완성도 있게 구현하고, 그 외 기능은 넣지 마세요. 흐름상 다른 버튼이 필요하면 눌렀을 때 "준비 중이에요" 안내만 뜨게 하세요.
2. 화면은 빈 상태가 아니라, 위 예시 내용이 이미 채워진 상태로 시작해야 합니다. 진짜 서비스처럼 보이도록 최소 3개 이상의 항목이 처음부터 화면에 보이게 하세요.
3. 버튼이나 항목을 누르면 화면이 실제로 반응해야 합니다 — 선택 표시가 켜지거나, 다음 화면으로 넘어가거나, 완료 메시지가 뜨는 식으로요. 눌러도 아무 일도 안 일어나는 장식용 버튼은 만들지 마세요.
4. 로그인, 회원가입, 결제, 서버 연결, 데이터베이스는 절대 만들지 마세요. 프로토타입 단계에서는 불필요하고, 이런 걸 넣으면 코드를 모르는 사람이 파일을 열어도 작동하지 않습니다.
5. 모든 코드(HTML·CSS·JavaScript)를 하나의 .html 파일 안에 담아, 다른 파일이나 프로그램 설치 없이 파일만 열면 바로 작동하게 하세요. 인터넷 연결이 끊겨도 작동해야 합니다.
6. "여기에 내용이 들어갑니다" 같은 자리표시자 텍스트나, 클릭되지 않는 가짜 화면 이미지는 넣지 마세요. 실제로 눌리고 반응하는 진짜 화면이어야 합니다.

출력 형식:
- 완성된 단일 HTML 파일의 전체 코드 (생략이나 "…이하 동일" 없이, 복사해서 붙여넣기만 하면 되는 완전한 코드)
- 이 파일을 컴퓨터에서 열어보는 방법을, 코드를 몰라도 따라 할 수 있게 3~4단계로 안내 (메모장·텍스트 편집기에 코드 붙여넣기 → 파일 이름을 프로토타입.html 로 저장 → 저장한 파일 더블클릭 → 브라우저에서 열림)
- 지금 이 프로토타입이 보여주는 것과, 아직 없는 것(다음에 만들 것)을 나눠서 정리
- 이 화면을 다른 사람에게 보여주고 물어볼 검증 질문 3개
- 마음에 안 드는 곳을 고쳐달라고 요청하는 예시 문장 3개
```

## anatomy

| part | quote | why |
|------|-------|-----|
| 역할 | "완벽한 제품이 아니라, 아이디어를 눈으로 보고 손으로 클릭해볼 수 있게 만드는 것이 당신의 유일한 목표입니다." | 역할에 직업만 주면 AI는 과하게 정교한 앱을 만들려다 초보자가 열지도 못하는 결과를 냅니다. 목표를 "클릭해볼 수 있게"로 좁히면 모든 판단이 '실제로 열리고 반응하는가'로 정렬됩니다. |
| 맥락 | "딱 하나 보여줄 행동(핵심 플로우): {{core_flow}}" | 초보자가 프로토타입에서 실패하는 첫 번째 이유는 욕심입니다 — 모든 기능을 넣으려다 아무것도 완성하지 못합니다. 증명할 행동 하나를 빈칸으로 강제하면, 검증된 프로토타이핑 원칙(one core flow)이 옵션이 아니라 기본값이 됩니다. |
| 요구사항 | "로그인, 회원가입, 결제, 서버 연결, 데이터베이스는 절대 만들지 마세요." | 스코프 컷을 네거티브 조건으로 못박은 문장입니다. 이걸 빼면 AI는 친절하게 로그인 화면부터 붙여 파일이 작동하지 않게 만듭니다. 방법론(만들지 말 것)을 지침 문장으로 내장해, 초보자가 몰라도 안전한 프로토타입이 나옵니다. |
| 출력 형식 | "열어보는 방법 3~4단계 → 있는 것/없는 것 정리 → 검증 질문 3개 → 고쳐달라 요청 예시 3개" | 코드만 주면 초보자는 그 코드를 어떻게 여는지 몰라 멈춥니다. 여는 방법·확인 질문·다음 수정 요청까지 한 세트로 주면 "받았는데 뭘 하지?"가 사라집니다 — 결과물이 아니라 실행까지 이어지는 행동 착지입니다. |

## tips

1. **고칠 땐 전체를 다시 요청하지 말고 한 곳씩 지목하세요.** 붙여넣은 코드가 마음에 안 들면 "방금 그 파일에서 예약하기 버튼만 더 크고 초록색으로 바꿔줘"처럼 한 부분만 요청하면, AI가 나머지는 그대로 두고 그 부분만 고친 새 코드를 줍니다. 처음부터 다시 만들면 잘 되던 것까지 어긋납니다.
2. **핵심 플로우 하나가 마음에 들면 화면을 하나씩 이어붙이세요.** "이 예약 완료 화면 다음에 '내 예약 목록' 화면을 하나 추가해줘"처럼 검증된 화면 위에 하나씩 쌓으면, 처음부터 전부 만들려다 길을 잃는 일 없이 프로토타입이 자연스럽게 커집니다.
