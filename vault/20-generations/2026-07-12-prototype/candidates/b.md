# 후보 b — 필드가 기획을 대신 세운다: 흐릿한 아이디어를 네 칸으로 붙잡아 더블클릭되는 첫 화면까지 끌고 가는 가이드 최대화형

## fields
| key | label | type | optional | help | placeholder | options |
|-----|-------|------|----------|------|-------------|---------|
| service_idea | 만들려는 서비스 | textarea | no | 가장 먼저 채우는 기획 결정 칸입니다. "무엇을 / 누구의 어떤 불편을 위해"만 한두 문장으로 적으면 아래 칸들이 술술 채워집니다. 흐릿하면 "___할 때 매번 불편해서 만든다"로 시작해보세요. | 냉장고에 있는 재료를 입력하면 오늘 해먹을 수 있는 요리를 추천해주는 웹앱. 자취 첫해라 뭘 만들지 매번 막막한 사람을 위한 것 | |
| target_user | 누가 쓰나 | text | no | 쓸 사람을 딱 한 명 떠올려 구체적으로 적으면 화면의 글씨 크기·말투·기능이 그 사람에게 맞춰집니다. "모두"라고 적으면 누구에게도 안 맞는 밋밋한 화면이 나옵니다. | 요리를 거의 안 해본 20대 자취생 | |

| mood | 분위기·색감 | select | yes | 고르면 색과 글씨 느낌이 정해집니다. 고민되면 비워두고 AI가 무난하게 정하게 두어도 됩니다. | 밝고 깔끔한 (흰 배경) | ["밝고 깔끔한 (흰 배경)", "따뜻하고 부드러운 (파스텔)", "차분하고 진한 (다크 모드)", "활기차고 컬러풀한"] |
| avoid | 이번엔 넣지 말 것 | text | yes | 굳이 빼고 싶은 게 있을 때만 적으세요. 없으면 비워두면 됩니다. | 광고 배너, 팝업창, 복잡한 설정 화면은 빼줘 | |

## template

```
당신은 코드를 전혀 모르는 사람을 위해 브라우저에서 바로 열리는 작동 프로토타입을 만들어주는 프론트엔드 프로토타이퍼입니다. 설명이나 계획서가 아니라, 더블클릭하면 화면이 뜨는 HTML 파일 하나를 넘겨주는 것이 당신의 유일한 목표입니다.

아래 정보를 바탕으로, 초보자가 바로 열어볼 수 있는 프로토타입을 만들어주세요.
- 만들려는 서비스: {{service_idea}}
- 누가 쓰나: {{target_user}}
- 첫 화면에 보여야 할 것: {{main_screen}}
- 사용자가 해볼 수 있는 하나의 동작: {{core_action}}
- 화면을 채울 예시 내용: {{sample_content}}
- 분위기·색감: {{mood}}
- 이번엔 넣지 말 것: {{avoid}}

요구사항:
1. 결과물은 HTML 파일 딱 하나여야 합니다. 디자인(CSS)과 동작(JavaScript)을 그 파일 하나 안에 함께 넣어, 설치나 서버 없이 파일을 더블클릭하면 브라우저에서 바로 열리게 해주세요.
2. 인터넷 연결이 없어도 열리도록, 외부 주소를 불러오는 라이브러리·CDN·이미지 링크를 쓰지 마세요. 아이콘이나 그림이 필요하면 이모지나 색 도형으로 대신해주세요.
3. "사용자가 해볼 수 있는 하나의 동작"이 진짜로 눌러지게 만들어주세요. 서버가 없어도 파일 안에 미리 넣어둔 예시 내용으로 반응하면 됩니다 — 버튼을 누르면 화면이 바뀌거나 내용이 나타나서, '작동한다'가 이 한 동작으로 눈에 보여야 합니다.
4. 화면이 휴대폰과 컴퓨터 양쪽에서 깨지지 않도록 크기가 자동으로 맞춰지게 해주세요.
5. 로그인·회원가입·결제·서버에 데이터 저장하기는 넣지 마세요. 이번 목표는 '진짜 서비스'가 아니라 '만져볼 수 있는 첫 화면'입니다.
6. 나중에 초보자가 직접 고칠 수 있도록, 코드 곳곳에 "여기 글자를 바꾸세요", "여기 색을 바꾸세요" 같은 한국어 주석을 달아주세요.

출력 형식:
- 완성된 HTML 전체 코드 한 개 (그대로 복사할 수 있는 코드블록 하나로)
- 이 파일을 여는 방법 3단계 (메모장·텍스트편집기에 붙여넣기 → 이름을 'index.html'로 저장 → 그 파일을 더블클릭)
- 파일을 열었을 때 눈으로 확인할 체크리스트 3개 (첫 화면이 뜨는가 / 그 버튼을 누르면 반응하는가 / 화면을 좁혀도 안 깨지는가)
- 마음에 안 들 때 그대로 붙여넣어 쓸 "다음 수정 요청" 문장 3개 (색을 바꾸고 싶을 때 / 버튼이나 항목을 더 넣고 싶을 때 / 글자·문구를 바꾸고 싶을 때)
```

## anatomy

| part | quote | why |
|------|-------|-----|
| 역할 | "더블클릭하면 화면이 뜨는 HTML 파일 하나를 넘겨주는 것이 당신의 유일한 목표입니다." | 초보자가 물으면 AI는 흔히 '설명'이나 '단계별 안내'로 답합니다. 목표를 '열리는 파일 하나'로 못박으면, AI가 코드 조각 나열이 아니라 통째로 실행되는 결과물을 내놓습니다. |
| 맥락 | "사용자가 해볼 수 있는 하나의 동작: {{core_action}}" | 프로토타입이 '움직이는 화면'이 되느냐 '죽은 그림'이 되느냐를 가르는 결정 칸입니다. 동작을 하나로 좁히면 AI가 그 하나를 확실히 작동시키고, 초보자가 흔히 요구하는 "기능 전부"의 미완성 덩어리를 피합니다. |
| 요구사항 | "인터넷 연결이 없어도 열리도록, 외부 주소를 불러오는 라이브러리·CDN·이미지 링크를 쓰지 마세요." | 코드를 모르는 사람의 유일한 실행 경로는 '더블클릭'뿐입니다. 이 네거티브 조건이 없으면 AI가 설치·서버 실행이 필요한 코드를 내놓아, 초보자는 첫 화면조차 못 봅니다. 제약이 곧 실행 가능성을 보장합니다. |
| 출력 형식 | "이 파일을 여는 방법 3단계 … 마음에 안 들 때 그대로 붙여넣어 쓸 '다음 수정 요청' 문장 3개" | 코드를 받아도 여는 법을 모르면 무용지물입니다. 결과물·여는 법·확인 체크리스트·고치는 법을 한 세트로 줘야 초보자가 화면을 실제로 띄우고, 마음에 안 들 때 대화를 이어갑니다 — 읽고 끝나지 않는 행동 착지입니다. |

## tips

1. **한 번에 다 만들려 하지 말고 "첫 화면 + 동작 하나"만 먼저 받으세요.** 그 파일이 실제로 열리는 걸 확인한 뒤, "이제 여기에 ___을 추가해줘"로 한 조각씩 키우면 매번 여는 데 성공하는 프로토타입이 차곡차곡 쌓입니다. 반대로 처음부터 많은 기능을 요구하면 코드가 길어져 어딘가 깨지고, 초보자는 어디가 문제인지 못 찾아 막힙니다.
2. **화면이 안 뜨거나 이상하면, 그 HTML 파일을 통째로 다시 붙여넣고 고쳐 달라고 하세요.** "이 파일을 브라우저에서 열었더니 ___가 안 보여. 원인을 찾아서 고친 파일 전체를 다시 줘"라고 요청하면 됩니다. 화면에 빨간 글씨나 에러 메시지가 보이면 그 문장까지 같이 붙여넣으면 훨씬 정확하게 고쳐줍니다.
