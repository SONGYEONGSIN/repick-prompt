# DECISION — 외주 산출물 검수 기록 (R50, --auto)

## 승자

**후보 c (합성 사양 분해형 — 항목을 하위 기준으로 쪼개 개별 판정한 뒤 상향 규칙으로 합성)** — 라틴 방진 3라운드 전부 만장일치 1위, 104/120 (2위 a 79/120, 3위 b 77/120). `auto: true`(사람 게이트 자동 선택, 사람이 뒤집을 수 있음).

## 이유

DOMAIN.md 1절이 지목한 이 도메인의 본질 리스크(사양 항목 하나가 정량·정성 하위 기준을 여러 개 묶고 있는데 단일 판정으로 뭉뚱그리면 부분 미달이 조용히 사라진다)를 c만 결과물 구조 자체로 해소했다. SCENARIO에 심은 세 개의 결합 사양(항목2 해상도+fps, 항목5 로고 시작+종료, 항목3 자막 언어+어법)에서 c는 "(하위기준 A: 충족, 하위기준 B: 미달 → 상위 항목은 부분충족)" 형태로 계산 과정 자체를 노출해 3명의 독립 심사자 전원이 구체성·지시이행도 축 최고점의 근거로 이 구조를 정확히 지목했다. 부수 효과로, 하위 기준을 사양 문언 단위로 쪼개 판정하다 보니 항목3(자막)의 "톤 불일치"처럼 문언("오탈자·문법 오류") 범위 밖의 관찰사실이 판정에 섞이지 않았다 — a·b는 이를 "부분충족"으로 확대 해석했으나 c만 문언 그대로 "충족"으로 판정하면서 톤 문제는 별도 사실로만 병기했다.

## 탈락 사유

- **a (결합형 표준, 2위)**: R31 골격(4분류+등급고정+역방향스캔+인간라우팅+상단 사실만)을 충실히 이식해 구체성·환각억제는 c와 근접했으나, 항목을 단일 판정 단위로만 다뤄 결합 사양의 부분 미달을 c만큼 명료하게 드러내지 못했다(지시이행도 축 17점으로 최하). 결정적으로, "미충족"으로 등급을 정확히 고정한 항목(라이선스·원본파일)과 "부분충족" 항목(초상권)이 자신의 라우팅 요구사항("확인 필요" 판정 항목만 대상)에서 빠져, 확인 요청 목록에 항목7 1건만 남는 구조적 공백을 3명의 심사자 전원이 지적했다(아래 지식 정제 게이트 참고).
- **b (가이드 최대화형, 3위)**: 재작업·확인 요청 문구를 발송 직전 상태로 완성해주는 실행력은 세 후보 중 가장 뛰어났으나(재작업요청 1건+확인요청 3건, 라우팅 커버리지 자체는 a보다 나음), 환각·과장억제 축(13점, 최하)에서 두 가지 결함이 3라운드 내내 반복 지적됐다 — ① 항목2(fps 29.97)에서 raw에 없는 "방송·영상 업계 표준 표기(NTSC 계열)"라는 업계 통념을 끌어와 판정을 완화하려 한 점, ② "저작권 리스크가 발생해 지급 보류로 이어질 수 있는 사안"류 확정적 뉘앙스를 반복해 대금 지급 결정권자(박지훈)의 판단 영역을 침범한 점.

## 지식 정제 게이트

### 발견 1 — 합성 사양 분해 (주 발견, 승자의 핵심 메커니즘)

**추출 규칙**: "발주 사양·요건·계약 조항처럼 항목 하나가 여러 개의 독립적으로 확인 가능한 하위 기준(정량+정량, 또는 정량+정성)을 한 문장에 묶고 있는 도메인에서는, 판정 전에 항목을 하위 기준으로 먼저 분해해 각각 개별적으로 대조·판정한 뒤, '하위 기준 중 하나라도 미달이면 상위 항목은 충족을 줄 수 없다'는 상향 규칙으로 합성해야 한다. 이 계산 과정을 결과물에 그대로 노출하면 상위 판정이 재량이 아니라 하위 판정의 산술적 귀결임이 검증 가능해진다. 부수 효과로, 판정 단위가 사양 문언 그대로 쪼개지므로 문언 범위 밖의 관찰사실이 판정에 섞여 들어가는 확대 해석도 함께 억제된다."

**판정: 신규**.
- ① 재사용 범위: 발주 사양·계약 요건·인수 기준처럼 "항목=여러 하위 기준의 묶음"인 모든 감사형 도메인에 일반화된다. v1.19(결정 기준별 1:1 대응 구조)는 여러 개의 **별개 항목**을 문서 구조 단위로 1:1 대응시키는 원칙이라 항목 간(inter-item) 층위이고, 이 규칙은 **항목 하나 내부**(intra-item)의 하위 기준을 다룬다는 점에서 층위가 다르다 — 라이브러리 어디에도 이 층위를 다루는 원칙이 없다.
- ② 실측 근거: 라틴 방진 3라운드 만장일치, 3명의 독립 심사자 전원이 서로 다른 위치 배치에서도 정확히 같은 구조("하위기준 분해→개별판정→상향합성")를 승리 요인으로 지목 — 결과물에 흔적이 남는 판정(부분충족 계산 과정이 결과물에 그대로 노출).
- ③ 기존 원칙과의 중복도: v1.19와는 층위가 달라 중복 없음. v1.41(집계 검산)과는 "계산 과정을 결과물에 노출한다"는 표면은 닮았지만, v1.41은 라벨 개수 집계의 사후 검산이고 이 규칙은 판정 자체를 하위 요소의 합성으로 구조화하는 것이라 대상이 다르다 — 중복 없음.

DNA `prompt-principles.md`에 품질 장치 섹션 신규 항목으로 추가(v1.46).

### 발견 2 — 등급 고정과 인간 라우팅의 범위 불일치 (부차 발견, a의 구조적 결함)

**추출 규칙**: "확인 상태 라벨 + 인간 라우팅(v1.27) 원칙을 '확인 필요' 라벨에만 좁게 적용하면, '미충족'처럼 이미 등급이 정확히 고정된(v1.31/32) 심각한 판정 항목이 오히려 라우팅 대상에서 새어나간다. 라우팅 대상은 '확인 필요'라는 특정 라벨이 아니라 '후속 조치(재작업 요청이든 확인 요청이든)가 필요한 모든 판정'으로 정의해야 한다."

**판정: 강화(v1.27/v1.44)**.
- ① 재사용 범위: v1.44(세분류 카테고리도 라우팅 대상에서 빠지지 않게 한다, R47)와 같은 축의 다른 표면 — v1.44는 "확인 필요"를 잘게 쪼갠 하위 카테고리가 새는 문제였고, 이번은 "확인 필요"보다 상위의 이미 존재하는 카테고리("미충족")째로 새는 문제다. 모든 원장형·대조표형 감사 도메인에 일반화된다.
- ② 실측 근거: 3명의 독립 심사자 전원이 a의 확인 요청 목록에 항목7(트리거 미도래=확인필요) 1건만 남고 라이선스·원본파일(미충족)·초상권(부분충족)이 빠진 것을 서로 다른 라운드에서 동일하게 지적 — 결과물의 확인 요청 목록 건수를 세면 판정 가능한 명확한 흔적.
- ③ 기존 원칙과의 중복도: v1.27·v1.44와 같은 축(인간 라우팅 커버리지) — 새 항목 추가 없이 기존 원칙에 근거 라운드만 추가.

DNA `prompt-principles.md`의 확인 상태 라벨 항목에 근거 라운드 추가(강화, 새 항목 없음).

## DOMAIN.md 예측-실제 대조

DOMAIN.md 5절은 "c가 본질 리스크(합성 사양 항목의 하위 기준 누락)를 정면 겨냥하므로 지시이행도·구체성에서 우세할 것"으로 예측하며, R42·R47 전례처럼 "이미 모델이 잘 하는 것을 규칙으로 강제"하면 효과가 묻힐 위험도 함께 적었다. 실제로는 SCENARIO에 심은 세 함정(항목2 fps 경계선, 항목3 톤 vs 문언, 항목5 로고 종료 부족) 모두에서 a·b가 실제로 걸리거나(fps 관행 완화, 톤 확대해석) 구조적으로 뭉뚱그렸다 — "이미 잘하는 행동"이 아니라 실제로 취약한 지점이었음이 확인됐다. 예측 적중, 격차도 25점 이상으로 뚜렷했다.
