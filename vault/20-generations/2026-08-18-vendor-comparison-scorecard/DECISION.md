# DECISION — 벤더·업체 비교 평가표 (R37)

## 승자

**c (가중치 투명화형)** — 라틴 방진 3라운드 전부 1위(만장일치, 33/35/35), 축별 합산 103/120. a(대상 우선 순회) 85/120, b(기준 우선 순회) 90/120.

`--auto` 모드: 종합 1위 자동 선택, ledger에 `"auto": true`로 기록. 사용자가 이 선택을 뒤집을 수 있음.

## 탈락 사유

- **a (대상 우선 순회, 85/120)**: 등급 고정 규칙(요구사항 2)은 3라운드 전부 정확히 지켰으나(기준4 두 벤더 모두 "확인 필요" 일관 처리), 결과물에 원문·기준목록에 없던 ①②③④⑤ 동그라미 숫자를 표·소제목·확인요청 목록 전반에 신설해 3명의 독립 심사자 전원이 바로사용가능성 감점 사유로 지목(3라운드 전부, anti-slop 위반). 확인 요청 대상으로 명시된 정우진(정보보호팀)을 라우팅에서 누락한 라운드도 있었다.
- **b (기준 우선 순회, 90/120)**: a와 같은 구조 마커 문제가 2/3 라운드에서 재현됐고, 유사한 확신도의 벤더 주장(오르카데스크 고객허브 연동 "A사 레퍼런스"만으로 충족 판정 등)에 다소 관대한 판정을 보였다는 지적을 받았다.
- **c (가중치 투명화형, 103/120, 승자)**: 구조 마커 없이 원 기준 번호("1. 2. 3.")만 사용해 3라운드 전부 바로사용가능성 최고점(9~9점대)을 받았고, "우선순위 미제공 → 종합 점수 미산출"을 상단에 명시적으로 선언해 가짜 정밀함을 경계하는 자세가 뚜렷했다. 다만 클리어헬프 SLA를 계약 조항 근거 없이도 오르카데스크와 동일하게 "충족"으로 판정해 뉘앙스 구분(a·b는 "부분충족"으로 구분)에서는 오히려 a·b보다 느슨했다.

## 예측-실제 대조 (DOMAIN.md 5절)

DOMAIN.md는 방향 풀을 backlog 방향 가설(a/b 통제쌍) + 가중치 투명화형(c, 본질 리스크 2번 가짜 정밀함 겨냥)으로 추천했다. **실제 승부처는 예측과 달랐다** — c가 이겼다는 결과 자체는 방향 풀 예측과 일치하지만, 승리 이유는 c가 정면 겨냥한 "근거 없는 종합 점수 금지"가 아니라 **계획하지 않았던 anti-slop 구조 마커(①②③) 자발적 신설 여부**였다. a·b·c 어느 후보도 실제로 종합 점수·순위를 만들려는 유혹에 빠지지 않아(세 결과물 모두 관찰 포인트 7 통과) 가중치 투명화 요구사항 자체는 이번 라운드에서 실전 시험대에 오르지 못했다 — R22(완성 예시 동봉 애매 판정)와 같은 패턴: 의도한 가설이 아니라 우연히 관찰된 다른 축이 승부를 갈랐다.

## 방향 가설 검증 판정 (backlog "N개 대상 채점 시 순회 순서가 일관성을 바꾸는가")

**기각.** 핵심 시험 지점(기준4 국내 리전 — 오르카데스크·헬로티켓 둘 다 자료 없음)에서 a(대상 우선)·b(기준 우선) 모두 3라운드 전부 예외 없이 "확인 필요"로 동일하게 라벨링했다 — 불일치 0건으로 완전히 동률. backlog가 명시한 기각 조건("두 후보의 불일치 건수가 비슷하면 기각 → 순회 순서는 일관성과 무관")이 문자 그대로 성립한다. 이번 라운드로 결론: **v1.31·v1.32의 등급 고정 규칙이 요구사항 문장에 명시돼 있으면, 대상이 여럿이어도(N=3) 순회 순서와 무관하게 규칙이 지켜진다** — 최소한 이번 SCENARIO(기준 5개 × 벤더 3사, 함정 1개가 벤더 2곳에 분산)의 난이도에서는 그렇다. 다만 심사자들은 a·b 양쪽에서 순회 순서와 무관해 보이는 다른 내적 일관성 문제(유사 확신도 주장에 대한 판정 엄격도 차이, 확인 요청 라우팅 누락)를 지적했다 — 이는 "N개 대상 판정의 일관성 리스크"가 실재하되, 원인이 순회 순서가 아니라 개별 판단 기준의 모호성일 수 있음을 시사한다. backlog에 새 재검 항목을 열지는 않는다 — 근거가 약하고(불일치 0건이라 반증 대상이 없음), R31의 원래 관찰(등급 고정 규칙 부재 상태에서의 비일관성)과 이번 실험(규칙 존재 상태)은 전제조건이 달라 직접 비교가 아니다.

## 지식 정제 게이트

**추출한 규칙**: "다중 기준×대상 비교표(N×M 그리드)를 생성시킬 때, 템플릿이 구조 마커(①②③) 금지를 명시적으로 요구사항에 박지 않으면 실행 시점에 자발적으로 재발한다."

**판정: 강화** (신규 아님). 기존 anti-slop 금지 목록에 "결과물 본문 안에 구조 마커(①②③) 표기 금지"가 이미 R1-c(v1)부터 있다 — 같은 축, 같은 방향. 다만 이번 라운드가 더하는 것은 실측 근거의 성격이다: R1-c는 자기검증 부속 메모에서 관찰된 사례였지만, 이번엔 **템플릿이 전혀 지시하지 않았는데도** 서로 다른 두 프롬프트(a·b, 독립 실행)에서 동일한 위반이 재현됐고, 3명의 독립 심사자가 3라운드 전부 정확히 같은 이유로 지적했다 — "결과물에만 흔적이 남는" 종류의 위반이면서 근거가 매우 강하다(R24 교훈의 기준 충족).

- **재사용 범위**: 여러 카테고리 적용 가능 — 비교·대조형 도메인(견적 비교, 후보 비교, 옵션 비교 등) 전반에 적용된다.
- **실측 근거**: 3라운드 × 3심사자 = 9회 독립 관찰 전부 동일 지목, 매우 강함.
- **기존 원칙과의 중복도**: 높음(같은 규칙의 축) — 그래서 새 항목을 추가하지 않고 기존 항목에 근거 라운드만 덧붙인다.
