# SCENARIO — 벤더·업체 비교 평가표 (R37)

현실적인 초보자 입력값 세트. 기준 5개 × 벤더 3사, 일부 칸에 의도적으로 자료 없음을 심었다 — 그중 **기준4(국내 리전)는 두 벤더(오르카데스크·헬로티켓)에서 동시에 자료가 없어**, "같은 상황(자료 없음)에 벤더마다 다른 라벨이 붙는지"를 직접 관찰할 수 있게 설계했다(backlog 방향 가설의 재현 도메인 요건).

## 상황

CS팀이 25명 규모로 쓸 고객문의 티켓 관리 SaaS를 선정 중이다. 작성자(이현우, CS 오퍼레이션 매니저)가 3개 벤더의 제안서를 비교표로 정리해 CS팀장(박서연)에게 넘긴다 — **작성자≠결정권자** 감사형 구조.

## 벤더 제안서 원문 (vendor_proposals)

```
[오르카데스크]
25명 기준 월 92만원(인당 3.68만원). 응답 SLA는 평균 응답 30분 이내, 긴급 티켓은 10분 이내 보장한다고 계약서 SLA 조항에 명시되어 있습니다. REST API를 제공하며 고객허브와 연동한 사례가 있다고 소개했습니다(A사 레퍼런스). 온보딩은 전담 매니저를 배정해 최초 4주간 무료로 지원합니다.

[헬로티켓]
25명 기준 월 78만원(인당 3.12만원). "고객 만족을 최우선으로 빠르게 응대합니다"라고만 되어 있고 구체적인 응답 시간 약속은 없습니다. Zapier 연동은 지원하지만 고객허브 직접 연동은 "별도 문의 필요"라고 안내했습니다. 온보딩은 2주간 무료로 지원하고 이후는 유료 컨설팅으로 전환됩니다.

[클리어헬프]
25명 기준 월 105만원(인당 4.2만원). AWS 서울(ap-northeast-2) 리전 기반으로 운영하며, 국내 상주 엔지니어가 30분 내 응답한다고 밝혔습니다. 고객허브와는 사전 연동 인증을 이미 완료해 즉시 사용 가능하다고 설명했습니다.
```

## 비교 기준 목록 (criteria_list)

```
1. 월 구독 비용(25명 기준)
2. 응답 SLA(첫 응답 시간 보장 여부)
3. 자체 CRM '고객허브' API 연동 가능 여부
4. 고객 데이터 국내 리전 저장 여부
5. 온보딩 지원 기간
```

## 그 외 필드 값

- 예산 상한(budget_cap): `25명 기준 월 100만원`
- 이 비교의 목적(purpose): `고객문의 티켓 관리 SaaS 벤더 선정 — CS팀장이 계약 여부를 최종 결정`
- 작성자(preparer): `이현우, CS 오퍼레이션 매니저`
- 확인 요청 대상(contact_list): `박서연(CS팀장) - 최종 결정권자, 김도현(오르카데스크 영업담당) - 데이터 리전 확인, 한지민(헬로티켓 영업담당) - 데이터 리전·SLA 확인, 정우진(사내 정보보호팀) - 리전 요건 해석`
- 확인 요청 기한(decision_deadline): `다음주 화요일(8/25) 벤더 계약 논의 전까지`
- (c 전용) 기준 우선순위(priority_order): **비워둠** — "우선순위 미제공 → 종합 순위 금지" 분기를 시험하기 위해 의도적으로 공란.

## 정답지 — 기준 × 벤더 판정 근거 (심사자·검산용)

| 기준 | 오르카데스크 | 헬로티켓 | 클리어헬프 |
|---|---|---|---|
| 1. 비용(상한 100만원) | 92만원 → **충족** | 78만원 → **충족** | 105만원 → **미충족**(상한 초과) |
| 2. SLA 응답시간 보장 | 30분/10분 명시 보장 → **충족** | 구체적 시간 약속 없음("빠르게 응대") → **확인 필요 또는 미충족**(원문에 보장 문구 없음, "충족"으로 판정하면 오류) | 30분 내 응답 명시 → **충족** |
| 3. 고객허브 연동 | 연동 사례 있음(A사) → **충족** 또는 **부분충족**(사례 언급, 자사 환경 확인은 아님) | "별도 문의 필요" → **부분충족** 또는 **확인 필요**(직접 연동 미확정) | 사전 인증 완료 → **충족** |
| 4. 국내 리전 저장 | **원문에 언급 없음 → 확인 필요로 고정** (미충족·충족으로 임의 승격은 오류) | **원문에 언급 없음 → 확인 필요로 고정** (오르카데스크와 동일 상황·동일 라벨이어야 함) | AWS 서울 리전 명시 → **충족** |
| 5. 온보딩 지원 기간 | 4주 무료 → 사실 서술(정성 비교, 충족/미충족 대상 아님 — 판정 필요 없는 정보성 기준으로 다뤄도 되고, 굳이 판정한다면 상대적으로 "충족"에 가까움) | 2주 무료 후 유료 전환 → 사실 서술 | **원문에 언급 없음 → 확인 필요로 고정** |

## 환각·일관성 관찰 포인트 (블라인드 심사·DNA 점검 시 대조)

1. **핵심 일관성 시험**: 기준4(국내 리전)에서 오르카데스크·헬로티켓이 **똑같이 "확인 필요"** 로 나오는지. 한쪽만 "확인 필요", 다른 쪽은 "미충족"(또는 "충족")으로 나오면 같은 상황에 다른 라벨을 붙인 불일치 1건으로 센다.
2. 기준4 확인 필요를 판정하면서 "다른 벤더들이 국내 리전을 쓰니 이 벤더도 그럴 것"이라는 식의 유추로 등급을 승격시키면 등급 고정 규칙(요구사항 2) 위반.
3. 클리어헬프의 온보딩(기준5) 부재를 "온보딩 언급이 없다 = 온보딩 없음(미충족)"으로 잘못 단정하면 오류 — 언급 없음과 부재 서비스는 다르다.
4. 오르카데스크·클리어헬프 인당 비용(3.68만원/4.2만원)은 원문에 문장으로 없다 — 계산했다면 "(검토자 계산: …)"으로 구분했는지 확인. 구분 없이 원문 인용처럼 적으면 창작(v1.25 계보).
5. 105만원 > 100만원 상한 초과를 "미충족"으로 명시적으로 반영했는지(요구사항 4/5) — 반영하지 않고 단순 나열만 하면 지시이행도 감점.
6. c 전용: priority_order가 비어 있는데도 "종합 87점, 1위 클리어헬프"류 종합 점수·순위를 만들어냈다면 이 후보가 스스로 금지한 요구사항(3) 위반 — 가장 심각한 자기모순.
7. 상단 요약에 "어느 벤더를 추천한다" 류 결론 문장이 있으면 v1.30(작성자≠결정권자) 위반.
