# DOMAIN — 재고·실물 실사 대조표 (R45)

> named query 실행 결과. GENERATE의 방향 풀 설계 직전에 작성.

## 1. 본질 리스크

이 도메인의 산출물이 실패하는 1순위 원인은 **차이(장부-실사)의 "사유"를 근거 없이 추측해 확정 서술하는 것**이다. 재고 실사는 필연적으로 차이(과다/부족)를 만들고, 사람은 그 차이를 설명하고 싶은 유혹을 느낀다(같은 유혹이 R30 데이터 검산 메모의 "불일치 원인 창작"으로 관찰됨 — v1.28). 재고 도메인에서는 이게 더 구체적인 형태로 나타난다: "파손 처리 누락으로 보임", "직원 시식/사용 추정" 같은 그럴듯한 원인을 raw에 그런 기록이 없는데도 만들어 붙인다.

두 번째 리스크는 **"경미한 차이"와 "조사가 필요한 차이"를 가르는 기준(중요도 임계값)이 주어지지 않으면 AI가 임의로 정한다**는 것 — v1.12(실행 조건은 일반 기본값으로 메꾸지 말고 전용 빈칸으로 받는다)와 같은 구조가 "허용 오차"라는 표면에서 재현될 수 있다.

세 번째는 **차이 수량 계산 자체의 산술 오류·검산 누락** — 장부 수량과 실사 수량의 차이를 계산하는 것은 raw 창작 금지의 계산·파생 수치 하위 규칙(v1.9/v1.25)이 정면으로 적용되는 지점이다.

## 2. 본질 루프

"만들면 끝"에 가깝다 — 실사는 특정 시점의 스냅샷 대조이고 반복·측정이 본질은 아니다(마케팅 실험처럼 판정→다음 실행으로 이어지는 루프가 아니다). 다만 **재실사(차이 사유 확인 후 재계수)**라는 좁은 재실행 경로는 있다 — quote-invoice-reconciliation(R43)·contract-compliance-checklist(R41)와 같은 "확인 요청 회신 → 재대조" 패턴.

## 3. 결과물의 소비 방식

작성자(창고·현장 실사 담당자)와 최종 결정권자(재고자산 조정을 승인하는 경리·재무 담당자, 또는 관리자)가 분리된 감사형 문서 — v1.30 조건(작성자≠결정권자 감사형 도메인)이 그대로 적용된다. 결재자는 결재선에서 빠르게 스캔하며 "장부를 실제로 고쳐도 되는가"를 판단한다. 짧은 정독 후 결재 — 3초 스캔은 아니지만 회의체 검토도 아니다.

## 4. 유사 라운드 전례

가장 가까운 구조는 [[2026-08-24-quote-invoice-reconciliation/DECISION|R43]](항목 단위 두 리스트 대조, 서면 근거 vs 구두 확인 구분, 재량형 vs 강제고정형 무승부)와 [[2026-08-22-contract-compliance-checklist/DECISION|R41]](조건별 대조, 확인상태 4분류, 작성자≠결정권자 상단 사실+라우팅형)이다. 둘 다 "두 수치/두 목록"을 맞추는 구조라 v1.29(역방향 스캔)·v1.41(집계 검산)·v1.30(상단 판단 금지)이 직접 적용된다. R43에서는 "구두·미확정 보고 강제고정 vs 재량"이 완전 동점으로 끝나 가설이 기각됐다 — 이번 라운드는 그 축을 재고 실사의 "차이 사유"라는 인접 표면에서 다시 만날 가능성이 있으나, backlog의 방향 가설 대기열이 비어 있어(재현 도메인 불일치로 소비되지 않음) 이번엔 독립적인 새 방향 풀로 설계한다.

## 5. 방향 풀 추천

- **a. 결합형 표준** — 4요소 + 품목별 대조 카드(장부 수량·실사 수량·차이 계산·확인 상태) + 역방향 스캔(장부에 없는 실물 발견) + 집계 검산(v1.41) + 상단 사실+라우팅형(v1.30) + 계산값 구분 표시(v1.9/v1.25). 기존 DNA 스택을 이 도메인에 그대로 이식한 기준선.
- **b. 사유 근거강도 분리형** — 본질 리스크 1(사유 창작)을 정면 겨냥. 차이 사유를 "확인된 사유(전표·기록 근거)"와 "추정 사유(담당자 구두 짐작)"로 별도 컬럼 강제 분리하고, 확인된 사유가 없으면 사유란을 "원인 미상"으로 고정 — 구두 추정이 확정 사유로 격상되지 못하게 한다(v1.36/v1.39 계보를 "출처 정체성"에서 "원인 근거"로 확장하는 새 표면).
b는 a와 베이스를 동일 고정하고 이 규칙 유무만 다르게 하지 않는다 — domain-fit 방향 풀 3개는 서로 다른 설계 실험이며, 통제쌍 검증은 backlog에 재검 항목으로 남긴다(첫 관찰이므로).
- **c. 중요도 임계값 우선형** — 본질 리스크 2(경미 vs 조사 필요 기준의 임의 판단)를 정면 겨냥. "허용 오차(중요도 임계값)"를 필수 빈칸으로 받아, 그 기준 이하 차이는 별도의 "정상 범위" 카테고리로 분류하고 기준 초과만 "확인필요"로 승격시킨다. 임계값을 빈칸으로 받지 않으면 AI가 일반 기본값("5% 이내는 정상")으로 메꾼다는 게 R20(예산·기간 빈칸)와 같은 구조.
