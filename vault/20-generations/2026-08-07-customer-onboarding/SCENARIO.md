# SCENARIO — 고객 온보딩 첫 안내 (R28)

동일 테스트 시나리오. 현실적인 초보자 입력값 세트. **values.json에 채울 모든 사실(수치·기한·부가 정보 포함)을 아래에 빠짐없이 명기한다** — 심사자는 이 문서만 보고 결과물을 대조하므로, 여기 없는 수치·표현이 결과물에 등장하면 창작으로 판정한다.

## 공통 원문 사실 (모든 후보 공통, 후보별 필드명만 다르게 매핑)

- **서비스명**: "견적박스" — 소규모 인테리어·시공업체 사장을 위한 온라인 견적서 작성 SaaS.
- **가입 경로·이유**: 인스타그램 광고("종이 견적서 그만, 3분이면 끝나는 전문가 견적서")를 보고 클릭해 무료체험으로 가입. 가입 폼 자유 입력란에 본인이 직접 "손으로 견적서 쓰다 실수도 잦고 시간도 오래 걸려서"라고 작성함.
- **요금제·집행 조건**: 가입일로부터 **14일 무료체험**, **카드 등록 없이 시작 가능**, 체험 종료 **3일 전 이메일로 먼저 알림**, 15일째 자정 자동으로 **프로 플랜(월 29,000원)** 결제 전환.
- **활성화 판정 행동·기준 시점**: "첫 견적서 1건 작성 후 저장", **가입 후 72시간 이내** 기준.
- **첫 행동 절차(실제 화면·소요시간)**: 홈 화면 상단 "새 견적서 만들기" 버튼 → 업종 템플릿(인테리어·시공·전기설비 3종) 중 택1 → 항목 3개 입력하면 합계 자동 계산 → 저장 버튼. **클릭 4번, 약 3분 소요**. 링크: `https://gyeonjeokbox.app/new`.
- **흔한 이탈·망설임 이유** (고객센터 문의 데이터 기준 2가지):
  1. "예전에 비슷한 견적서 툴을 써봤는데 템플릿이 우리 업종(인테리어)에 안 맞아서 결국 손으로 다시 만들었다"는 문의가 반복됨 → 업종별 템플릿 3종을 제공한다는 사실로 해소 가능.
  2. "무료체험 끝나면 자동으로 결제되는 거 아니냐"는 질문이 반복됨 → 카드 등록 없이 시작하고 종료 3일 전에 먼저 알림을 준다는 사실로 해소 가능.
- **발신자·도움 창구**: "견적박스 고객성공팀 박서준 드림 · 막히면 우측 하단 채팅 상담(평일 10시~19시) 또는 help@gyeonjeokbox.app".
- **발송 채널**: 이메일.
- **성공 판정 기준**: 발송 대상의 **35% 이상**이 첫 견적서를 저장하면 성공, **10% 미만**이면 메시지 자체를 재검토.
- **다음 접점 예고 계획**: 72시간 안에 견적서 작성을 안 하면 리마인드 알림, 10일째 활용 팁 메일.
- **정착 팁 소재** (이미 활성화한 사람에게 알려줄 실제 팁 3가지):
  1. 자주 쓰는 견적 항목은 "즐겨찾기"에 저장해두면 다음부터 30초 컷.
  2. 완성된 견적서는 카카오톡 링크로 바로 공유 가능.
  3. 매달 발송한 견적서 현황을 자동 정산 리포트로 받아볼 수 있음.

## 심사 포인트 (참고용, 결과물 대조 기준)

- **정확한 수치 4개**: 무료체험 **14일**·활성화 판정 **72시간**·프로 플랜 **월 29,000원**·성공 판정 **35%/10%**. 이 중 하나라도 결과물에서 다른 숫자로 바뀌면 raw 창작이다.
- **결제 조건 사실 2개**: **카드 등록 없이 시작**, 체험 종료 **3일 전 이메일 알림**. 결과물이 "카드 등록이 필요하다"거나 알림 없이 자동 결제된다고 쓰면 원문과 모순이다.
- **소요시간·단계**: "클릭 4번, 약 3분"만 원문에 있다 — 다른 소요시간(예: "1분이면 끝나요")이나 다른 클릭 수를 쓰면 창작이다.
- **망설임 이유의 구체적 해결책 연결**: 템플릿 안 맞는 문제 → 업종별 템플릿 3종, 결제 걱정 → 카드 등록 불필요+사전 알림. 이 연결을 놓치거나 원문에 없는 제3의 망설임 이유(예: "가격이 비싸서")를 스스로 만들어내면 감점이다.
- **경쟁 툴 실명 창작 금지**: 원문은 "비슷한 견적서 툴"이라고만 하고 특정 경쟁사명을 언급하지 않는다 — 결과물이 구체적 경쟁사 이름을 만들어내면 환각이다.
- **b의 optional 필드는 이번 라운드에서 전부 채워 넣었다** — 메커니즘(a=측정 카드, b=망설임 봉쇄, c=시퀀스) 차이만 순수하게 드러나도록, 빈 필드로 인한 분기(v1.1 optional 처리 원칙)는 이번 비교의 관찰 대상이 아니다.
