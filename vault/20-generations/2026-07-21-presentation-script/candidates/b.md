# 후보 b — 시간 예산 강제형: 총 발표시간을 슬라이드별 목표 발화시간으로 쪼개고 리허설 컷 순서까지 미리 정하는 발표 대본

## fields
| key | label | type | optional | help | placeholder | options |
|-----|-------|------|----------|------|-------------|---------|
| topic | 발표 주제 | text | false | 무엇에 대한 발표인지 한 줄로 | "2026년 신제품 A 출시 전략 발표" | |
| audience | 청중과 그들의 상황 | textarea | false | 청중이 누구이고 지금 어떤 상태·니즈·우려를 갖고 있는지 | "임원진 8명, 지난 분기 실적 부진으로 신사업 투자 리스크에 예민한 상태" | |
| goal | 발표 목표 | select | false | 이 발표가 끝난 뒤 청중에게 원하는 반응 | "투자 승인 받기" | 설득/투자유치, 정보공유/보고, 교육/트레이닝, 동기부여/타운홀 |
| total_minutes | 총 발표 시간(분) | number | false | Q&A는 제외한, 실제로 말할 수 있는 시간 | "15" | |
| qna_minutes | Q&A 별도 시간(분) | number | true | 별도로 배정된 질의응답 시간이 있을 때만 입력 | "5" | |
| slide_count | 예상 슬라이드 수 | number | true | 정해둔 장수가 있으면 입력, 미정이면 비워두면 시간에 맞춰 제안 | "12" | |
| key_points | 꼭 담아야 할 핵심 내용·데이터 | textarea | false | 실제 수치·사례·인용 등 결과물에 들어갈 실데이터 | "3분기 매출 22% 성장, 경쟁사 B사 대비 재구매율 1.8배, 고객 인터뷰 인용: '이전보다 훨씬 빠르다'" | |
| tone | 발표 톤 | select | true | 없으면 목표에 맞는 기본 톤 적용 | "차분하고 데이터 중심" | 차분하고 데이터중심, 열정적이고 에너지틱, 캐주얼하고 편안한, 격식있고 공식적인 |

## template

```
당신은 기업 발표·세미나·피칭 대본을 전문으로 쓰는 발표 코치 겸 스크립트 작가입니다. 발표는 글이 아니라 정해진 시간 안에 소리 내어 전달되는 실시간 수행이라는 점을 항상 최우선으로 고려합니다.

아래 정보를 바탕으로 발표 개요와 슬라이드별 대본을 작성해주세요.
- 발표 주제: {{topic}}
- 청중과 상황: {{audience}}
- 발표 목표: {{goal}}
- 총 발표 시간: {{total_minutes}}분
- Q&A 별도 시간: {{qna_minutes}}분
- 예상 슬라이드 수: {{slide_count}}장
- 꼭 담아야 할 핵심 내용·데이터: {{key_points}}
- 발표 톤: {{tone}}

요구사항:
1. 먼저 핵심 메시지를 한 문장으로 정해 대본 맨 위에 명시하세요 — 시간이 부족해서 다른 부분을 다 잘라내도 청중이 이 한 문장만은 반드시 들고 나가야 하기 때문입니다.
2. 총 발표 시간(Q&A 시간이 주어졌다면 그 시간은 제외)을 오프닝·본론·클로징 3구간으로 나누고, 각 구간과 슬라이드마다 목표 발화시간을 분:초 단위로 배정해 대본에 표기하세요 — 시간 배분 없이 순서대로 쓰기만 하면 뒤 슬라이드가 밀려서 클로징이 잘리기 때문입니다. 기본 배분은 오프닝 10~15%, 본론 65~75%, 클로징 15~20%이되 발표 목표에 따라 조정하세요.
3. 슬라이드별로 작성한 대본을 한국어 평균 발화속도(분당 300~350자) 기준으로 환산했을 때 배정된 목표 발화시간 안에 들어오는지 스스로 계산하고, 초과하는 슬라이드는 원고 단계에서 먼저 줄이세요 — 실제로 소리 내어 읽어보기 전에 원고에서 걸러야 리허설 때마다 매번 다시 잘라내는 일을 줄일 수 있습니다.
4. 오프닝은 시작 15~20초 안에 질문·숫자·사례 중 하나로 청중의 주의를 끄는 훅으로 시작하세요 — 도입부가 늘어지면 청중의 집중이 본론 전에 이미 흩어지기 때문입니다.
5. 본론에는 {{key_points}}의 실제 내용을 반드시 포함하되, 거기 없는 구체적 수치·날짜·사례는 새로 만들지 말고 근거가 불확실한 부분은 [확인 필요]로 표시하세요 — 발표 중 없는 숫자를 만들어 말하면 질의응답에서 바로 신뢰가 무너지기 때문입니다.
6. 클로징에는 핵심 메시지 재확인 한 문장과 청중에게 요구하는 구체적 행동(CTA)을 포함하세요 — 요약 없이 끝나면 청중이 무엇을 해야 할지 각자 다르게 해석하기 때문입니다.
7. "바쁘신 와중에 참석해주셔서 감사합니다" 류의 상투적 인사말 나열이나, "혁신적인" "놀라운" 같은 형용사만으로 이루어진 강조는 쓰지 마세요 — 시간이 가장 아까운 자원인 발표에서 내용 없는 문장은 그 자체로 시간 낭비이기 때문입니다.

출력 형식:
- 핵심 메시지 (한 문장)
- 시간 배분표: 구간/슬라이드 번호 | 제목 | 목표 발화시간 | 예상 글자수
- 슬라이드별 대본: 슬라이드 번호와 목표 발화시간을 각 슬라이드 앞에 표기하고, 그 아래 실제로 읽을 대본 본문을 작성
- 리허설 판정 기준: 실제로 소리 내어 읽어 시간이 초과됐을 때 어느 부분부터 잘라낼지, 이번 발표 내용에 맞춰 우선순위 3단계로 제시 (예: 1순위 배경 설명 축소 → 2순위 사례를 1개로 축소 → 3순위 Q&A 예비 슬라이드 삭제)
```

## anatomy
| part | quote | why |
|------|-------|-----|
| 역할 | "발표는 글이 아니라 정해진 시간 안에 소리 내어 전달되는 실시간 수행이라는 점을 항상 최우선으로 고려합니다" | 이 도메인의 본질 리스크(시간 초과)를 역할 정의 단계에서부터 못 박아, 이후 모든 요구사항이 그 관점에서 나오게 한다 |
| 맥락 | "총 발표 시간: {{total_minutes}}분 / Q&A 별도 시간: {{qna_minutes}}분" | 실행 여건(시간 제약)을 기본값에 맡기지 않고 필수 빈칸으로 받아, 이후 시간 배분 요구사항이 실제 숫자 위에서 작동하게 한다 |
| 요구사항 | "각 구간과 슬라이드마다 목표 발화시간을 분:초 단위로 배정해 대본에 표기하세요" | R14(면접 준비)의 "답변당 목표 발화 시간" 계보를 발표 도메인에 이식한 핵심 문장 — 검증 가능한 산출물(시간 표기)을 강제한다 |
| 요구사항 | "한국어 평균 발화속도(분당 300~350자) 기준으로 환산했을 때 배정된 목표 발화시간 안에 들어오는지 스스로 계산하고" | 리허설(소리 내어 시간 재기)이라는 중간 루프를 원고 작성 단계로 앞당겨, 시간 초과라는 물리적 리스크를 사전에 걸러낸다 |
| 출력 형식 | "리허설 판정 기준: ... 우선순위 3단계로 제시" | 시간 초과가 실제로 벌어졌을 때의 대응까지 결과물에 포함시켜, 발표 직전 리허설에서 바로 쓸 수 있는 실행 자산으로 만든다 |

## tips
1. **total_minutes는 실제 발화 가능 시간만 넣으세요.** Q&A나 사회자 소개 시간까지 포함해서 적으면 슬라이드별 시간 배정이 실제보다 여유 있게 계산되어, 리허설에서 초과가 드러납니다.
2. **slide_count를 비워두면 AI가 총 시간에 맞춰 적정 장수를 역산합니다.** 이미 정해진 템플릿(회사 표준 덱 등)이 있어 장수가 고정돼 있을 때만 채우세요.
3. **key_points에는 실제 숫자와 인용을 그대로 붙여넣으세요.** 여기 없는 수치는 대본에서 [확인 필요]로 표시되므로, 발표에서 꼭 말해야 하는 숫자는 반드시 이 빈칸에 넣어야 합니다.
4. **리허설 판정 기준은 받은 그대로 쓰지 말고 실제로 소리 내어 한 번 읽은 뒤 우선순위를 다시 확인하세요.** 사람마다 발화 속도가 다르므로 분당 300~350자는 출발점이지 정답이 아닙니다.
