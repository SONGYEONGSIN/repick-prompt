# DOMAIN — 발표 자료 개요와 스크립트 작성

Named query 실행 (2026-07-21, R17). 근거: DNA v1.14, ledger 최근 5건, MEMORY.md.

## 1. 본질 리스크

발표는 **정보 과다로 핵심 메시지가 실종**되는 것이 1순위 실패 원인이다 — 발표자는 "아는 걸 다 말하고 싶다"는 유혹에 빠져 슬라이드/포인트를 계속 늘리고, 청중은 발표가 끝난 뒤 "그래서 결론이 뭐였지"를 남기지 못한다. 2순위는 **시간 초과** — 발표는 글쓰기류(이메일·보고서)와 달리 실시간 낭독이라는 물리적 제약이 있어, 대본 분량과 실제 발화 시간이 어긋나면 뒷부분이 잘리거나 급하게 읽히는 사고가 실전에서만 드러난다.

## 2. 본질 루프

"만들면 끝"에 가깝다 — 단발성 실전 수행(자소서·이력서·면접 준비류와 동형). 다만 **리허설이라는 중간 루프**가 존재한다: 대본을 쓰고 → 소리 내어 읽어보며 시간을 재고 → 초과분을 잘라내는 반복이 표준 워크플로우다. 이는 R14(interview-qa-prep) c후보의 "발화 시간·판정 기준" 계보와 같은 축 — 측정-반복(마케팅 이메일류)과는 다르게, 측정 대상이 "성과 지표"가 아니라 "발화 시간 자체"라는 점이 특이하다.

## 3. 결과물의 소비 방식

이중 소비: (1) 발표자 본인이 리허설 자료로 **정독하며 소리 내어 연습** (2) 청중은 슬라이드를 **3~5초 스캔**하며 발표자의 말을 듣는다. 두 소비자·두 매체(말/화면)가 다른 문서라는 점이 유튜브 스크립트(장면별 대본+썸네일)와 구조적으로 가장 유사하다.

## 4. 유사 라운드 전례

- **R14 interview-qa-prep** — 실시간 구두 수행 준비라는 점에서 가장 가깝다. c(연습 루프) 후보의 "발화 시간·발음 유의구간·판정 기준" 장치가 근소 2위였으나 강점으로 지목됨 — 리허설 판정 기준의 유효성 신호.
- **R6 cover-letter** — "다음 관문 대비물"(자소서→면접 예상 질문) 부속물 패턴. 발표도 "Q&A 예상 질문"이 다음 관문 대비물로 이어질 수 있다.
- **R4 reels-script** — 낭독/촬영이라는 실행 여건 제약이 있는 스크립트류. 시간·분량 미스매치가 감점 요인이었던 전례(혼자 촬영 불가 장면)와 유사하게, 발표는 "배정 시간과 분량 불일치"가 실행 여건 리스크다.

## 5. 방향 풀 추천

1. **a = 결합형 표준** — 구조 내장(오프닝 훅-본론-클로징) + 코치형 help + 대상 맥락 빈칸(청중 특성·발표 상황). 베이스라인.
2. **b = 시간 예산 강제형** (본질 리스크2·본질 루프 정면 타격) — 총 발표 시간을 섹션별로 나눠 슬라이드마다 "목표 발화 시간" 배정을 요구사항으로 강제하고, 리허설 판정 기준(읽었을 때 초과 시 잘라낼 우선순위)까지 출력 형식에 포함.
3. **c = 단일 메시지 수렴형** (본질 리스크1 정면 타격) — "발표가 끝나고 청중이 기억해야 할 딱 한 문장"을 먼저 정하게 하고, 전 슬라이드가 그 한 문장에 기여하는지 자체 검증해 기여하지 않는 슬라이드는 스스로 컷하는 발산→수렴 구조.

## 예측-실제 대조 (라운드 종료 후 기입)

- 예측: 본질 리스크가 둘(메시지 실종/시간 초과)로 나뉘어 단일 방향 우세를 점치기 어려움 — b·c 중 하나가 이길 가능성이 결합형(a)보다 높음 (R12·R14·R15 3연속 결합형 패배 추세와 일치 예상).
