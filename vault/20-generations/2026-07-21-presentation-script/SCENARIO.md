# SCENARIO — 발표 자료 개요와 스크립트 작성 (R17)

현실적인 초보자 입력값 세트. **values.json에 채울 모든 사실을 아래에 빠짐없이 명기** — 심사자는 이 문서만 보고 결과물을 대조하므로, 아래에 없는 사실이 결과물에 등장하면 창작(환각)으로 간주한다.

## 상황

한 CS/오퍼레이션 담당자가 3개월 전 도입한 고객 셀프서비스 챗봇의 성과를 팀장급 정기 회의에서 공유하고, 내년 1분기 확장(2개 채널 추가 적용) 예산 승인을 받아야 하는 발표를 준비 중이다.

## 확정 사실 (values.json에 반영될 전부)

- **발표 주제**: 고객 셀프서비스 챗봇 도입 3개월 성과 공유 및 내년 1분기 확장 예산 승인 요청
- **발표 자리 성격**: 월간 정기 팀장 회의. 발표 직후 팀장들이 구두로 확장 예산 승인 여부를 논의·결정한다.
- **청중**: 팀장 8명(CS팀장, 개발팀장, 마케팅팀장 등). 챗봇 도입 초반 3주간 오작동으로 문의량이 오히려 22% 늘어 "일만 늘었다"는 불만을 제기한 적 있고, 실제 효과가 있었는지 회의적인 분위기.
- **발표 목표**: 초반 불만에도 불구하고 팀장들이 내년 1분기 확장(2개 채널 추가) 예산을 승인하도록 설득하는 것.
- **발표 시간**: 15분 (이후 Q&A 5분 별도, 총 회의 배정 시간 20분)
- **예상 슬라이드 수**: 미정 (비워둠 — AI가 시간에 맞춰 제안)
- **핵심 데이터·실데이터** (전부):
  - 평균 문의 처리시간: 도입 전 42분 → 도입 후 27분 (약 36% 단축)
  - 월 오류(오배정) 건수: 15건 → 3건
  - 고객 만족도(CSAT, 5점 만점): 3.4 → 4.1
  - 도입 초반 3주간: 챗봇 오작동으로 인입 문의 오히려 22% 증가, 이 시점에 팀장들 불만 제기
  - 현재 운영비: 월 200만원. 확장(2개 채널 추가) 시 월 150만원 추가 소요
  - 고객 인터뷰 인용 원문: "예전보다 훨씬 빠르게 답을 받아서 좋아요"
- **톤**: 담백하고 데이터 중심
- **피해야 할 표현·주의할 배경** (a용): 초반 3주 불만은 언급하되 "실패"라는 표현은 쓰지 않을 것 — 경쟁 서비스 대신 "유사 서비스"라는 표현 사용
- **회사 관행상 반드시 넣어야 하는 항목** (c용): 발표 서두에 목차 슬라이드, 마지막에 다음 분기 일정 슬라이드는 항상 포함
- **Q&A 별도 시간** (b용): 5분

## values.json에 없는(의도적 공백) 값

- 예상 슬라이드 수(slide_count) — 비워서 AI가 시간에 맞춰 슬라이드 수를 스스로 제안하는지 확인.

## 심사 배치 (순서 편향 통제)

라틴 방진 3회 — 3명의 독립 심사자에게 각기 다른 익명 순서로 결과물을 제시한다 (각 후보가 각 위치 A/B/C에 1회씩 배정).

- 심사 1: A=a, B=b, C=c
- 심사 2: A=b, B=c, C=a
- 심사 3: A=c, B=a, C=b
