# DOMAIN — 번역·표기 일관성 점검표

> named query 실행 (domain-fit.md), 방향 풀 설계 직전.

## 1. 본질 리스크

원문과 번역을 문장 단위로 대조할 때 실패하는 1순위 원인은 **누락(omission)이 "의역"으로 위장되는 것**이다 — 번역에서 통째로 빠진 문장을, 검토자가 "그 정도는 의역 범위"라고 스스로 설득해 넘어가면 정작 사용자에게 전달돼야 할 정보(경고문·조건·수치)가 조용히 사라진다. 두 번째 리스크는 **용어 불일치**(같은 원어 용어가 문서 안에서 다르게 번역됨)가 개별 문장 단위 대조에서는 각 문장이 "오역은 아님"으로 통과해버려 문서 전체 수준의 불일치가 보이지 않는 것. 세 번째는 **의미 변경과 스타일적 의역의 경계를 검토자(AI)가 재량으로 판단**하다가 판정이 라운드마다 흔들리는 것 — v1.31~v1.33 계보(등급 고정)가 반복 확인한 리스크가 그대로 재현될 표면이다.

## 2. 본질 루프

"만들면 끝"에 가깝다 — 원문·번역 한 쌍을 받아 한 번 대조해 점검표를 내는 완결형 감사 산출물이다(revision-comparison-memo·requirement-compliance-check와 같은 유형). 실험 문법(지표·판정·후속 측정)은 방향 후보에 필수가 아니다. 다만 번역은 보통 여러 언어·여러 문서에 반복 적용되므로, 팁 절에 "다음 문서/언어 쌍에도 같은 틀을 재사용하라"는 안내는 유효하다(감사형 문서의 통상적 재사용 팁 수준).

## 3. 결과물의 소비 방식

번역 QA 담당자 또는 번역가 자신이 게시(출시) 전에 훑어보며 어떤 줄을 고칠지 결정하는 **작업 체크리스트**로 소비된다. 통째로 게시되는 완성 문서(v1.20의 FAQ류)가 아니라, 검토자가 항목별로 대조하고 일부만 수정 지시로 넘기는 **감사형 중간 산출물**이다 — requirement-compliance-check·requirement-source-traceback과 같은 소비 방식. 항목 수가 많으면 스캔 우선순위(심각도)가 중요해진다.

## 4. 유사 라운드 전례와 승부처

- **revision-comparison-memo (R33)**: 두 시점(개정 전/후) 원문을 조항 단위로 대조, 완전 신설·삭제는 등급 고정 — 축이 "시간"이라면 이번은 축이 "언어"다. 등급 고정(v1.31) 원칙이 그대로 이식 가능한 구조.
- **requirement-source-traceback (R38)**: 항목마다 원문 인용 + 확인 상태 3분류. "출처 강도/출처 정체성 분리"(v1.36)는 이번 도메인에 직접 대응하는 축이 없다(번역 검증은 출처가 항상 원문 하나).
- **requirement-compliance-check (R31)**: 정방향 대조(목록→원문)만으로는 목록 밖 리스크를 놓친다 — 역방향 커버리지 스캔(v1.29) 신규. 번역 도메인은 이 원칙이 "대조 대상이 조항이 아니라 문장"으로 그대로 재현될 자리라고 backlog가 이미 지목했다(2026-08-11 보충 표).
- **vendor-comparison-scorecard (R37)**: N×M 그리드(문장×판정축)에서 anti-slop 구조 마커(①②③) 자발적 신설 리스크 — 문장이 많은 이 도메인도 같은 그리드 구조라 요구사항에 명시할 것.

## 5. 방향 풀 추천

- **a. 결합형 표준** — 문장 단위 대조 카드(원문 인용 + 번역 인용 + 판정: 정확/의미 변경/누락/표기 불일치) + 확인 상태 라벨(v1.27) + 역방향 스캔(v1.29를 문장 입도로 재현: 번역문에서 원문에 없는 내용이 추가됐는지도 함께 확인) + 구조 마커 금지(v1.35) 명시.
- **b. 용어집 우선형** — 핵심 용어(원어→고정 번역) 전용 빈칸을 별도로 받아, "용어집 위반"과 "일반 오역·누락"을 별도 판정 축으로 분리한다. 본질 리스크 2(문장 단위 대조에서 안 보이는 문서 전체 수준의 용어 불일치)를 정면 겨냥.
- **c. 심각도 등급 고정형** — 완전 누락(문장 전체가 번역에 없음)은 최고 심각도, 의미 변경(원문의 조건·수치·주체가 바뀜)은 그다음, 스타일적 의역 차이는 최하위로 등급을 규칙에 고정하고 검토자 재량에 맡기지 않는다. 본질 리스크 3(의미 변경 vs 의역의 재량적 경계)을 정면 겨냥 — v1.31~v1.33 등급 고정 계보의 여섯 번째 도메인 재현 기회.
