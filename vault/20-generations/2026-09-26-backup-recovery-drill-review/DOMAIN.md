# DOMAIN — 백업·복구 점검 기록

> named query 실행 결과 (`vault/40-queries/domain-fit.md`). GENERATE 방향 풀 설계 직전.

## 1. 본질 리스크

이 도메인의 1순위 실패 원인은 **"복구 시험을 했다는 사실"과 "요구 기준(RTO/RPO)을 실제로 충족했다는 사실"을 섞어버리는 것**이다 — 시험이 시행됐다는 이유만으로 충족으로 기록하거나, 반대로 시행됐는지 자체가 불분명한 항목을 재량으로 완화 판정하는 실패다. 세부적으로 최소 다섯 갈래가 갈린다:
1. 시험 자체가 아예 없음(기한 지남, 기록 전무) — equipment-inspection의 "미실시" 완전부재 등급 고정(v1.31/32/54)과 같은 축.
2. 시험은 했지만 측정값이 요구 기준(RTO≤N시간, RPO≤N시간)을 초과 — **정량 임계값 대조 계산**이 이 도메인 고유의 신규 표면이다(성능 회귀 보고서 R42의 기준선 대조와 구조적으로 같으나, 임계값이 시스템마다 다르게 주어진다는 점이 다르다).
3. 시험 주기 자체가 아직 도래하지 않음 — equipment-inspection의 회차 계산(v.50)과 동일 축.
4. 시험을 시도했으나 환경 문제로 측정 자체가 실패(검증 실패) — v1.43의 "검증 자체의 실패로 부재 여부 미확인" 축.
5. 수치 없이 "문제없었다" 식 모호한 서술만 있음 — 확인 상태 라벨의 "원문 표현 모호" 사유(v1.27).
그리고 **정량 기준은 충족했지만 정성적 위험 신호(데이터 유실 의심 등)가 남아 있는 경우**(v1.42, 정량 임계값이 정성 신호를 지우지 않는다)도 이 도메인에서 자연스럽게 재현된다 — RTO는 지켰지만 복구 담당자가 "일부 트랜잭션 로그 유실 의심"을 남긴 경우.

## 2. 본질 루프

**측정·반복이 본질이다.** 백업·복구 점검은 "한 번 만들면 끝"이 아니라 분기·반기 등 정해진 주기로 반복 시행되고, 매 회차 RTO/RPO라는 명시적 수치 기준과 대조된다 — equipment-inspection-history-reconciliation(R54)과 같은 "주기 계산형" 루프이며, 여기에 더해 판정 자체가 "시행 여부"뿐 아니라 "수치 충족 여부"까지 이중으로 요구된다는 점에서 순수 주기 계산보다 한 겹 더 복잡하다.

## 3. 결과물의 소비 방식

작성자는 IT/보안 실무자(백업 운영 담당자), 결정권자는 정보보호책임자(CISO)나 감사 대응 담당자로 **작성자≠결정권자**가 명확히 분리된 감사형 도메인이다. 소비 방식은 ISMS-P/ISO27001류 내부 감사 증적 문서와 동일하게 **시스템 단위 항목별 대조**(스캔이 아니라 항목 하나하나를 결재선이 확인) — training-completion-checklist(R47)·equipment-inspection(R54)과 같은 "과정/장비별 1:1 대응" 소비 패턴에 해당한다.

## 4. 유사 라운드 전례

- **equipment-inspection-history-reconciliation (R54)**: 주기 계산 + 완전부재 고정 + 폐기 장비 별도 절(결번 방지) + 명단 밖 역방향 스캔 — 구조가 가장 가깝다.
- **performance-regression-report (R42)**: 측정치를 기준선과 대조하는 정량 임계값 비교, raw 밖 인과 결합 금지.
- **data-migration-verification-report (R46)**: 검증 자체의 실패(조회 실패)를 별도 확인필요 사유로 분리.
- **inventory-physical-count-reconciliation (R45)**: 정량 임계값이 정성 위험 신호를 지우지 않는다(OR 규칙 함정).
- **license-subscription-usage-review (R57)**: 완전부재/이탈 트리거 형태 완전 열거 요구.

## 5. 방향 풀 추천

1. **a — 결합형 표준**: 기존 DNA(확인 상태 3~4분류+인간 라우팅 v1.27/39/43, 완전부재 등급 고정 v1.31/32/54, 역방향 스캔 v1.29, 집계 검산 v1.41, 결번 방지 별도 절 v1.50, 정량 임계값이 정성 신호를 지우지 않는다 v1.45)를 이 도메인에 그대로 이식한 표준형. RTO/RPO 초과 계산은 요구사항 문장으로만 지시(별도 프레임워크 절 없음).
2. **b — 가이드 최대화형**: help/placeholder를 RTO/RPO 개념 자체를 모르는 초보 작성자도 채울 수 있도록 최대화. 이탈 방지 최우선.
3. **c — 정량 임계값 대조 프레임워크 내장형 (본질 리스크 정면 겨냥)**: "시스템마다 RTO/RPO 목표 대비 실측치 갭을 먼저 계산해 노출하는 별도 계산 절"을 요구사항에 구조화 — 본질 리스크 2(정량 대조)를 정면으로 겨냥한다.
