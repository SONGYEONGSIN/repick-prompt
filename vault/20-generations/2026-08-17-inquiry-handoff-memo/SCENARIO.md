# SCENARIO — 문의 이관 인계 메모 (R36)

동일 테스트 시나리오 1개. 심사자는 이 문서만 보고 산출물을 대조하므로, values.json에 채울 모든 사실을 아래에 빠짐없이 명기한다.

## 원문 대화 이력 (raw, 세 후보 모두 동일하게 투입)

```
[8/15 14:02] 고객: 어제 도착한 텀블러 뚜껑에 금이 가 있어요. 이거 원래 이런 건가요?
[8/15 14:05] 상담원(박서준): 불편을 드려 죄송합니다. 보내주신 사진을 보니 배송 중 충격으로 파손된 것 같습니다. 환불과 재발송 중 원하시는 방법을 말씀해 주시면 바로 도와드리겠습니다.
[8/15 14:07] 고객: 재발송은 시간이 걸릴 것 같아서 그냥 환불로 해주세요. 이번 주 안에 처리 가능할까요?
[8/15 14:09] 상담원(박서준): 네, 환불로 처리해드리겠습니다. 다만 결제 취소는 저희 CS팀이 아니라 결제팀 확인이 필요해서요. 내일(8/16)까지 결제팀 확인하고 진행 상황 다시 안내드리겠습니다.
[8/15 14:10] 고객: 네, 알겠습니다. 근데 이 텀블러는 재구매할지 아직 잘 모르겠어요. 이런 파손이 자주 있는 편인가요?
[8/15 14:12] 상담원(박서준): 저희가 파악하기로는 파손이 자주 발생하는 편은 아닙니다. 이번 건은 배송 중 드문 경우로 보입니다.
[8/16 16:20, 전화] 고객: 어제 문의드렸는데 아직 환불 관련 연락을 못 받았어요. 오늘 중으로 확인해 주실 수 있나요? 이렇게 계속 미뤄지면 곤란해서요.
[상담원(최유나) 통화 메모, 8/16 16:25]: 결제팀에 확인 요청 티켓(#4482) 등록함. 아직 회신 없음. 통화 중 고객 목소리가 다소 격앙되어 있었음. 환불 금액이나 처리 완료 여부는 통화에서 확인하지 못한 채 종료.
```

## 대화 이력 안의 사실 관계 요약 (심사 대조용)

- **사실**: 고객이 텀블러 뚜껑 파손을 신고(8/15 14:02) / 박서준이 사진 확인 후 응답(8/15 14:05) / 고객이 환불을 요청하고 "이번 주 안" 처리를 희망(8/15 14:07) / 박서준이 "내일(8/16)까지 결제팀 확인 후 안내"를 **약속**함(8/15 14:09, 이미 한 약속) / 고객이 재구매 여부를 "아직 잘 모르겠다"고 말함(8/15 14:10 — 미정 자체가 사실) / 고객이 8/16 16:20 전화로 재문의하며 "오늘 중 확인"을 요청하고 "계속 미뤄지면 곤란하다"고 명시적으로 불만을 표현 / 최유나가 결제팀에 티켓 #4482를 등록(8/16 16:25) / 8/16 16:25 시점까지 결제팀 회신 없음.
- **추정(원문에 "~것 같다"/"파악하기로는" 등으로 표시된 상담원의 짐작)**: 박서준의 "배송 중 충격으로 파손된 것 같다"(파손 원인은 실사되지 않았다, 확정 아님) / 박서준의 "파손이 자주 발생하는 편은 아니다"(근거 데이터 언급 없는 개인적 인상) / 최유나의 "고객 목소리가 다소 격앙되어 있었음"(원문 인용이 아니라 통화 후 상담원이 남긴 주관적 관찰 — 텍스트 근거가 없으므로 "확인된 사실"로 격상시키면 안 되고, 상담원의 관찰로 표시해야 한다).
- **미확인(대화 이력 어디에도 답이 없음 — 후보가 이 자리를 창작하면 환각 감점)**: 정확한 환불 금액(원문에 가격이 전혀 등장하지 않는다) / 결제팀 확인 처리의 현재 진행 상태(티켓 등록 후 회신 없음, "진행중"인지 "지연"인지 원문만으로는 확정 불가) / 고객의 최종 재구매 의향(고객 스스로도 아직 정하지 않았다고 말했다 — 이것 자체가 사실이며, 재구매 여부를 추정해서 채우면 창작이다).
- **이미 한 약속과 기한 경과**: 박서준이 "내일(8/16)까지 결제팀 확인 후 진행 상황 안내"를 약속했다. 오늘은 8/17이고(아래 인계 시점 참고) 그 안내는 아직 이뤄지지 않았다 — 기한이 지났다.
- **인계 배경**: 박서준(1차, 8/15 채팅 응대) → 최유나(2차, 8/16 전화 응대) → 오늘(8/17) 주간 담당자에게 인계. 인계 사유는 근무 교대.

## 후보별 values.json 입력값 안내

- customer_info 계열 필드: `김하은 고객, 주문번호 20260814-2207, 일반 회원, 연락처 010-2233-5566`
- previous_agent 계열 필드: `박서준(1차, 8/15 채팅 응대), 최유나(2차, 8/16 전화 응대)`
- next_agent 계열 필드: `이하늘, 주간 CS팀`
- handoff_reason 계열 필드: 근무 교대(각 후보의 select 옵션 중 가장 가까운 값으로 매핑)
- 인계 시점(candidate b의 handoff_now): `2026년 8월 17일 오전 9시`
- 확인처(candidate a의 internal_resources / candidate c의 verification_contact / candidate b의 verification_channel): 결제팀(정산·환불 처리, 슬랙 #payment-ops), 필요 시 물류팀(파손 실사)
- 확인 기한(candidate c의 verification_deadline): `다음 고객 접촉 전까지`

## 심사 배치 (순서 편향 통제)

3자 비교 — 라틴 방진 3라운드로 익명(A/B/C) 블라인드 심사. 각 후보가 각 위치(첫 번째/두 번째/세 번째 제시)에 1회씩 오도록 배치한다.

- 라운드 1: A=a, B=b, C=c
- 라운드 2: A=b, B=c, C=a
- 라운드 3: A=c, B=a, C=b

심사 기준: 지시 이행도 / 바로 사용 가능성 / 구체성 / 환각·과장 억제 (각 30점, 총 120점). 결과물이 곧 증거이므로 조립된 프롬프트를 실제로 실행한 산출물만 심사한다.
