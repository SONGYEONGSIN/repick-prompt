# DOMAIN.md — 뉴스레터 작성 (R18)

Named query 실행: [[domain-fit]] (GENERATE 방향 풀 설계 직전).

## 1. 본질 리스크

뉴스레터가 실패하는 1순위 원인은 **다목적 과적재**가 아니라 **"이번 호를 왜 지금 열어야 하는가"의 부재** — 사보식으로 이것저것 다 담아 특정 없는 소식 나열이 되면 구독자는 제목만 보고 열지 않는다(오픈 실패). 두 번째 리스크는 **매호 포맷이 흔들려 신뢰가 쌓이지 않는 것**(이번엔 이렇게, 다음엔 저렇게 — 구독이 아니라 발송물마다 새로 평가받음). marketing-email(R12)의 "욕심/다목표"와 인접하지만, 뉴스레터는 단일 캠페인이 아니라 **반복 발송물**이므로 리스크의 축이 "이번 한 통의 목표 분산"이 아니라 "회차 간 일관성 부재 + 오픈 이유 부재"로 이동한다.

## 2. 본질 루프

**"만든 뒤 측정·반복"이 본질** — 뉴스레터는 1회성 문서가 아니라 회차(issue)가 누적되는 시리즈다. marketing-email(R12)·insta-content(R15)처럼 성과 측정(오픈율·클릭)이 본질이지만, 여기에 더해 **회차 간 연속성**이라는 별도 루프가 있다: 이번 호가 다음 호 구독 유지로 이어지는가. 즉 측정 루프(이번 발송이 목표 행동을 만들었나)와 시리즈 루프(이번 호가 다음 호를 계속 열게 만들었나)가 이중으로 작동한다.

## 3. 결과물의 소비 방식

받은편지함에서 **제목·프리뷰 텍스트로 3초 내 열지 결정**(링크드인 훅과 유사한 승부처), 연 뒤에는 **모바일 스크롤로 30초~2분 스캔** — 정독이 아니라 훑어보다 관심 섹션만 클릭. 결재·정독형 문서(보고서·제안서)와 반대 극단.

## 4. 유사 라운드 전례

- **marketing-email(R12)**: 가장 가까운 구조 — 발송물·측정 본질. 승부처는 성과 판정 카드(목표 행동 층위 지표). 단, R12는 단발 캠페인이라 "회차 간 일관성" 축이 없다.
- **blog-draft(seed)**: 글쓰기 본질(제목·구조·톤) 공유하지만 1회성 문서 — 반복 발송·구독 유지 개념 없음.
- **insta-content(R15)**: 측정-실험 문법 승리 + "감의 출처는 감으로" 정직 처리. 뉴스레터도 발행 판정 카드 계보 적용 후보.
- **business-email-reply(R16)**: 무관 (원문 대응형, 뉴스레터는 발신 주도형).

## 5. 방향 풀 추천 (3개, 서로 다른 설계 방향)

- **a = 결합형 표준** (프레임워크 내장 + 코치형 help + 대상 맥락 빈칸) — 기본 포함. 지금까지 8승(R7·R9·R10·R11·R17 등)의 범용 강자, 베이스라인.
- **b = 발행 성과 판정형** (실험 문법: 이번 호의 단일 목표 행동 정렬 + 발행 판정 카드 — 오픈율이 아니라 목표 행동 층위 지표·판정 시점·다음 호 조정안) — R12·R15 계보를 뉴스레터 도메인에 적용, 측정 루프를 정면 겨냥.
- **c = 시리즈 정체성 고정형** (매호 반복되는 고정 섹션 포맷 + 발신자 목소리/캐릭터 고정 + "왜 계속 구독해야 하는가"를 매호 첫 줄에 답하는 구조) — 본질 리스크 2(회차 간 일관성 부재)를 정면 겨냥, 지금까지 없던 신규 축.

## 예측

b(측정 루프 정렬) 또는 c(시리즈 일관성)가 결합형(a)을 이길 가능성 — 뉴스레터는 marketing-email형 단발 리스크만이 아니라 시리즈 리스크가 추가된 도메인이므로, 신규 축인 c가 두드러질 수 있다는 가설. 라운드 종료 후 DECISION.md에 예측-실제 대조 1줄 기록.
