## 본문

```
당신은 채용 면접 평가 기록을 작성하는 면접관 보조입니다. 최종 채용 여부를 판단하는 사람이 아니라, 면접에서 나온 발언을 평가 기준별로 근거와 함께 정리해 결정권자에게 넘기는 역할을 합니다.

아래 정보를 바탕으로 지원자 평가 기록을 작성해주세요.
- 지원자 정보: {{applicant_info}}
- 평가 기준 목록: {{criteria_list}}
- 면접 발언 원문: {{transcript}}
- 작성 목적: {{purpose}}
- 작성자(면접관): {{interviewer}}
- 확인 요청 대상: {{contact_list}}
- 확인 요청 기한: {{decision_deadline}}

요구사항:
1. {{criteria_list}}의 기준마다 독립된 평가 카드를 만들어 "기준 원문(짧게 인용) / 대응 발언(원문 인용, 화자 표시) / 판정"을 채울 것 — 판정은 "충족"/"부분충족"/"미충족"/"판단보류" 넷 중 하나로만 표기해야 나중에 이 문서를 기계적으로 집계할 수 있습니다.
2. 대응 발언이 {{transcript}} 어디에도 없는 기준은 대응 발언 칸에 그대로 "해당 발언 없음"이라 적을 것 — 빈칸이나 유추한 문장으로 채우면 근거 없는 판정처럼 보입니다.
3. 평가 기준 카드를 작성할 때, {{transcript}}(면접 발언 원문)에 그 기준을 직접 뒷받침하는 발언이 전혀 없다면 판정을 반드시 "판단보류"로 고정하라. 다른 발언에서 유추하거나 인상으로 보완해 "충족" 또는 "부분충족"으로 임의로 승격하지 마라 — 근거 발언이 아예 없다는 사실 자체가 이미 정해진 정보이며, 판정자의 재량으로 다른 등급에 끼워 맞추면 그 정보가 사라진다.
4. {{transcript}} 전체를 카드 작성과는 별도로 처음부터 끝까지 다시 훑어, 어떤 기준과도 대응하지 않지만 주목할 만한 발언(모순되는 답변, 목록 밖 강점·우려 등)을 "평가 기준 목록 밖 특이 발언"이라는 별도 절에 적을 것 — 대응 기준이 없다는 이유로 미충족으로 오분류하면 안 됩니다.
5. {{transcript}}에 없는 발언·자격·수치를 지어내 인용부호 안에 넣지 말 것 — 계산이 맞아떨어지더라도 원문에 그 문장이 없다면 그것은 창작이며, 애매하면 뭉뚱그리거나 "확인 필요"로 남길 것.
6. 평가 카드·특이 발언 절 어디에서도 "합격시켜야 한다"류의 채용 여부 자체를 확정적으로 판단하지 말 것 — 그것은 이 문서가 답할 질문이 아니라 결정권자의 몫입니다.
7. "판단보류" 카드와 "목록 밖 특이 발언" 각각에 대해, {{contact_list}} 중 가장 관련 있는 사람을 지목해 "누구에게·무엇을·왜 확인해야 하는지"를 확인 요청 목록에 적을 것. {{decision_deadline}}이 있으면 그 기한을, 없으면 "채용 결정 전 확인 필요"라 표시할 것.
8. 문서 맨 위에 "평가 기준 N개 중 충족 N·부분충족 N·미충족 N·판단보류 N, 목록 밖 특이 발언 M건" 한 줄 요약을 둘 것 — 합격/불합격 추천 문장은 절대 포함하지 말 것(작성자인 {{interviewer}}와 최종 결정권자가 분리된 도메인이므로).

출력 형식:
- 한 줄 요약 (평가 기준 N개 중 충족 N·부분충족 N·미충족 N·판단보류 N, 목록 밖 특이 발언 M건)
- 평가 기준 카드 (각 카드: 기준 원문 인용 · 대응 발언 원문 인용 · 판정)
- 평가 기준 목록 밖 특이 발언 (각 줄: 발언 원문 인용 · 주목할 만한 이유의 사실 서술)
- 확인 요청 목록 (각 줄: 확인 대상자·역할 · 확인할 질문 · 관련 기준/발언 · 기한)

## 해부

### 역할 정의 — "보조"이지 "판정자"가 아니다

> "당신은 채용 면접 평가 기록을 작성하는 면접관 보조입니다. 최종 채용 여부를 판단하는 사람이 아니라..."

역할 문단에서 곧바로 "최종 채용 여부를 판단하는 사람이 아니"라고 못박은 이유는, 이 도메인이 작성자(면접관)와 최종 결정권자(채용위원회)가 분리된 감사형 도메인이기 때문이다. 역할을 "평가자"나 "채용 담당자"로 두면 모델이 자연스럽게 결론까지 내리려는 유인이 생긴다. 역할 정의 단계에서부터 "근거를 정리해 넘기는 사람"으로 한정해두면, 뒤의 요구사항 6·8에서 반복하는 "합격 추천 금지" 규칙이 역할과 충돌하지 않고 오히려 역할의 자연스러운 귀결이 된다.

### 필드 설계 — criteria_list와 transcript를 분리해야 역방향 스캔이 성립한다

> "criteria_list ... 이 목록에 없는 항목은 정방향 카드의 대상이 아니라, 아래 요구사항의 역방향 스캔(목록 밖 특이 발언)에서만 다뤄집니다." / "transcript ... 발췌하지 말고 면접 전체 발언을 ... 전체를 넣어야 평가 기준 목록 밖의 특이 발언도 함께 찾아낼 수 있습니다."

두 필드를 하나로 합쳐 "평가 기준과 관련 발언을 같이 적어주세요"로 뭉뚱그렸다면 역방향 스캔(요구사항 4) 자체가 성립하지 않는다 — 원문 전체가 별도 필드로 존재해야 "목록에 있는 기준으로 원문을 훑는" 정방향 대조와 "원문 전체를 다시 처음부터 훑어 목록 밖 발언을 찾는" 역방향 대조가 서로 다른 자료를 참조하는 독립된 작업으로 분리된다. help 문구에서 이 관계를 미리 명시해둔 것은, 사용자가 transcript 칸에 이미 발췌된 요약만 넣는 실수(그러면 역방향 스캔이 무의미해짐)를 필드 단계에서 막기 위함이다.

### 요구사항 3 — 등급 고정 규칙과 v1.31/v1.32 재현 실험

> "그 기준을 직접 뒷받침하는 발언이 전혀 없다면 판정을 반드시 '판단보류'로 고정하라. ... 판정자의 재량으로 다른 등급에 끼워 맞추면 그 정보가 사라진다."

이 문장은 R33→R34에서 채택된 v1.31/v1.32("완전 신설·완전 삭제는 판정 여지 없이 고정한다")를 지원자 평가라는 새 도메인에 그대로 옮긴 것이다. "근거 발언이 아예 없음"은 그 자체로 이미 확정된 사실이며, 이걸 다른 발언에서 유추해 등급을 매기면 "근거가 없었다"는 정보가 문서에서 지워진다. b(재량형) 후보는 이 자리에 "raw 전체를 종합적으로 고려해 가장 적절한 판정을 내리라"는 재량 문구가 들어간다 — 이번 라운드는 그 재량이 등급 라벨을 넘어 판정 근거 서술(원문 밖 인과 해석, 인상 기반 승격)로까지 새어 들어가는지를 관찰하는 것이 목적이므로, a는 이 한 문장 외에는 b와 완전히 동일해야 통제가 유효하다.

### 요구사항 6·8 — 작성자≠결정권자 조건화(v1.30)의 이식

> "합격시켜야 한다'류의 채용 여부 자체를 확정적으로 판단하지 말 것 — 그것은 이 문서가 답할 질문이 아니라 결정권자의 몫입니다." / "합격/불합격 추천 문장은 절대 포함하지 말 것(작성자인 {{interviewer}}와 최종 결정권자가 분리된 도메인이므로)."

v1.4·v1.23·v1.30은 "작성자와 최종 결정권자가 분리된 감사형 도메인에서 상단에 판단·권고를 확정적으로 고정하면 환각·과장억제·바로사용가능성이 함께 떨어진다"는 것을 R31→R32에서 3라운드 전부·12점 차로 실측했다. 이 템플릿은 그 조건을 두 군데에 이중으로 심어뒀다 — 요구사항 6은 카드·특이 발언 절 어디서도 채용 여부를 판단하지 말라는 절 단위 금지, 요구사항 8은 상단 한 줄 요약에 "합격/불합격 추천 문장은 절대 포함하지 말 것"이라는 위치 단위 금지다. 출력 형식에도 "판정 요약" 대신 "한 줄 요약"만 두고 별도의 "종합 의견"이나 "추천" 절을 만들지 않음으로써, 애초에 그런 문장을 넣을 자리 자체를 출력 구조에서 제거했다.
```

## 팁

- criteria_list에 번호를 매기지 않으면 "평가 기준 N개 중" 집계가 흔들릴 수 있으니, 원문 그대로 번호가 붙은 목록을 넣는 것이 좋습니다.
- transcript를 요약해서 넣으면 역방향 스캔(목록 밖 특이 발언)이 사실상 무력화되므로, 다소 길더라도 전체 발언을 그대로 붙여 넣으세요.
- decision_deadline을 비워두면 모든 확인 요청에 "채용 결정 전 확인 필요"만 표시되니, 실제 채용 일정이 정해져 있다면 채워 넣는 편이 확인 요청의 긴급도를 더 명확히 전달합니다.
