# R20 — SNS 광고 카피 작성 · **중단 (미완)**

> **이 라운드는 심사 전에 사용자 요청으로 중단되었다.** 승자 없음, ledger 미기록, 라이브러리 미승격, 백로그 미소비.
> 재개하면 AUTO-SCORE의 블라인드 심사부터 이어가면 된다 — 앞 단계 산출물은 모두 보존돼 있다.

## 완료된 단계

| 단계 | 상태 | 산출물 |
|---|---|---|
| 1 RETRIEVE | 완료 | DNA v1.17 · ledger 19건 · 참조 확인 |
| 2 GENERATE | 완료 | [[DOMAIN]] + `candidates/{a,b,c}.md` |
| 3 AUTO-SCORE | **부분** | [[SCENARIO]] · `values.json` · `assembled/*.txt` · `outputs/{a,b,c}.md` 까지. **블라인드 심사 미실행** |
| 4 HUMAN GATE | 미실행 | — |
| 5 LEARN | 미실행 | — |

## 방향 풀 (DOMAIN 도출)

- **a — 실험 문법형**: 결과물을 카피 1개가 아니라 소재 세트로 정의. 서로 다른 각도의 소재 + 성과 판정 카드 내장. 필드 8(필수 6)
- **b — 결합형 표준**: 검증된 피드 광고 구조 내장 + 코치형 help + 대상 맥락 빈칸. 필드 9(필수 6)
- **c — 심사·규제 통과형**: 근거 없는 최상급·효능 표현 봉쇄, 광고 표시 의무, 금지 표현 네거티브 조건. 필드 7(필수 6)

## 기계 점검 (완료분)

세 후보 모두 4요소 구조 충족, 빈칸 6±3 이내, 전 필드 placeholder·help 보유, anti-slop 위반 0.
b의 `①②③` 검출은 오탐 — 템플릿이 순번 마커 사용을 *금지하는* 문장이었다.

**형식으로는 갈리지 않았다.** 산출물 심사가 판정을 결정할 지점이다.

## 재개 시 유의

- `success_metric`(a·b 공통 선택 필드)을 **의도적으로 비운 채** 조립했다 — 초보자가 성과 기준을 모르는 상황을 재현해, 비어도 판정 카드를 만들어내는지 보려는 설계다.
- **예산·기간을 받는 필드는 a에만 있다.** b·c는 묻지 않는다 — 측정 본질 도메인에서 갈릴 수 있는 구조 차이.
- 시나리오에 함정 6종을 심었다: 실데이터 활용 / raw 창작 / 감의 출처 유지 / 측정 / 심사·규제 / 소비 문법. 상세는 [[SCENARIO]].
- 심사는 **라틴 방진 3회**로 순서 편향을 통제해야 한다 (단일 심사는 두 번째 제시물 편향 4/4 실측).

## 예측-실제 대조 (domain-fit named query)

예측: **a 우세** (측정 본질 도메인에서 실험 문법이 결합형을 이긴 전례 R12·R15).
실제: **미확정** — 심사 미실행. 이 질의의 누적 성적(3승 3패)에는 반영하지 않는다.
