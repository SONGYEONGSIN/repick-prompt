# DOMAIN — 인스타그램 콘텐츠 기획·카피 (R15)

> Named query [[40-queries/domain-fit|"도메인 본질 분석"]] 실행. GENERATE 방향 풀 설계 직전.
> **타깃**: 키워드 입력 + 형식 필드(정보전달 1장 / 카드뉴스 6장) 분기 → ① 정보전달 = 1장 압축 카피 ② 카드뉴스 = 구조안(후킹 표지→본문→마무리 CTA) + 업로드용 6장 완성 카피. 출력이 폴더(`informationsend` / `cardnews1~6`)에 그대로 매핑되는 통합 템플릿.
> **근거**: DNA v1.13 / `30-ledger/prompt-ledger.jsonl` / [[00-principles/MEMORY]] — R4(SNS 유일 전례)·R12(측정 본질 도메인) 중심.

## 1. 본질 리스크 — 이 도메인 결과물이 실패하는 1순위 원인

**한 문장: "모든 카드를 같은 밀도로 채우는 균등분배 사고" — 표지도 후킹 대신 제목 나열, 본문도 압축 대신 정보 과적재.**

세 실패를 순위와 함께 판정한다 (질의에서 요청한 정보 과적재 / 첫 장 후킹 실패 / 저장 유도 부재 대조):

- **1순위 = 표지(첫 장) 후킹 실패 [진입 게이트]** — 카드뉴스는 **스와이프 게이트** 구조라 표지를 안 넘기면 본문 5장이 존재하지 않는 것과 같다. 정보전달 1장도 피드에서 첫 시선(첫 3어절·이미지)을 못 잡으면 스크롤로 소멸. 진입 실패는 나머지 모든 실패의 **상류**다. R4 reels가 확립한 "첫 3초 훅이 조회수의 대부분을 결정"([[20-generations/2026-07-12-reels-script/candidates/c|R4-c tips]])의 static 카드 이식 — reels의 첫 3초 = 카드뉴스의 표지 = 정보전달의 첫 줄.
- **2순위 = 저장·공유 유도 부재 [도달 게이트]** — 진입에 성공해도 저장/공유가 안 되면 알고리즘 도달이 끊겨 "만든 뒤 반복" 루프(§2)가 성립하지 않는다. 카드뉴스는 본디 **저장(레퍼런스)용 포맷** — 마지막 카드에 "다시 볼 이유"(요약·체크리스트·저장 트리거)가 없으면 소비되고 잊힌다.
- **공통 기전 = 정보 과적재** — 표지에 정보를 욱여넣어 후킹을 죽이고(1순위 유발), 본문 6장을 균등 밀도로 채워 저장가치를 죽인다(2순위 유발). "1카드 1메시지" 붕괴가 근본 기전. DNA 금지 항목 "결과물 본문 안에 구조 마커(①②③)"([[00-principles/prompt-principles]] anti-slop)가 여기서 특히 위험 — 카드뉴스는 카드 자체가 순번이므로 본문 내 번호 마커가 이중 혼동.

→ **방향 설계 함의**: 승부처는 "카드에 무슨 정보를 담나"가 아니라 **장별 역할 분담을 프롬프트가 강제하느냐**(표지=후킹, 본문=1카드 1메시지, 마지막=저장/행동). 프레임워크 내장(카드뉴스·숏폼 문법)은 R7 이후 **기본기이지 차별화가 아님**([[00-principles/prompt-principles]] v1.6).

## 2. 본질 루프 — "만들면 끝"인가 "만든 뒤 측정·반복"인가

**측정·반복이 본질. R12보다 강함 — 실험 문법(지표·판정·후속) 방향 필수 포함.**

- SNS 콘텐츠는 **직렬 발행물**이다. 한 편으로 끝이 아니라 피드/채널을 시간에 걸쳐 쌓는다. 알고리즘이 **저장·공유·도달·체류**라는 측정 가능한 신호로 재도달을 결정 → 다음 편은 이번 편의 신호를 학습해 개선한다.
- **R12 직접 이식**: "측정이 본질인 도메인에선 실험 문법(가설-지표-판정) 방향이 범용 결합형을 이김 → 도메인 본질-방향 궁합 신호"([[00-principles/MEMORY]] R12, `30-ledger/prompt-ledger.jsonl` 2026-07-17-marketing-email). SNS는 마케팅 이메일보다 **더** 측정·반복적이다 — 이메일은 1회 발송(구매/쿠폰), SNS는 저장/공유/도달 신호 + **직렬 재발행**으로 피드백 루프가 더 빠르고 연속적.
- **전례가 이미 루프를 암시**: R4 승자 c의 tips가 "첫 3초 훅 3개로 작게 테스트 → 저장 수·완주율 높은 훅 확인" + "반응 좋은 영상 붙여넣어 시리즈로 확장"을 이미 담았다([[20-generations/2026-07-12-reels-script/candidates/c|R4-c tips]]). 즉 R4는 측정-반복 루프를 **tips(부속)로만** 담았고, R15는 이를 **방향으로 승격**할 수 있다.
- DNA 근거: 행동 착지 2차 강화 "성과가 측정되는 발송물은 성과 판정 카드(목표 행동 층위 지표·판정 시점·성공/실패 후속)까지"([[00-principles/prompt-principles]] v1.12). SNS 발행물이 정확히 이 범주.

## 3. 결과물의 소비 방식 — 누가, 어떤 채널·시간 예산으로

- **채널**: 모바일 세로 화면, 엄지 스와이프, 소리 없이 시각으로. 피드 스크롤 중 **3초 스캔이 기본** — 정독도 결재도 아님(자소서 R6·보고서 R5와 대비).
- **정보전달 1장**: 피드에서 스치듯 스캔. 한 장에 다 담기므로 **3초 안에 핵심 1개** 전달 못 하면 끝. 압축이 전부.
- **카드뉴스 6장**: 표지 후킹 성공 시 → 스와이프하며 카드당 **1~2초씩 스캔**(정독 아님) → 가치를 느끼면 **저장**(나중에 정독). 소비 예산 = 진입 판단 ~1초 / 카드당 1~2초 / 저장 결정은 마지막 카드 또는 전체 가치 인지 시점.
- reels(R4)와 가장 유사(3초 스캔 진입)하나 **static**이라 텍스트 밀도 관리가 더 중요 — 카드 1장이 모바일 화면을 꽉 채우므로 과적재가 곧 이탈.

→ **소비 예산이 곧 리스크 지도**: 진입(1초)=표지 후킹 / 스캔(1~2초)=1카드 1메시지 / 저장 결정=마지막 카드 값. §1의 3실패가 소비 3구간에 정확히 대응.

## 4. 유사 라운드 전례 — 구조가 가장 가까운 라운드와 승부처

- **1순위 전례: R4 reels-script (2026-07-12)** — 볼트 내 **유일한 SNS 콘텐츠 라운드**. 승자 c = 프레임워크 내장(숏폼 문법: 무음 자막·2~3초 전환·어절 분량·훅 유형·혼자 촬영 전제). 승부처 = 문법 내장 + **실데이터 필수 빈칸**(가격·일정·정원 — 없으면 AI가 창작) + **첫 3초 훅 3개 발산→수렴**(`30-ledger/prompt-ledger.jsonl` 2026-07-12-reels-script, 20/20). **주의**: R4는 프레임워크 내장 5연승기(R2~R6)의 승리 — R7 이후 **내장 단독은 기본기로 격하**되었으므로, 카드뉴스 문법 내장은 R15에서 baseline이지 승부처가 아님.
- **2순위 전례: R12 marketing-email (2026-07-17)** — §2 측정 루프의 근거. 승자 c = 단일 목표 정렬 + 발송 실험 카드. **결합형 4연승을 종료시킨 라운드** — "측정 본질 도메인 → 실험 문법 승"([[00-principles/MEMORY]] R12). R15가 측정 본질(§2)이면 이 전례가 결합형 baseline을 이길 수 있음을 예고.
- **보조 전례: R8 product-detail-page** — 저장/설득 카피 + 자기검증 루프(대상이 되어 저항 지점 스스로 고침). 카드뉴스 표지 후킹 검증에 이식 가능(스크롤하는 대상이 되어 "이 표지에서 멈출까"를 자기검증). 단 R8은 랜딩(1회 전환)이라 직렬성은 약함.

## 5. 방향 풀 추천 — 서로 다른 설계 방향 3개

세 방향 모두 **형식 필드 분기(정보전달 1장 / 카드뉴스 6장) + 폴더 매핑 출력(`informationsend` / `cardnews1~6`)**을 공통 골격으로 하되, 차별 축이 다르다. 카드뉴스·숏폼 문법 내장 + 실데이터 필수 빈칸(R2/R4)은 셋 다 baseline으로 흡수.

- **방향 A — 결합형 표준 (baseline, R7~R11 3승 패턴 SNS 이식)**
  구조 내장(카드뉴스 문법: 표지 후킹 유형·1카드 1메시지·6장 역할 분담·마지막 저장 유도) + **코치형 help** + **대상 맥락 빈칸**(누구의 어떤 저장 동기를 겨냥하나 — "출퇴근길에 저장해뒀다 주말에 따라 할 사람"). R6/R7의 대상 맥락 빈칸([[00-principles/prompt-principles]] v1.6)을 "저장 동기"로 특화. 형식 분기 + 폴더 매핑 완성 카피 = **바로 업로드 가능성**(R1·R6 발송 세트 착지). *역할*: 대조 기준선.

- **방향 B — 실험 문법 / 저장-도달 측정 루프 (본질 루프 §2 정면, R12 이식) [측정 본질 겨냥 필수 방향]**
  카피를 "1회 발행물"이 아니라 **측정→반복하는 실험**으로 설계. ① 표지 후킹을 **복수(A/B) 후보**로 발행 → ② **단일 신호 정렬**(도달이 목표면 좋아요 아닌 공유 수, 팔로워 확보면 저장 수 — R12 "목표 행동 층위 지표") → ③ **발행 후 판정 카드**(어느 표지가 저장을 불렀나·판정 시점·성공 시 시리즈 확장/실패 시 표지만 교체 재발행). R4 tips가 부속으로 담은 측정-반복을 방향으로 승격. **SNS가 R12보다 더 직렬·반복적이므로 결합형 baseline을 이길 유력 후보**([[00-principles/MEMORY]] R12 전례).

- **방향 C — 후킹·저장 카피 공학 (본질 리스크 §1 정면) [균등분배 사고 봉쇄 방향]**
  도메인 최대 실패(진입 게이트 + 저장가치)를 아티팩트 품질로 정면 격파. ① 표지 = 후킹 문법(호기심 갭·숫자 약속·흔한 고민·반전) **복수 후보 강제 발산→수렴**(R4 첫 3초 훅 3개 이식) + ② 본문 = "1카드 1메시지, 과적재 금지" 규칙으로 균등분배 봉쇄 + ③ 마지막 카드 = "저장할 이유"(요약·체크리스트·재방문 값) 명시 설계 + ④ 정보전달 1장 = "핵심 1개로 압축, 나머지는 버려라". **자기검증 루프**(R8) 이식 — "스크롤하는 대상이 되어 이 표지에서 멈출지·이 6장을 저장할지 스스로 판정한 최종본만 출력". B가 *루프*(측정·반복)를 겨냥한다면 C는 *단발 아티팩트*의 후킹·저장가치를 겨냥.

> **본질 겨냥 충족**: 결합형 표준(A) 기본 포함 + 본질 루프 정면(B, §2) + 본질 리스크 정면(C, §1) — 질의 요건(본질 겨냥 ≥1) 초과 충족.

## 예측 (DECISION.md에서 반증 대상 — 축적 규칙)

- **본선 예측**: B(실험 문법) ↔ C(후킹·저장 공학)의 대결로 수렴, A(결합형)는 대조 기준선일 가능성. R12가 "측정 본질 → 실험 문법 승"을 실증했고 SNS는 더 강한 측정-반복 도메인이므로 **B에 소폭 무게**.
- **반대 가설(주의)**: 타깃의 **폴더 매핑(informationsend/cardnews1~6) + 업로드용 완성 카피** 요구는 "바로 사용 가능성"(아티팩트 완결성, R1·R6) 신호가 강하다 — 이는 C/A에 유리. **측정 본질(B)이 아티팩트 완결성 요구를 이기는가**가 이 라운드의 진짜 시험. R14 교훈(DOMAIN.md 예측이 빗나갈 수 있음 — 결합형 우세 예측이 압박질문 방향에 패배)을 기억해 예측을 확정 아닌 가설로 둔다.
- **공통 리스크 체크포인트**: 형식 분기(1장/6장)가 한 템플릿에서 깔끔히 갈라지는가 / 카드 본문에 ①②③ 마커가 새지 않는가(카드뉴스 이중 혼동) / 실데이터 빈칸이 카드에 담길 수치·일정을 실제로 받아내는가(R2/R4 창작 방지).
