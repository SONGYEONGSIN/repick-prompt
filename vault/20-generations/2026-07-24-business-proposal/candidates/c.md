# 후보 c — 대안 대비 raw 근거 비교표로만 승부하는 사업 제안서

## fields

| key | label | type | optional | help | placeholder | options |
|-----|-------|------|----------|------|------|------|---------|
| audience | 결재 대상 | text | false | 누가 이 제안을 검토·결재하나요? 여러 명이면 최종 결재자 한 명 기준으로 | 본부장 김OO (재무팀 사전검토 포함) | |
| topic | 제안 주제 | text | false | 무엇을 제안하나요, 한 줄로 | 고객문의 CS 챗봇 자동화 도입 | |
| current_state_raw | 현재 상태 (raw 수치) | textarea | false | 현재 상황을 아는 만큼 숫자·사실로만. 감이나 추정은 적지 마세요 | 월 CS 문의 1,200건, 처리 인력 3명, 인건비 900만원/월, 평균응답 6시간 | |
| alternatives_raw | 대안별 raw 비용·특징 (현상유지 포함) | textarea | false | 현상유지를 반드시 포함해서, 검토했던 대안들의 실제 견적·특징을 아는 만큼만. 모르는 항목은 모른다고 적어주세요 | ①현상유지: 추가비용 0, 인력 3명 유지, 응답 6시간 / ②외주 A사 견적: 월 450만원, SLA 2시간, 초기비용 없음 / ③자체 챗봇: 초기 800만원+월 100만원, 응답속도 미확인 | |
| proposed_cost_raw | 제안안 raw 비용·자원 | textarea | false | 제안하는 안의 실제 견적·소요 자원. 모르는 항목은 [확인필요]로 남겨도 됩니다 | 솔루션 라이선스 월 120만원, 초기 구축비 500만원(2개월), 유지보수 담당 0.5명 | |
| evidence_raw | 효과 근거 자료 | textarea | true | 효과 주장을 뒷받침할 실제 자료: 타사 도입 사례, 파일럿 결과, 벤치마크 수치. 없으면 비워두세요 — 비우면 문서에는 [확인 필요]로만 표시됩니다 | 동종업계 B사 도입 후 응답시간 6시간→40분 (B사 2025Q4 IR자료) | |
| known_risks_raw | 알고 있는 리스크 | textarea | true | 이미 알고 있는 우려나 반대 이유. 없으면 비워도 됩니다 | 초기 오응답률 우려, 기존 인력 재배치에 대한 반발 가능성 | |
| constraint | 예산·기한 제약 | text | true | 승인 예산 상한이나 결정 기한이 있으면 | 예산 상한 1,000만원, 다음 분기 예산안 마감 8/15 전 결재 필요 | |

## template

```
당신은 의사결정자에게 제출할 사업 제안서를 작성하는 전략 기획자입니다. 당신의 최우선 임무는 설득이 아니라 정직한 비교입니다 — 입력된 raw 데이터에 없는 수치는 어떤 경우에도 만들어내지 않습니다.

맥락:
- 결재 대상: {{audience}}
- 제안 주제: {{topic}}
- 예산·기한 제약: {{constraint}}
- 현재 상태(raw): {{current_state_raw}}
- 검토한 대안들(raw, 현상유지 포함): {{alternatives_raw}}
- 제안안 비용·자원(raw): {{proposed_cost_raw}}
- 효과 근거 자료(raw): {{evidence_raw}}
- 알고 있는 리스크(raw): {{known_risks_raw}}

요구사항:
1. 문서 최상단에 "요청 사항 + 필요 결재 + 기한"을 3줄 이내로 고정하라. 결재자가 본문을 다 읽지 않아도 무엇을 승인해야 하는지 즉시 알아야 하기 때문이다.
2. {{alternatives_raw}}에 나열된 모든 대안(현상유지 포함)과 제안안을 "비용 / 효과 / 리스크" 3열 비교표로 만들어라. 대안 하나만 부각하고 나머지를 생략하면 결재자가 스스로 비교할 근거가 사라지기 때문이다.
3. 비교표와 ROI 관련 숫자는 {{current_state_raw}}, {{alternatives_raw}}, {{proposed_cost_raw}}에 실제로 적힌 값에서 사칙연산으로 유도 가능한 것만 계산하고, 계산식을 괄호로 노출하라(예: "900만원 - (120만원+500만원/12) ≈ 738만원/월 절감"). raw에 없는 시장규모·성장률·전환율·효과 추정치는 절대 만들어내지 말고, 근거가 없는 항목은 수치 대신 "[확인 필요]"로 표시하라. 이것이 이 제안서의 신뢰도를 결정하는 가장 큰 리스크이기 때문이다.
4. {{evidence_raw}}가 있으면 해당 자료의 출처를 짧게 인용해 효과 주장 옆에 붙이고, 비어 있으면 그 효과는 "추정" 또는 "[확인 필요]"라고 명시하라. 근거 없는 낙관적 효과 서술은 raw로 위장한 창작이기 때문이다.
5. 리스크·완화책 표를 별도로 만들어, {{known_risks_raw}}에 적힌 항목과 비교표 작성 중 드러난 대안별 약점을 모두 포함하라. 불리한 사실을 먼저 인정한 뒤 대응책을 붙이는 순서로 쓰라. 리스크를 감추면 결재 이후 실행 단계에서 신뢰를 잃기 때문이다.
6. 핵심 제안 문장(한 줄 요약)을 3개 후보로 만든 뒤, 비교표 결과와 가장 부합하는 1개를 확정해 상단 요약에 반영하라. 첫 문장이 결재자의 첫인상을 결정하기 때문이다.
7. 문서 맨 끝에 "제출 전 셀프 체크"를 부속 메모로 분리해 붙여라 — raw에 없는 숫자를 쓰지 않았는지, [확인 필요] 항목이 몇 개 남았는지, 다음 관문(재무 검토 등)에서 나올 질문에 답이 준비됐는지 스스로 점검하는 체크리스트다. 제출 후 정정은 신뢰를 깎기 때문에 제출 전에 걸러야 한다.

출력 형식:
- 상단 요약 (요청사항 + 결재 범위 + 기한, 3줄 이내)
- 제안 배경 (현재 상태 raw 인용)
- 대안 비교표 (현상유지 포함 전 대안 x 비용/효과/리스크)
- 절감·효과 계산 근거 (계산식 노출 + [확인 필요] 항목 명시)
- 리스크·완화책 표
- 실행 계획 (단계·기한)
- 제출 전 셀프 체크 (부속 메모)
```

## anatomy (4항목)

- 역할: "당신의 최우선 임무는 설득이 아니라 정직한 비교입니다 — 입력된 raw 데이터에 없는 수치는 어떤 경우에도 만들어내지 않습니다" — 사업 제안서 도메인의 본질 리스크 2번(근거 없는 낙관적 수치 창작)을 역할 정의 단계에서부터 원천 차단해, 이후 모든 요구사항이 이 제약을 상속하게 만든다.
- 맥락: {{current_state_raw}}, {{alternatives_raw}}, {{proposed_cost_raw}}, {{evidence_raw}}를 모두 raw 데이터 전용 빈칸으로 분리 — 사용자가 "아는 값"과 "모르는 값"을 뒤섞지 않고 입력하게 강제해, AI가 빈 곳을 창작으로 메우지 않고 [확인 필요]로 남길 근거를 확보한다.
- 요구사항: 대안 비교표(현상유지 포함)를 필수화하고 ROI 계산을 raw 사칙연산으로만 제한한 것이 이 후보의 핵심 — 다른 결합형·관문형과 달리 "정량적 근거의 정직성과 비교 가능성"을 요구사항의 최우선 축으로 명시했다.
- 출력 형식: 비교표와 리스크표를 본문 구조에 강제로 박아 넣어, AI가 서술형 문장으로 뭉개고 지나갈 여지를 없애고 결재자가 표만 훑어도 대안 대비 판단이 가능하게 한다.

## tips (2개)

- alternatives_raw에 현상유지를 포함시키지 않으면 비교표 자체가 성립하지 않으므로, help 문구로 "현상유지를 반드시 포함해서"를 명시했다 — 이 필드가 비어있거나 부실하면 후보 c의 차별점이 무력화된다.
- evidence_raw를 optional로 두되 비었을 때의 동작(효과는 "추정"/"[확인 필요]"로 표시)을 요구사항 4에 명시해, 선택 필드가 비어도 결과물이 조용히 낙관적 수치로 채워지지 않도록 막았다.
