# DOMAIN.md — 사업 제안서 작성 (R19)

Named query 실행: [[domain-fit]] (GENERATE 방향 풀 설계 직전).

## 1. 본질 리스크

사업 제안서가 실패하는 1순위 원인은 **결정자의 승인 기준과 무관하게 제안자 중심으로 쓰이는 것** — 우리가 얼마나 훌륭한지만 나열하고, 상대가 실제로 무엇을 근거로 예산·결재를 내리는지(예산 상한, 기존 시스템과의 충돌 여부, 도입 후 성과 확인 시점)에 답하지 못하면 "검토는 했지만 움직이지 않는" 제안서가 된다. 두 번째 리스크는 **raw 근거 없는 낙관적 수치(시장규모·ROI·효과)의 창작** — 제안서는 본질적으로 설득 문서이기 때문에 근거가 얇을수록 AI가 그럴듯한 수치로 메꾸려는 유혹이 코드/이메일류보다 크다. work-report(R5)의 "결정 요청 상단 고정"과 인접하지만, 업무 보고는 이미 발생한 사실을 결재받는 것이고 제안서는 아직 일어나지 않은 미래 지출을 설득해야 하므로 리스크의 축이 "요청 위치"보다 "결정자 기준 정렬 + 근거 없는 낙관"으로 이동한다.

## 2. 본질 루프

**"제출 → 결재/거절"의 단발 결정형** — 뉴스레터(R18)·마케팅 이메일(R12)처럼 반복 발송·측정이 본질은 아니다. 오히려 work-report(R5)·process-judgment(R11)와 같은 결재형 루프에 가깝다. 단, 제안서는 이미 일어난 일을 보고하는 게 아니라 아직 없는 예산을 설득해 얻어내야 하므로, cold-email(R1)·cs-reply(R7)류의 **설득 요소**(약점 인정, 대상 맥락)가 결재형 구조 위에 결합돼야 한다. 파일럿·단계적 도입을 제안하는 경우 실험 문법(성공/실패 판정 기준, R11·R12)도 관여한다.

## 3. 결과물의 소비 방식

결재권자가 보통 **요약(Executive Summary)을 먼저 훑고, 승인 여부에 확신이 없으면 본문을 정독**하는 2단계 소비 — 보고서(work-report)와 유사하나 결재권자 혼자가 아니라 **관련 부서(재무·실무)가 함께 검토**하는 경우가 많아, presentation-script(R17)의 복수 이해관계자 연결이 적용될 여지가 있다.

## 4. 유사 라운드 전례

- **work-report(R5)**: 가장 가까운 구조 — 결재형 문서. 승부처는 결정 요청을 기한과 함께 최상단에.
- **cover-letter(R6)**: 대상(회사) 맥락 빈칸 + 검증형 부속물(셀프 체크) — 제안서도 특정 상대 1곳을 겨냥하는 문서.
- **cs-reply(R7)·product-detail-page(R8)**: 약점 정면 인정 후 실데이터 반박 — 제안서의 가격·레퍼런스 약점 방어에 직결.
- **process-judgment(R11)**: 행동 착지(하지 말 것 + 가장 싼 첫 실험·판정 기준) — 파일럿 제안 구조에 직결.
- **presentation-script(R17)**: 복수 이해관계자 연결 — 재무팀·실무팀이 함께 검토하는 제안서에 적용 후보.

## 5. 방향 풀 추천 (3개, 서로 다른 설계 방향)

- **a = 결합형 표준** (프레임워크 내장 + 코치형 help + 대상 맥락 빈칸) — 기본 포함. 지금까지 다수 승(R7·R9·R10·R11·R17·R18)의 범용 강자, 베이스라인.
- **b = 결정자 관문 정렬형** — 결정 요청+기한을 최상단 고정(R5 계보), 결정자의 구체적 승인 기준(예산 상한·기존 시스템 충돌 여부·확인 시점)을 대상 맥락 빈칸으로 받고, 약점(가격·레퍼런스 부족)을 정면 인정 후 실데이터로 반박(R7·R8 계보), 파일럿 착수 + 성공/중단 판정 기준(R11 계보)까지 구조화. 본질 리스크 1(결정자 기준 정렬 실패)을 정면 겨냥.
- **c = 근거 비교표형** — 대안(현상유지·경쟁사) 대비 비용·효과 비교표, 리스크·완화책 표를 요구사항에 강제하고, ROI·수치는 전용 빈칸의 raw 데이터만 사용하도록 필드를 설계해 본질 리스크 2(근거 없는 낙관적 수치 창작)를 정면 겨냥.

## 예측

b(결정자 관문 정렬형)가 결재형 도메인 특성상 결합형(a)을 이길 가능성 — 단, domain-fit named query 누적 성적은 2승 3패로 신뢰도가 낮으므로 예측에 큰 확신을 두지 않는다. 라운드 종료 후 DECISION.md에 예측-실제 대조 1줄 기록.
