# 후보 a — 최소 빈칸 (필수 4개)

**한 줄 컨셉**: 지원 회사·직무와 나의 경력 raw 메모만 넣으면, 이 사람에게만 나올 법한 면접 예상 질문 9~10개를 유형별(지원동기·직무역량·인성·압박·돌발)로 예측하고, 실제 경험 근거의 구술형 답변 스켈레톤과 역질문 후보·당일 체크리스트까지 — 자소서/이력서 부속물 수준이 아닌 실전 면접 대비 본편을 한 번에 만듭니다.

## fields

| key | label | type | optional | help | placeholder | options |
|---|---|---|---|---|---|---|
| `company` | 지원 회사 (특징 한 줄 포함) | text | | 회사 이름과 함께 업종·성장단계·최근 이슈 같은 특징을 한 줄로 붙여주세요. 이름만 적으면 AI가 "성장하는 스타트업이라서" 같은 아무 회사에나 통하는 답변을 만들고, 면접관은 그 순간 지원자가 회사를 조사 안 했다는 걸 압니다. | 예: 카카오모빌리티 (모빌리티 플랫폼, 최근 물류·B2B 신사업 확장 중) | |
| `position` | 지원 직무 (연차 포함) | text | | 직무명과 연차(신입/1~2년차/3~5년차 등)를 함께 적어주세요. 연차에 따라 예상 질문의 깊이와 답변에 담을 자신감의 정도가 달라집니다. | 예: 백엔드 개발자 (경력 3년차) | |
| `jd_requirements` | 채용공고 요구역량·자격요건 (원문) | textarea | | 채용공고의 '자격요건'·'우대사항'을 요약하지 말고 원문 그대로 붙여넣으세요. 이 칸이 질문 예측 정확도를 가장 크게 좌우합니다 — 비어 있으면 이 회사·이 공고가 아니라 어느 회사에나 나올 법한 뻔한 질문만 나옵니다. | 예: MSA 환경 개발 경험, 대용량 트래픽 처리 경험, Kotlin/Spring 우대, 유관 부서와의 협업 능력 | |
| `background` | 나의 경력·경험 raw 메모 | textarea | | 정리하지 말고 날것 그대로 적으세요. 프로젝트·맡은 역할·구체적으로 한 행동·수치로 보여줄 수 있는 결과, 그리고 자신 있는 성과가 있다면 함께 적어주세요. 여기 없는 내용은 AI가 절대 지어내지 않으므로, 빠뜨린 사실이 곧 놓치는 질문 대비입니다. | 예: 커머스 스타트업 2년 재직. 주문 시스템 레거시를 MSA로 분리하는 프로젝트에서 결제 모듈 담당, 장애율 월 12건→2건으로 감소. 트래픽 급증 대응으로 캐시 레이어 도입해 응답속도 40% 개선. 신입 1명 온보딩 멘토링 경험. | |
| `concern` | 약점처럼 보일까 걱정되는 부분 | textarea | optional | 경력 공백, 짧은 재직 기간, 직무 전환, 부족한 경험처럼 스스로 걱정되는 지점을 솔직하게 적으세요. 비워두면 background 안에서 면접관이 파고들 법한 지점을 AI가 대신 찾지만, 직접 적으면 실제로 물어볼 압박 질문에 더 정확히 대비됩니다. | 예: 이직 준비 중 5개월 공백기가 있어서 이 부분을 물어볼까 걱정된다 | |

## template

```
당신은 수많은 지원자를 실제로 면접해온 현직 면접관이자, 그 시선으로 예상 질문과 실전 답변까지 함께 준비해주는 면접 코치입니다. 그럴듯한 일반론이 아니라, 이 지원자의 이력에서만 나올 수 있는 질문을 정확히 예측하고, raw 경력 정보에 근거한 구술형 답변 뼈대까지 만들어 면접장에서 그대로 쓸 수 있게 하는 것이 당신의 목표입니다.

아래 정보를 바탕으로 면접 예상 질문과 답변을 준비해주세요.
- 지원 회사: {{company}}
- 지원 직무: {{position}}
- 채용공고 요구역량·자격요건: {{jd_requirements}}
- 나의 경력·경험 raw 메모: {{background}}
- 약점처럼 보일까 걱정되는 부분: {{concern}}

요구사항:
1. 질문은 지원동기·회사이해도 / 직무역량·경험 검증 / 인성·협업 태도 / 압박·약점 관련 / 예상 밖 돌발 질문, 이렇게 다섯 유형으로 나눠 만들어주세요. 유형마다 준비 전략이 다른데 뒤섞어 나열하면 지원자가 어떤 질문에 어떻게 대비해야 할지 감을 못 잡기 때문입니다.
2. 직무역량 질문은 반드시 {{background}}에 적힌 구체적 프로젝트·상황과 {{jd_requirements}}를 직접 연결해 만들어주세요 — "본인의 강점은?" 같은 일반 질문이 아니라 "말씀하신 [구체 프로젝트]에서 [구체 상황]을 어떻게 처리했는지" 식으로 이 사람만 받을 법한 질문으로 좁혀주세요. 어느 지원자에게나 낼 수 있는 질문은 예측 정확도가 없고, 이력에서 나온 질문이라야 실전에서 실제로 나올 확률이 높기 때문입니다.
3. 각 질문에는 상황-과제-행동-결과 흐름의 답변 스켈레톤을 함께 주되, 본문에 그 단계 이름이나 기호는 절대 쓰지 말고 자연스러운 구술 문장으로 이어주세요. 라벨이 그대로 드러나면 외운 스크립트처럼 들려 오히려 면접관에게 어색한 인상을 주기 때문입니다.
4. 답변 스켈레톤은 {{background}}에 실제로 적힌 사실(수치·사건·역할)만 사용하고, 없는 성과나 경험을 새로 지어내지 마세요. 구체적인 시점이나 정도가 background에 없다면 그럴듯한 숫자로 채우지 말고 "[구체 수치·시점 확인 후 채우기]"로 남겨주세요. 면접장에서 지어낸 디테일은 꼬리질문 한 번에 무너지고, 그 순간 나머지 답변까지 전부 의심받기 때문입니다.
5. 압박·약점 질문은 최소 2개 포함하고, {{concern}}이 채워져 있다면 그 내용을 직접 겨냥해 만들어주세요. {{concern}}이 비어 있다면 {{background}} 안에서 면접관이 파고들 법한 약한 지점(짧은 경력, 공백기, 직무 전환 등)을 스스로 찾되, background에 없는 부정적 추측은 덧붙이지 마세요. 답변 스켈레톤은 약점을 회피하거나 반박부터 하지 말고, 먼저 담담히 인정한 뒤 background의 실제 근거(그 이후의 행동·개선)로 이어지는 구조로 짜주세요. 도망치는 답변은 오히려 약점을 확정해버리지만, 정면 인정 후 근거로 돌아오는 답변은 신뢰를 주기 때문입니다.
6. 지원동기·회사이해도 질문의 답변 스켈레톤에는 {{company}}에 적힌 특징을 실제로 녹여주세요. "귀사"라는 표현은 쓰지 말고 회사명을 그대로 쓰세요. 면접관은 지원자가 이 회사를 실제로 조사했는지를 이 질문 하나로 가려내는데, 어느 회사에나 낼 법한 답은 그 자리에서 티가 나기 때문입니다.
7. 마지막 질문은 반드시 정형화되지 않은 돌발 질문 1개를 포함해주세요(예: 가치관을 묻는 질문, 최근 이슈에 대한 의견, 30초 안에 스스로를 설명하기 등). 단, 이 질문의 답변은 완성된 정답 문장이 아니라 "이렇게 접근하면 된다"는 사고의 틀만 제시해주세요. 실제 면접은 예측 가능한 질문만 나오지 않는데, 돌발 질문까지 통째로 암기한 티가 나면 오히려 역효과이기 때문입니다.
8. 모든 답변 스켈레톤은 실제 구술 분량(40~60초, 한국어 기준 약 200~300자)에 맞게 써주세요. 너무 길면 읽는 글이 되어 외울 수 없고, 실제 면접 답변은 말로 하는 것이라 글이 아니라 구술 리듬으로 준비해야 하기 때문입니다.
9. 여러 질문에 걸쳐 {{background}}의 같은 경험 하나만 반복해서 재활용하지 말고, 서로 다른 사례로 나눠 배치해주세요. 같은 경험만 계속 나오면 면접관에게 "이 사람은 경험이 하나뿐이구나"라는 인상을 주기 때문입니다.
10. 전체 질문·답변 세트를 완성한 뒤, 방금 만든 질문을 던진 면접관의 시선으로 다시 읽어 방어적이거나 변명처럼 들리는 문장이 있으면 스스로 찾아 고친 최종본만 출력하세요. 중간 수정 과정은 출력하지 마세요. 방어적으로 들리는 답변은 실전에서 신뢰를 깎아먹는데, 이 검증을 미리 걸러내야 지원자가 그대로 쓸 수 있는 답변만 받기 때문입니다.

다음은 피해주세요: "열정적입니다", "책임감이 강합니다" 같은 형용사만 나열한 자기소개(반드시 경험으로 증명), 질문 없이 답변만 나열하는 구성, 본문 안에 ①②③ 같은 구조 기호 표기.

출력 형식:
- 예상 면접 질문 + 답변 스켈레톤 (유형별로 묶어서 총 9~10개: 지원동기·회사이해도 2개 / 직무역량·경험검증 3개 / 인성·협업 2개 / 압박·약점 2개 / 돌발 질문 1개) — 각 항목은 "질문" · "답변 스켈레톤" · "답변할 때 이것만은 놓치지 마세요" 한 줄 코칭으로 구성
- 이 면접에서 특히 조심해야 할 것 3가지 — background와 concern을 근거로 면접관이 의심할 법한 지점과 대응 방향
- 마지막 역질문 후보 3개 — 지원자가 면접관에게 물어볼 질문 (실무 이해도가 드러나는 질문 위주)
- 면접 당일 셀프 체크리스트 4개 이상 (예: 압박질문 답변이 방어적으로 안 들리는지 / 회사 특징이 답변에 실제로 녹아있는지 / 모든 스켈레톤이 구술 가능한 분량인지 / 없는 경험을 지어낸 부분은 없는지)
```

## anatomy

| part | quote | why |
|---|---|---|
| 역할 | "그럴듯한 일반론이 아니라, 이 지원자의 이력에서만 나올 수 있는 질문을 정확히 예측하고, raw 경력 정보에 근거한 구술형 답변 뼈대까지 만들어 면접장에서 그대로 쓸 수 있게 하는 것이 당신의 목표입니다." | 역할을 '면접 예상 질문 작성자'로만 두면 어느 지원자에게나 통하는 뻔한 질문 목록이 나옵니다. "이 지원자의 이력에서만 나올 수 있는"이라는 조건을 역할 단계에 못박아, 뒤에 나올 background·jd_requirements 연결 요구사항이 자연스럽게 예고되게 만듭니다. 이 템플릿의 핵심 승부처인 "질문 예측의 정확도"를 역할 정의에서부터 고정합니다. |
| 맥락 | "채용공고 요구역량·자격요건: {{jd_requirements}}" / "나의 경력·경험 raw 메모: {{background}}" | 대상 맥락(이 회사·이 공고가 실제로 원하는 것)과 실데이터(지원자의 실제 경험)를 각각 필수 빈칸으로 분리했습니다. 자소서·이력서 템플릿에서 이 두 칸이 optional이었던 것과 달리 필수로 올린 이유는, 이 템플릿의 산출물 자체가 "질문 예측"이라 이 두 정보가 비면 예측할 근거 자체가 사라지기 때문입니다 — 최소 빈칸이라는 방향성 안에서도 이 둘만은 타협하지 않았습니다. |
| 요구사항 | "직무역량 질문은 반드시 {{background}}에 적힌 구체적 프로젝트·상황과 {{jd_requirements}}를 직접 연결해 만들어주세요 — '본인의 강점은?' 같은 일반 질문이 아니라 ... 이 사람만 받을 법한 질문으로 좁혀주세요." | 면접 질문 예측이라는 도메인의 검증된 방법론(개인화된 질문 생성, STAR 답변 구조, 압박질문의 정면 인정 후 근거 반박, 구술 분량 제약)을 요구사항 문장에 통째로 내장했습니다. 지원자가 면접 방법론을 몰라도 두 필수 빈칸만 채우면 구조 품질이 보장되며, 각 항목에 "왜 그래야 하는지" 이유를 병기해 명시하지 않은 유사 상황(예: 돌발 질문에서도 암기 티 금지)까지 AI가 일반화하도록 설계했습니다. |
| 출력 형식 | "예상 면접 질문 + 답변 스켈레톤 (유형별로 묶어서 총 9~10개) ... 마지막 역질문 후보 3개 ... 면접 당일 셀프 체크리스트 4개 이상" | 기존 자소서·이력서 템플릿의 "예상 질문 3~5개"라는 부속물 수준을 넘어, 질문·답변·역질문·당일 체크리스트까지 갖춘 발송 세트로 착지시킵니다. 이 산출물 자체가 "다음 관문 대비물"이므로, 여기서는 질문 개수를 9~10개로 늘리고 역질문·체크리스트라는 실전 사용 부속물까지 강제해 읽고 끝나지 않고 면접 당일 그대로 들고 갈 수 있게 했습니다. |

## tips

1. `background` 칸에는 문장을 다듬지 말고 사실과 숫자를 최대한 많이 던지세요. 프로젝트 하나당 최소 "무엇을 맡았는지 + 어떤 행동을 했는지 + 숫자로 보이는 결과" 세 조각을 넣어야, 서로 다른 질문 9~10개가 같은 경험 하나를 우려먹지 않고 다양한 사례로 나뉩니다. 여기 적지 않은 경험은 어떤 질문의 답변 재료로도 등장하지 않습니다.
2. `concern` 칸을 비워두면 AI가 background에서 알아서 약점을 추측하지만, 실제로 면접관에게 가장 자주 나오는 질문(공백기·짧은 경력·직무 전환 이유)은 본인이 가장 잘 압니다. 걱정되는 부분이 있다면 부끄러워하지 말고 적으세요 — 이 템플릿은 그 지점을 정면으로 뚫고 지나가는 답변을 만들도록 설계됐습니다. 답변 세트를 받은 뒤에는 반드시 소리 내어 읽어보세요 — 글로는 자연스러워도 말로 하면 어색한 문장이 꼭 나옵니다.
