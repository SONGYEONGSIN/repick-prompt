# DOMAIN — 사용자 리서치 질문 설계 (R26)

> named query 실행: [[40-queries/domain-fit|도메인 본질 분석]]. GENERATE 방향 풀 설계 직전.

## 1. 본질 리스크

이 도메인 결과물이 실패하는 1순위 원인은 **편향 질문(leading question)과 가상 미래 의도 질문(hypothetical "would you")**이다. 리서치 초보자(창업자·PM)가 스스로 만드는 질문지는 검증하려는 가설을 질문 문장 안에 이미 심어버리는 경우가 압도적으로 많다 — "이 기능이 있으면 쓰시겠어요?"류는 응답자가 예의상 긍정하기 쉬워 신호가 아니라 노이즈를 만든다. 두 번째 리스크는 닫힌 질문(예/아니오로 끝나는 질문) 위주로 구성돼 실제 인터뷰에서 후속 캐묻기(follow-up probe) 없이 표면 답변에서 멈추는 것이다. 이는 DNA의 "raw에 없는 세부를 만들어내지 않는다"(v1.9~) 계열과 다른 축이다 — raw 창작 금지가 *결과물 작성 시점의* 환각을 막는 것이라면, 여기서는 *질문 자체의 설계 결함*이 인터뷰 실행 시점에 편향된 raw를 생성하게 만드는 상류 리스크다.

## 2. 본질 루프

"만들면 끝"이 아니라 **"질문지 → 실제 인터뷰 실행 → 응답 기록(raw) → (기존 라이브러리 interview-insights로) 분석"**의 상류 단계다. 측정-반복 루프(R12·R15·R20 실험 문법 계열)와는 다르다 — 반복 실행되는 것은 인터뷰 자체(응답자마다 재사용)이지 질문지 자체를 지표로 판정하지 않는다. 대신 이 질문지의 품질이 다운스트림 `interview-insights` 분석의 입력 품질을 통째로 결정한다는 점에서, 행동 착지보다는 **다음 관문 대비물**(R6 패턴: 자소서→면접 준비)에 더 가깝다 — "이 질문지로 인터뷰 후 어떻게 정리해서 분석에 넘길지"가 출력 형식의 자연스러운 종착점이다.

## 3. 결과물의 소비 방식

1차 소비자는 **인터뷰를 직접 진행하는 사람**(창업자·PM, 대개 리서치 비전문가) — 인쇄하거나 화면에 띄워놓고 **실시간 대화 중에** 참조한다. 정독이 아니라 "다음에 뭘 물어볼지 3초 안에 확인"하는 소비 방식이며, 문어체가 아니라 **입으로 자연스럽게 읽을 수 있는 구어체 질문**이어야 한다. 인터뷰 도중 즉흥 후속 질문(probe)을 만들 여유가 없는 초보자를 위해, 각 핵심 질문에 딸린 후속 캐묻기 문구까지 미리 준비되어 있어야 실전에서 쓸모가 있다.

## 4. 유사 라운드 전례

- **R14 interview-qa-prep** (구조상 가장 근접) — 질의응답을 예상해 준비시키는 문서, "raw 미확정 지점을 질문 예상 범위에 정면 포함"(v1.13) 원칙이 여기서 재현될 수 있다: 다만 R14는 *답변자*(면접 대상자) 관점에서 예상 질문에 답을 준비하는 것이고, 이번 라운드는 *질문자* 관점에서 편향 없는 질문을 설계하는 것 — 방향이 반대다.
- **competitor-research** (기존 라이브러리, 같은 카테고리 `research`) — "확실하지 않으면 추정이라고 표시" 장치가 있으나 이 도메인엔 추정 표시보다 **질문 설계 방법론 자체**(편향 회피 규칙)가 더 본질적이다.
- **interview-insights** (기존 라이브러리, `analysis`) — 이 질문지의 다운스트림 소비자. "근거 인용 요구"가 핵심 장치였는데, 그 인용거리(원문 발화)의 품질은 애초에 질문이 얼마나 편향 없이 설계됐는지에 달려있다 — 즉 이번 라운드의 승부가 좋아지면 그 하류 라운드(R-interview-insights, 이미 라이브러리 존재)의 잠재 품질도 함께 오른다.
- **R11 process-judgment** — "프레임워크 내장" 원칙이 검증된 방법론(리서치 방법론계에서는 Mom Test/5 whys/laddering 같은)을 요구사항 문장으로 내장하는 패턴이 그대로 적용 가능한 도메인.

## 5. 방향 풀 추천

결합형 표준(a)은 기본 포함하되, 본질 리스크(편향 질문)·소비 방식(실시간 구어체 진행)을 각각 정면으로 겨냥한 방향을 최소 1개씩 둔다.

- **a = 결합형 표준** — 구조 내장(카테고리/목적별 질문 프레임워크) + 코치형 help + 대상 맥락 빈칸(리서치 목적·대상) + 완성 예시 동봉(v1.21 baseline) 결합. 범용 안전판.
- **b = 편향 차단 정면 겨냥형 (도메인 본질 리스크 겨냥)** — "가상 미래 의도('쓰시겠어요?') 질문 금지, 과거 실제 행동만 캐묻기", "질문 문장에 가설/정답을 심지 않기(편향 자가진단 체크리스트 요구사항 내장)"를 요구사항으로 명시 내장. 닫힌 질문 최소화·후속 캐묻기(follow-up probe) 의무 배치.
- **c = 실전 인터뷰 진행 최적화형 (소비 방식 겨냥)** — 질문 시퀀싱(라포 형성 → 넓은 질문 → 구체적 질문 → 마무리) + 구어체 표현 강제 + 질문마다 딸린 후속 캐묻기 문구 + 인터뷰 직후 바로 쓸 기록 템플릿(다음 관문 대비물, interview-insights로 넘길 원문 발화 기록 양식)까지 출력 형식에 포함.

## 예측 (라운드 종료 후 DECISION.md에서 실제 승자와 대조)

DNA 이력상 "프레임워크 내장"과 "결합형"이 강세이나, R12·R14·R15·R20처럼 도메인 본질을 정면 겨냥한 방향이 이길 때는 항상 그 도메인의 핵심 실패 원인을 직접 봉쇄하는 구조였다. 이 도메인의 핵심 실패 원인(편향 질문)은 b가 정면으로 겨냥하므로 **b 우세를 예측**한다. domain-fit 누적 성적은 4승 8패로 신뢰도가 낮으므로 결과와 무관하게 반증 기록만 남긴다.
