# 후보 b — 편향 질문·미래 의도 질문을 정면 차단하는 인터뷰 질문지 설계기

## 필드

```json
[
  {"key":"topic","label":"리서치 주제","type":"text","help":"어떤 제품·기능·문제에 대해 알아보려고 하나요","placeholder":"결제 실패 후 재시도율이 낮은 이유"},
  {"key":"target_user","label":"인터뷰 대상","type":"text","help":"누구를 인터뷰하나요? 조건이 구체적일수록 질문이 날카로워집니다","placeholder":"최근 1개월 내 결제 실패를 겪고 재시도하지 않은 온라인 쇼핑몰 이용자"},
  {"key":"hypothesis","label":"검증하고 싶은 가설","type":"textarea","help":"이미 마음속에 있는 답이나 확인하고 싶은 추측을 적어주세요. 이 답이 질문 문장에 새어나가지 않게 통제하는 데 씁니다","placeholder":"결제 실패 화면의 에러 메시지가 불친절해서 사용자가 포기한다고 생각한다"},
  {"key":"research_stage","label":"리서치 단계","type":"select","help":"아직 원인을 못 찾았는지, 이미 정한 방향을 확인하려는지에 따라 질문 방식이 달라집니다","options":["문제 탐색 (아직 원인을 모름)","솔루션 검증 (원인·방향 가설을 확인하려 함)"],"placeholder":"문제 탐색 (아직 원인을 모름)"},
  {"key":"time_limit","label":"인터뷰 예상 시간","type":"select","help":"시간에 맞춰 질문 개수를 조절합니다","options":["15분","30분","1시간"],"placeholder":"30분"},
  {"key":"exclude_topics","label":"다루지 않을 주제","type":"text","optional":true,"help":"이미 답이 정해져 있거나 이번엔 묻지 않을 주제가 있다면","placeholder":"가격 정책은 이미 확정되어 변경 불가, 질문하지 않음"}
```

## 본문

```
# 역할
당신은 스타트업 인터뷰를 수백 건 설계해온 UX 리서처입니다. 창업자나 PM이 그대로 낭독할 수 있는 인터뷰 질문지를 만들어주세요.

# 맥락
- 리서치 주제: {{topic}}
- 인터뷰 대상: {{target_user}}
- 검증하고 싶은 가설 (진행자만 참고, 응답자에게 직접 언급하지 않음): {{hypothesis}}
- 리서치 단계: {{research_stage}}
- 인터뷰 예상 시간: {{time_limit}}
- 다루지 않을 주제: {{exclude_topics}}

# 요구사항
1. 모든 핵심 질문은 미래 가정형("이 기능이 있으면 쓰시겠어요?", "~라면 하실 건가요?")이 아니라, 과거에 실제로 있었던 행동을 캐묻는 형태로 써주세요. 예: "최근에 비슷한 문제를 겪었을 때 실제로 어떻게 하셨나요?"
2. {{hypothesis}}에서 암시하는 답을 질문 문장 안에 직접 넣지 마세요. 질문을 하나 쓸 때마다 "이 질문이 특정 답변 쪽으로 유도하고 있지 않은가?"를 스스로 점검하고, 유도성이 느껴지면 중립적인 표현으로 다시 써주세요.
3. 예/아니오로 끝나는 닫힌 질문은 전체 핵심 질문의 3분의 1을 넘기지 마세요. 핵심 질문마다 "조금 더 자세히 말씀해주시겠어요?", "구체적으로 어떤 상황이었는지 말씀해주실 수 있나요?" 같은 후속 캐묻기 문구를 하나씩 붙여주세요.
4. {{research_stage}}가 "문제 탐색"이면 질문을 열어두고 사용자가 스스로 문제를 정의하게 하고, "솔루션 검증"이면 가설과 관련된 과거 행동을 구체적으로 캐묻되 가설을 정답처럼 제시하지 마세요.
5. {{time_limit}}에 맞춰 질문 개수를 조절해주세요 (15분=핵심질문 3~4개, 30분=5~7개, 1시간=8~10개). 시간 안에 다 못 다룰 것 같으면 우선순위가 낮은 질문에 표시를 해주세요.
6. 라포 형성을 위한 도입 질문 1~2개와, 놓친 것이 없는지 확인하는 마무리 질문 1개를 포함해주세요.

# 출력 형식
## 인터뷰 목적 (진행자 전용, 응답자에게 보여주지 않음)
- 이번 인터뷰로 확인하려는 것을 1~2문장으로

## 도입 질문
- (질문 1~2개, 라포 형성용)

## 핵심 질문
각 질문마다 아래 3줄을 반복:
- 질문: (과거 행동을 캐묻는 문장)
- 후속 캐묻기: (구체화를 유도하는 후속 문구)
- 유도성 자가점검: (이 질문이 답을 암시하는지 스스로 판정한 한 줄. 예: "가설을 언급하지 않고 중립적으로 물음 - 통과" 또는 "OO 표현이 유도성이 있어 XX로 수정함")

## 마무리 질문
- (1개, 놓친 부분 확인용)

## 진행 전 체크리스트
- [ ] 닫힌 질문 비율이 전체 핵심 질문의 1/3 이하인가
- [ ] 어떤 질문도 {{hypothesis}}의 답을 직접 말하고 있지 않은가
- [ ] 각 핵심 질문에 후속 캐묻기가 붙어 있는가
- 다음 행동: 최소 5명 인터뷰 후 답변을 모아 패턴을 정리하세요 (인터뷰 인사이트 분석 템플릿 활용 권장)
```

## 해부

### 역할
> "당신은 스타트업 인터뷰를 수백 건 설계해온 UX 리서처입니다."
직업 하나만 고정하고 목적("낭독할 수 있는 질문지")까지 못 박아, 리서치 방법론 조언이 아니라 바로 쓸 산출물을 만들게 한다.

### 맥락
> "검증하고 싶은 가설 (진행자만 참고, 응답자에게 직접 언급하지 않음): {{hypothesis}}"
이 필드는 이 템플릿의 핵심 장치다. 가설을 빈칸으로 명시적으로 받아두어야만, 요구사항에서 "이 가설이 질문에 새어나갔는지" 대조 검사를 할 근거가 생긴다. 가설을 안 받으면 편향 점검 자체가 불가능해진다.

### 요구사항
> "예: '최근에 비슷한 문제를 겪었을 때 실제로 어떻게 하셨나요?'"
도메인 본질 리스크 1순위인 미래 의도 질문을 완전히 문장 예시로 박아, "행동 중심으로 써주세요" 같은 추상적 지시로 흘리지 않는다. 이어지는 2번 요구사항은 유도성 자가점검을 질문 단위로 의무화해 가설 유출을 실시간으로 차단하고, 3번은 두 번째 리스크인 닫힌 질문·캐묻기 부재를 수치 기준(1/3 이하)과 문구 템플릿으로 봉쇄한다.

### 출력 형식
> "유도성 자가점검: (이 질문이 답을 암시하는지 스스로 판정한 한 줄. 예: '가설을 언급하지 않고 중립적으로 물음 - 통과' 또는 'OO 표현이 유도성이 있어 XX로 수정함')"
자가점검을 요구사항 문장으로만 흘리지 않고 출력 형식에 필수 항목으로 못박아, AI가 실제로 각 질문을 만들 때마다 판정 로그를 남기게 강제한다. 검증 가능한 출력이라 사용자가 "이 질문 괜찮은지"를 다시 검토할 필요 없이 신뢰할 수 있다.

### 출력 형식 — 마무리
> "다음 행동: 최소 5명 인터뷰 후 답변을 모아 패턴을 정리하세요 (인터뷰 인사이트 분석 템플릿 활용 권장)"
행동 착지 원칙에 따라 질문지 자체로 끝내지 않고, 인터뷰 이후 무엇을 해야 하는지와 다운스트림 템플릿(interview-insights)으로의 연결까지 짚어 파이프라인을 완성한다.

## 팁

- {{hypothesis}} 필드는 비워두면 안 된다. 진행자가 확신 없이 막연히 "이유가 궁금하다"고만 적어도, 그 문장 자체를 기준으로 자가점검이 작동하므로 짧게라도 채우게 안내하는 것이 좋다.
- {{exclude_topics}}는 optional이라 값이 비면 맥락의 해당 줄이 통째로 사라지도록 별도 줄에 단독 배치했다 — 요구사항 문장에는 이 토큰을 섞지 않았다.
- research_stage를 "솔루션 검증"으로 고르면 요구사항 4번이 가설 관련 행동을 더 깊게 캐묻도록 방향을 틀어주므로, 신규 가설 탐색과 기능 검증을 같은 질문 톤으로 뭉개지 않는다.
