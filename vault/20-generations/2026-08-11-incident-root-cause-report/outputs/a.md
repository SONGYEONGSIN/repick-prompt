## 전체 결론

**원인 확정.**

v2.14.0 배포(PR #1842, 재고 확인 결과 Redis 캐싱)에서 캐시 키 설계 결함으로 캐시가 사실상 작동하지 않게 되었고, 캐시 미스마다 재고 확인 API를 동기 호출하며 DB 커넥션을 평상시 8배(0.4초→3.2초) 오래 점유해 커넥션 풀(50개)이 소진된 것이 이번 장애의 확정된 인과 사슬입니다. 14:40 v2.14.0 롤백과 동시에 14:45 지표가 완전히 정상 복귀한 것이 이 메커니즘을 직접 뒷받침합니다. 이 메커니즘이 뒷받침하는 즉각 조치로서, **v2.14.0을 롤백된 상태로 유지하고 PR #1842의 캐시 키 설계 결함이 수정·검증되기 전까지 재배포를 보류하는 것**을 지금 승인해 주시기 바랍니다. 다만 DB 인스턴스 전환 작업(후보원인 2)이 장애와 완전히 무관한지는 인프라팀 로그로 아직 검증되지 않았으므로(아래 확인요청 참조), 이 부분과 재발방지 조치(커넥션 풀 확장 vs 캐시 키 재설계)의 최종 선택은 이 결론에 포함하지 않았습니다.

- 처리 용량 감소율: 15.6 ÷ 125 ≈ 12.5% (정상 대비 약 8분의 1 수준으로 급감) — raw의 "정상 시 0.4초 / 장애 시 평균 3.2초" 수치로부터 조사자가 재계산한 값이며, raw에 이 비율이 문장으로 직접 기재되어 있지는 않음.

**판정: 확정 원인** — 시간적 겹침뿐 아니라 "캐시 키 설계 결함 → 캐시 미스 87% → 동기 API 호출로 DB 커넥션 평균 3.2초 점유 → 커넥션 풀(50) 소진 → 5xx/응답지연"까지 각 단계가 원문(APM 트레이스, 모니터링 알림)으로 뒷받침되고, 원인 제거(롤백) 시점과 완전 정상화 시점이 정확히 일치함.
