- "14:22 - 모니터링 알림: 결제 서비스 DB 커넥션 풀 사용량 100% 도달 (풀 사이즈 50)" — 커넥션 점유 시간이 8배로 늘어난 상태에서 동일한 풀 사이즈(50)로는 요청 처리량이 급감해 풀이 고갈되는 것과 일치.
- "14:40 - 한지훈: v2.14.0 롤백 실행" 이후 "14:45 - 모니터링 알림: 에러율 0.3%로 정상 복귀, P95 응답시간 210ms로 복귀" — 원인으로 지목된 배포를 되돌리자 즉시 정상화됨. 인과관계를 강하게 뒷받침.
- "14:31 - 한지훈: 결제 서비스 재시작 실행 (에러율 6.1%→1.8%로 일시 완화)" → "14:36 - 모니터링 알림: 에러율 재상승 (1.8%→34%), DB 커넥션 풀 재차 100% 도달" — 코드(캐시 키 로직)는 그대로 둔 채 프로세스만 재시작했을 때는 일시적 완화에 그치고 동일 로직이 다시 캐시 미스를 유발해 재발함. 코드 결함이 근본 원인이라는 판단과 부합.
- (조사자 계산) 이 시간대 결제 시도 약 2,100건 중 약 710건 실패 → 710 ÷ 2,100 ≈ 33.8%로, raw에 기록된 최대 에러율 34%(14:36 시점)와 근사한 값. 원문에 명시된 계산은 아니며, 실패 건수 대비 시도 건수 비율을 조사자가 계산한 것.

**반박 증거**: raw 증거 내에서 발견되지 않음.

**참고(조사자 해석, raw에 명시적 연결 문장 없음)**: 영향 범위가 "신규 결제 요청 전체(기존 결제 조회는 영향 없음)"인 점은, 재고 확인 로직이 결제 생성(신규 결제) 경로에서만 호출되고 결제 조회 경로에서는 호출되지 않는다는 정황과 일치하는 것으로 보이나, 이를 명시적으로 확인하는 raw 문장은 없어 추정으로 남겨둔다.

**판정: 확정 원인**
(캐시 키 설계 결함 → 캐시 미스율 87% → 동기 호출로 DB 커넥션 평균 3.2초 점유 → 커넥션 풀 100% 소진 → 5xx/응답 지연이라는 메커니즘이 APM 트레이스로 구체적으로 뒷받침되고, 롤백 후 즉시 정상 복귀로 인과관계가 재확인됨)
