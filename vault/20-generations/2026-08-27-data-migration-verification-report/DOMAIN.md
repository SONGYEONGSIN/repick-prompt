# DOMAIN — 데이터 이관 검증 보고서 (R46)

> named query 실행 결과. GENERATE의 방향 풀 설계 직전에 작성.

## 1. 본질 리스크

이 도메인의 산출물이 실패하는 1순위 원인은 **불일치(원본-대상)의 "원인"을 근거 없이 추측해 확정 서술하는 것**이다 — 재고 실사(R45)·데이터 검산(R30)·성능 회귀(R42)에서 반복 관찰된 패턴이 그대로 재현될 위험이 있다. 이관 로그에 원인이 명시돼 있지 않은데도 "네트워크 타임아웃으로 유실된 것으로 보임" 같은 그럴듯한 원인을 만들어 붙이는 유혹이 크다.

두 번째 리스크는 이 도메인에 **고유한 표면**이다 — **"정상적인 변환"과 "진짜 유실·변형"을 가르는 기준(허용 변환 규칙)이 주어지지 않으면 AI가 임의로 정한다.** 이관은 필연적으로 형식 변환(NULL→빈 문자열, 트리밍, 인코딩 정규화, 타입 캐스팅)을 동반하는데, 이런 정상 변환까지 전부 "변형"으로 잡으면 진짜 위험 신호가 노이즈에 묻히고, 반대로 AI가 일반 상식("이 정도는 정상적인 변환이겠지")으로 관대하게 판정하면 진짜 손상을 정상으로 오분류한다 — v1.12(실행 조건은 전용 빈칸으로) 계보가 "허용 변환 규칙"이라는 새 표면에서 재현될 수 있다.

세 번째는 **레코드 단위 대조가 컬럼(필드) 단위 세부를 가릴 수 있다는 것** — 원본·대상 레코드가 "존재"하고 "일치"하는지만 보면, 어느 컬럼이 바뀌었는지·그 컬럼이 금액·개인정보 같은 민감 필드인지가 뭉개진다. 완전 유실/완전 신규 출현(레코드 단위 v1.31 계보)과 부분 변형(컬럼 단위, 이 도메인 고유)은 서로 다른 위험도를 가지므로 같은 등급 라벨로 뭉뚱그리면 안 된다.

네 번째는 **차이 건수·비율 계산 자체의 산술 오류·검산 누락** — 원본 건수와 대상 건수의 차이, 불일치율 계산은 raw 창작 금지의 계산·파생 수치 하위 규칙(v1.9/v1.25)이 정면으로 적용되는 지점이다.

## 2. 본질 루프

"만들면 끝"에 가깝다 — 이관 검증은 특정 시점(컷오버 전후)의 스냅샷 대조다. 다만 **재이관(실패·불일치 레코드만 재처리 후 재검증)**이라는 좁은 재실행 경로는 있다 — R45(재실사)·R43/R41(확인 요청 회신 → 재대조)과 같은 패턴.

## 3. 결과물의 소비 방식

작성자(이관 실행 엔지니어)와 최종 결정권자(컷오버·전환을 승인하는 시스템 오너 또는 PM)가 분리된 감사형 문서 — v1.30 조건(작성자≠결정권자 감사형 도메인)이 그대로 적용된다. 결재자는 "이 이관 결과로 전환해도 되는가"를 짧은 정독으로 판단한다 — 회의체 검토는 아니지만 3초 스캔도 아니다.

## 4. 유사 라운드 전례

가장 가까운 구조는 [[2026-08-26-inventory-physical-count-reconciliation/DECISION|R45]](두 수치 목록 대조, 원인 근거강도 분리, 역방향 스캔, 집계 검산)와 [[2026-08-24-quote-invoice-reconciliation/DECISION|R43]](항목 단위 두 리스트 대조, 서면 근거 vs 구두 확인 구분)이다. 레코드 단위로는 [[2026-08-12-revision-comparison-memo/DECISION|R33]](완전 신설·완전 삭제 등급 고정)과도 구조가 겹친다 — "원본에만 있음(유실)"·"대상에만 있음(예상 밖 신규)"은 R33의 완전 삭제/완전 신설과 동형이다. 다만 **컬럼(필드) 단위 부분 변형**이라는 축은 지금까지 감사 축 10종 어디에도 없었다 — 레코드는 양쪽에 다 있지만 내부 값 일부만 달라지는 경우를 다루는 첫 사례다. 방향 가설 대기열의 유일한 미검증 항목("결정 기준별 1:1 대응 구조" 재검)은 재현 도메인이 명시적으로 **교육 이수 현황 점검표**로 지정돼 있어(backlog 3-1 규칙) 이번 타깃과 맞지 않으므로 소비하지 않고 대기열에 남긴다.

## 5. 방향 풀 추천

- **a. 결합형 표준** — 4요소 + PK(고유식별자) 단위 레코드 카드 대조(원본 존재·대상 존재·값 일치) + 역방향 스캔(대상에만 있는 예상 밖 레코드) + 완전 유실/완전 신규 출현 등급 고정(v1.31 계보) + 계산값 구분 표시(v1.9/v1.25) + 집계 검산(v1.41) + 상단 사실+라우팅형(v1.30). 기존 DNA 스택을 이 도메인에 그대로 이식한 기준선.
- **b. 변환 규칙 사전선언형** — 본질 리스크 2(정상 변환 vs 진짜 유실·변형의 임의 판단)를 정면 겨냥. "정상으로 허용되는 변환 규칙"(예: NULL→빈 문자열, 앞뒤 공백 제거, 전화번호 하이픈 통일)을 전용 필수 빈칸으로 받아, 값 차이가 그 규칙 중 하나로 완전히 설명되면 "정상 변환(규칙 일치)"으로, 규칙에 없는 방식으로 값이 달라졌으면 예외 없이 "변형 의심"으로 고정한다 — 규칙을 빈칸으로 받지 않으면 AI가 일반 기본값("이 정도는 흔한 변환이겠지")으로 관대하게 메꾼다는 게 R45의 임계값 함정과 같은 구조.
- **c. 컬럼 민감도 우선형** — 본질 리스크 3(레코드 단위 대조가 컬럼 단위 세부·민감도를 가림)을 정면 겨냥. 값이 달라진 레코드는 어느 컬럼이 바뀌었는지 컬럼명까지 특정해 명시하고, 민감 필드(금액·개인정보·상태값 등)를 전용 빈칸으로 미리 지정받아 그 필드가 포함된 변형 건은 별도 "우선 검토" 절 최상단에 격상시킨다 — 레코드 단위 등급(일치/유실/신규출현/변형)만으로는 "이름 철자가 하나 바뀐 변형"과 "결제 금액이 바뀐 변형"이 같은 무게로 뭉뚱그려진다는 문제를 겨냥.
