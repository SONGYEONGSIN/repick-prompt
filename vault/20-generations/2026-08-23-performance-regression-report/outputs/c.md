## 신고 항목별 판정 카드

### 1. 박서연 — 전반적 로딩 저하 및 빈도 증가

- 신고 항목(원문): "칸반보드 로딩이 요즘 답답할 정도로 느려요. 예전보다 훨씬 자주 그런 것 같고, 하루에도 몇 번씩 멈칫거려요."
- 기준선 측정치(원문): "P95 응답 320ms, P50 응답 140ms"
- 기준선 측정 조건(원문): "8/4(월) 새벽 배치 성능 테스트... 동시 접속 150세션, 테스트 프로젝트 카드 50개 기준... 브라우저 무관(헤드리스 크롬 자동화 테스트)"
- 현재 측정치(원문): "8/20(목) 오후 2시 재측정 — 기준선과 동일 조건(동시 접속 150세션, 카드 50개)으로 수동 재현: P95 410ms, P50 165ms" (조건 동일 재측정 값 우선 사용)
- 현재 측정 조건(원문): "동시 접속 150세션, 카드 50개... 8/20(목) 오후 2시... 수동 재현"
- 측정 조건 동등성: 동등 (raw에 "기준선과 동일 조건"으로 명시된 재측정 값)
- (계산: P95 320ms→410ms, +28.1% / P50 140ms→165ms, +17.9%)
- 참고: "하루에도 몇 번씩 멈칫거려요", "예전보다 훨씬 자주"와 같은 발생 빈도에 대한 신고는 raw 자료에 빈도를 직접 측정한 수치가 없어 이 판정에서는 확인 불가. 아래 판정은 응답시간 수치에 한정함.
- 최종 판정: **회귀 확인** (동일 조건 재측정에서 P95·P50 모두 기준선 대비 뚜렷이 악화)

### 2. 김도현 — 크롬에서 5초 이상, 사파리는 양호

- 신고 항목(원문): "크롬에서 칸반보드 열면 5초 넘게 걸려요. 근데 사파리에서는 그런대로 괜찮은 것 같아요."
- 기준선 측정치에서 확인되는 관련 수치: 기준선 자료 없음 (기준선은 "브라우저 무관(헤드리스 크롬 자동화 테스트)"으로만 측정되어 크롬-사파리 간 비교값이 존재하지 않음; 참고 원문: "P95 응답 320ms")
- 기준선 측정 조건(원문): "동시 접속 150세션, 테스트 프로젝트 카드 50개 기준... 브라우저 무관(헤드리스 크롬 자동화 테스트)" — 브라우저별 분리 측정 없음
- 현재 측정치(원문): "8/20(목) 오후 재측정 — 브라우저 비교, 동시 접속 150세션·카드 50개 동일 조건: 크롬 P95 430ms, 사파리 P95 415ms. 유의미한 차이 없음."
- 현재 측정 조건(원문): "동시 접속 150세션·카드 50개 동일 조건"
- 측정 조건 동등성: 동등 (크롬-사파리 두 측정치가 raw에 "동일 조건"으로 명시됨; 다만 이 조건에 대응하는 기준선 수치 자체는 없음)
- 최종 판정: **회귀 아님** (조건을 통제한 재측정에서 크롬-사파리 간 유의미한 차이가 확인되지 않아, 신고된 "크롬 특이적" 지연은 서버 응답시간 데이터로는 뒷받침되지 않음. 단, 전반적 응답시간 자체는 항목 1에서 별도로 다룬 회귀와 동일 선상에 있을 수 있음)

### 3. (주)그린테크 — 카드 100개 초과 프로젝트에서만 저하

- 신고 항목(원문): "카드가 100개 넘는 프로젝트에서만 느려요, 작은 프로젝트는 빠른데 이 프로젝트만 그래요."
- 기준선 측정치에서 확인되는 관련 수치: 기준선 자료 없음 (기준선은 "테스트 프로젝트 카드 50개 기준"으로만 측정됨; 참고 원문: "P95 응답 320ms")
- 기준선 측정 조건(원문): "동시 접속 150세션, 테스트 프로젝트 카드 50개 기준"
- 현재 측정치(원문): "8/20(목) 오후 재측정 — 카드 500개 프로젝트, 동시 접속 150세션 동일: P95 1,400ms. (이 카드 수 조건의 기준선 측정치는 없음.)"
- 현재 측정 조건(원문): "카드 500개 프로젝트, 동시 접속 150세션"
- 측정 조건 동등성: 상이 (동시 접속자 수는 150세션으로 일치하나, 카드 수가 기준선 50개 대비 500개로 크게 다름)
- 위 재측정치(P95 1,400ms)는 raw에도 명시되어 있듯 "이 카드 수 조건의 기준선 측정치는 없음" 상태이므로, 이 격차를 회귀의 크기로 서술하지 않음. 카드 100개~500개 구간에서 기준선과 동일 동시접속 조건(150세션)으로 진행된 재측정치는 raw에 없음.
- 최종 판정: **판정 불가(기준선 자료 없음)**

### 4. 이하은 — 저녁 6~8시 시간대 유독 저하

- 신고 항목(원문): "저녁 6시에서 8시 사이에 유독 느려요. 낮에는 괜찮은데."
- 기준선 측정치에서 확인되는 관련 수치: 기준선 자료 없음 (기준선은 "8/4(월) 새벽 배치 성능 테스트"로만 측정되어 저녁 시간대 값이 없음; 참고 원문: "P95 응답 320ms")
- 기준선 측정 조건(원문): "8/4(월) 새벽... 동시 접속 150세션, 테스트 프로젝트 카드 50개 기준"
- 현재 측정치 1(원문, 참고): "8/19(수) 저녁 7시 모니터링: 동시 접속 480세션(이번 주 최고 피크), 카드 목록 API P95 890ms, P50 310ms." — 측정 조건 동등성: 상이 (동시 접속 480세션으로 기준선 150세션과 크게 다름)
- 현재 측정치 2(원문, 조건 동일 재측정 값 우선 사용): "8/20(목) 오후 재측정 — 시간대 비교, 동시 접속 150세션으로 통제: 오후 2시 P95 405ms, 저녁 7시 P95 412ms. 유의미한 차이 없음."
- 현재 측정 조건(원문): "동시 접속 150세션으로 통제"하여 오후 2시와 저녁 7시를 비교
- 측정 조건 동등성: 동등 (동시 접속자 수를 150세션으로 통제한 상태에서 시간대만 비교한 재측정치)
- 최종 판정: **회귀 아님** (동시 접속자 수를 통제한 재측정에서 오후와 저녁 간 유의미한 차이 없음. 8/19 저녁 관측치가 높았던 것은 시간대 자체보다 동시 접속 세션 수 급증(480세션, 평시 대비 약 3배)이라는 조건 차이에 기인한 것으로 보이며, 이는 항목 1의 전반적 회귀와 결합되어 나타난 결과로 판단됨)
