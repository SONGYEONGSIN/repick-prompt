# DECISION — 채용 공고 작성 (R24)

## 후보

- **a** — 결합형 표준: 채용 공고 8단 구조(제목·회사소개·포지션소개·주요업무·자격요건·우대사항·근무조건·전형절차) 내장 + 코치형 help + 위법·차별 조건 정면 필터링(요구사항 3번)을 결합형 표준에 포함.
- **b** — 위법·차별 표현 봉쇄형(도메인 본질 겨냥): 근거 법령명 병기 + 형용사→검증 가능 기준 자동 변환을 승부처로 설계.
- **c** — XML 구조 태그(방향 가설 대기열 소비, a와의 통제쌍): **a와 필드·요구사항·출력형식 내용이 완전히 동일**, 본문의 4요소 경계 표기만 콜론 라벨에서 XML 태그(`<역할>`·`<맥락>`·`<요구사항>`·`<출력형식>`)로 변경.

## AUTO-SCORE — 블라인드 심사 (라틴 방진 3회, 4기준 0~10점 × 3라운드 = 120점 만점)

| 라운드 | 위치 매핑 | 결과 |
|---|---|---|
| 1 | A=a, B=b, C=c | a 36 > c 35 > b 32 |
| 2 | A=b, B=c, C=a | c 39 > a 38 > b 31 |
| 3 | A=c, B=a, C=b | c 38 > a 36 > b 29 |

**합계**: c **112**/120 (2/3 라운드 1위, 최고 총점) · a 110/120 (1/3 라운드 1위) · b 92/120. 세부는 [[2026-08-02-job-posting/SCORES|SCORES.md]] 참고.

DNA 준수 기계 점검: 3후보 모두 4요소 구조 준수, 필드 수 6±3 이내(a 8·b 7·c 8), 전 필드 placeholder 있음, anti-slop 위반 0건. 위법·차별 조건(raw 함정) 누출은 **세 후보 전부 0건** — 대표의 비공식 코멘트를 모두 합법적으로 재구성.

## 판정 — **사람 게이트가 뒤집었다: 승자 a**

> `--auto`는 종합 1위인 **c**(112/120)를 자동 선택했다. **2026-08-04 PR 리뷰에서 사람이 이를 뒤집어 a(110/120)를 승격했다.** 아래 원 서술은 자동 판정 시점의 기록이며 그대로 보존한다.

**뒤집은 근거** — a·c는 XML 태그 유무 외 **완전히 동일한 통제쌍**이다. 그렇다면 판정은 축별로 봐야 한다:

| 축 | a | c | |
|---|---|---|---|
| 지시이행도 (가설이 겨냥한 축) | 30 | 30 | **동점 — 3라운드 전부 10-10, 효과 0** |
| 바로사용가능성 | **27** | 25 | **a 우세** |
| 구체성 | 28 | 28 | 동점 |
| 환각억제 | 25 | 29 | c 우세 |

1. **가설이 겨냥한 축이 전혀 움직이지 않았다.** XML이 지시 이행을 올린다는 주장의 직접 증거가 0이다.
2. **[[backlog]]가 명시한 기각 조건이 성립했다** — "지시 이행이 올라도 바로 사용 가능성이 떨어지면 기각". 실제로는 지시 이행이 **안 올랐고** 사용성은 **떨어졌다**.
3. **c의 2점 우위는 이 라운드 자신이 노이즈로 규정한 축에서 나왔다** — a가 raw에 없는 "성동구"를 덧붙인 실행별 우연 변동. 같은 템플릿이 다음 실행에선 반대로 나올 수 있는 종류의 차이다.
4. 남는 판단 기준은 **형식 일관성**인데, c의 XML 본문은 라이브러리 33종 중 **유일**했다. 본문은 사용자가 복사해 붙여넣는 물건이라 형식 파편화가 그대로 사용자 부담이 된다.

승격본은 후보 a를 직렬화기로 통과시켜 교체했고(본문 4요소 deep-equal, 손편집 0), frontmatter(slug·categoryId·title·description·order)는 필드가 동일하므로 그대로 유지했다.

## LEARN — 지식 정제 게이트

### ① "XML 구조 태그" 방향 가설 — **애매 판정 (DNA 미반영)**

가치 기준 대조:
- ① 재사용 범위 — XML 태그 구조는 모든 도메인에 적용 가능해 범위는 넓다.
- ② 실측 근거 — **약하다.** a/c 통제쌍은 가설이 직접 겨냥한 지표인 **지시이행도에서 3라운드 전부 10 대 10 완전 동점**이었다. 총점 차이(c +2)는 환각억제·구체성 축에서 나왔는데, 이는 a가 raw 범위 밖 "성동구"를 임의로 추가해 감점된 반면 c는 그러지 않은 **실행(생성) 단계의 우연한 변동**이지 구조 표기 방식과 무관하다. 3명의 심사자 중 누구도 XML 구조를 승패 요인으로 지목하지 않았다. 구조적으로도, XML 태그는 모델에 들어가는 입력 프롬프트에만 존재하고 결과물(채용 공고 텍스트) 자체에는 남지 않으므로, 심사자가 그 효과를 직접 관찰할 방법이 애초에 없었다.
- ③ 기존 원칙과의 중복도 — 없음(신규 축이었으나 근거 부족).

→ **DNA에 반영하지 않는다.** R22(완성 예시 동봉)의 애매 판정과 같은 구조 — 통제쌍 자체는 올바르게 설계됐으나(a/c 순수 통제), 이번엔 격차 자체가 가설이 예측한 메커니즘과 무관한 곳에서 나와 "격리된 실측"이 되지 못했다. R23이 완성 예시 가설을 확정할 수 있었던 것은 예시가 결과물에 **가시적으로 반영**되어 심사자가 실제로 그 차이를 관찰·지목할 수 있었기 때문인데, XML 태그는 설계상 결과물에 흔적을 남기지 않아 이 방식의 통제쌍 검증 자체가 구조적으로 약한 신호만 만들어낸다는 점을 이번 라운드가 보여준다.

**정제 질문** (충돌은 아니나 애매 판정에 따라 기록): XML 구조 태그의 효과를 검증하려면, 결과물이 아니라 **모델이 프롬프트를 얼마나 정확히 파싱했는지 자체**(예: 요구사항 8개 항목의 누락률, 필드 순서 준수 실패율처럼 지시이행도를 더 세밀하게 나누는 지표)를 봐야 할 수 있다. 현재처럼 "결과물 품질"만 보는 블라인드 심사로는, 눈에 보이지 않는 입력 구조 변화의 순효과를 격리하기 어렵다는 것이 이번 라운드의 방법론적 교훈이다. 이 가설은 backlog에서 애매 판정으로 종결하고(재검 대기열에 다시 넣지 않음), 향후 유사한 "입력 전용 구조 변화" 가설은 결과물 대신 지시 이행 세부 실패율을 측정하는 방식으로 검증법을 바꿀 것을 다음 라운드 설계자에게 제안한다.

### ② raw에 없는 세부 창작 금지 — **강화 (기존 원칙 재확인, 신규 도메인)**

후보 b는 raw에 없는 "입사 전 최소 근무 기간에 대한 협의가 가능하신 분"이라는 요건을 스스로 창작해 3라운드 전부 심사자에게 지적받아 최하위(92/120)로 밀렸다. 이는 기존 원칙(v1.9, raw에 없는 구체적 세부를 만들어내지 않는다)이 채용 공고(고용주 관점) 도메인에서도 그대로 유효함을 보여주는 재현 사례다.

가치 기준: ① 재사용 범위 — 기존 원칙과 동일 축. ② 실측 근거 — 3라운드 전부 재현. ③ 기존 원칙과의 중복도 — 완전히 동일한 축·방향.

→ 새 항목을 추가하지 않고, 기존 원칙에 근거 라운드(R24)만 추가한다.

### ③ 위법·차별 조건 필터링 — **관찰 메모 (DNA 미반영, 변별력 없음)**

이 라운드가 원래 겨냥했던 도메인 본질 리스크(채용절차법·남녀고용평등법 위반 조건이 raw에 섞이는 함정)는 세 후보 모두 완벽하게 막아냈다(누출 0건, R21의 "이미 잘 봉쇄된 리스크는 변별력을 잃는다" 패턴 재현). b가 이 리스크를 정면 겨냥해 설계됐음에도 a·c와 차별화되지 못한 것은, product-detail-page(R8)·cs-reply(R7) 이후 누적된 "명시 봉쇄 + 대안" 원칙이 이미 충분히 일반화되어 있어 별도 강화가 불필요함을 시사한다. DNA에는 반영하지 않는다(기존 "실행 여건 불가능 요구 명시 봉쇄" 원칙이 이미 충분히 포괄).

## DOMAIN.md 예측 대조

DOMAIN.md는 b(위법·차별 표현 봉쇄형, 도메인 본질 겨냥)가 우세할 것으로 예측했다. 실제로는 a/c(결합형 표준 계열)가 1·2위를 차지하고 b가 3위로 밀렸다 — **빗나감** (domain-fit 예측 누적 4승 7패). b가 정면 겨냥한 위법·차별 리스크를 a·c도 동일하게 잘 막아내 차별화 요인이 되지 못했고, 오히려 b 자신의 결함(raw 밖 요건 창작)이 감점 요인이 됐다.

## 채택 여부

- `--auto` 모드로 종합 1위 c를 자동 채택해 라이브러리에 승격한다. 사용자가 이 판단(특히 a/c 격차가 노이즈 수준이라는 위 분석)을 검토해 뒤집을 수 있다.
- ledger에는 실제 벌어진 일(라틴 방진 2/3 1위, 최고 총점 c 승, a와 근소 격차) 그대로 기록하고, principle_delta는 위 ②(raw 창작 금지 강화)로 남긴다. XML 태그 가설은 애매 판정이라 principle_delta에 포함하지 않는다.
