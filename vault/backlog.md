# 진화 백로그 — 타깃 대기열

자동 라운드(`/prompt-evolve --auto`)가 소비하는 타깃 작업 대기열 + 후보 설계 방향 가설.

## 소비 규칙

0. **선행 가드 (라운드 시작 전 필수)**: 열린 `evolve/*` PR이 있으면 새 라운드를 시작하지 않는다 — 미머지 PR은 백로그를 갱신하지 못해 다음 라운드가 같은 타깃을 중복 집는다 (R14가 R11 미머지분과 같은 타깃 반복한 사고). 아래 질의 결과가 `0`이어야 진행하고, 아니면 "직전 라운드 PR 미처리"만 보고하고 종료.

   ```
   gh pr list --state open --json headRefName --jq '[.[] | select(.headRefName | startswith("evolve/"))] | length'
   ```

   **`gh pr list --head 'evolve/'` 를 쓰지 마라** — `--head`는 접두사가 아니라 정확한 브랜치명을 받는다. `evolve/*` PR 8건이 실재하는 상태에서 `0`을 반환하는 것을 실측 확인했다(2026-07-31). 이 가드는 도입 이후 줄곧 무력했다.
1. 위에서부터 첫 번째 미완료(`- [ ]`) 항목을 꺼내 `$TARGET`으로 사용한다.
2. 라운드 완료 시 해당 항목을 `- [x]`로 바꾸고 뒤에 ` → <run-slug> (R<n>)`을 덧붙인다.
3. 새 타깃은 맨 아래에 추가한다 (우선순위가 높으면 위로).
4. 대기열이 비면 라운드를 돌지 않고 "백로그 소진"만 보고한다 — 임의 타깃 생성 금지.

## 방향 가설 (GENERATE 소비)

라운드의 후보 $N개 중 1개의 설계 방향으로 배정해 검증하는 가설 대기열 (라운드당 1개). 검증 완료 시 `- [x]`로 바꾸고 ` → <run-slug> (R<n>, 순위/채택 여부)`를 덧붙인다. 외부 지식은 여기서 실측을 거쳐야만 DNA에 오를 수 있다 (LEARN 게이트의 실측 근거 요건).

- [x] **요구사항에 이유 병기** — 템플릿의 요구사항 문장마다 "왜"를 붙인다. 근거: Claude 플랫폼 문서 General principles "Add context to improve performance". → 2026-07-15-cold-email-reason-ab (승격, DNA v1.8 + 라이브러리 18종 소급)
  - 1차 검증: [[2026-07-15-cs-reply-reason-ab/DECISION|R7 챔피언 A/B]] — 무승부(39 vs 38, 교차 불일치)로 판정 불충분 (천장 효과: 대조군에 이미 이유 존재). 정성 신호 2건은 가설 지지.
  - 재검: [[2026-07-15-cold-email-reason-ab/DECISION|R1 챔피언 A/B]] — 보정 후 근소 우세 + 설득 핵심 3차원 교차 일치 + 기제 신호 누적 5건 → 휴먼 게이트 승인, 승격.

- [x] **완성 예시 동봉 (multishot)** — 템플릿 본문에 짧은 **결과물 완성 예시** 1~2개를 내장한다. 근거: Anthropic 프롬프트 엔지니어링 문서의 "Use examples (multishot prompting)" — 예시가 출력 형식·톤의 일관성을 올린다. → 2026-07-31-service-faq (R22, 1위/애매·미실증 — 아래 참고)
  - **1차 검증 결과**: 예시를 내장한 후보(c)가 라틴 방진 3심 만장일치 1위(103/120)로 승리했으나, [[2026-07-31-service-faq/DECISION|R22 DECISION]]에서 3심 전원이 승리 이유로 지목한 것은 환각·과장 억제(정책 밖 질문 미창작)와 부속 메모 배제였고 **예시 자체는 아무도 언급하지 않았다**. 승자가 예시 유무 외에도 "창작 허용 여부"·"부속 메모 유무"까지 통제군과 달라 변인이 셋 섞여 순효과를 분리할 수 없었다 — 지식 정제 게이트에서 **애매 판정, DNA 미반영**.
  - **반대 가설(기각 조건)**: 완성 예시가 산출물을 예시 쪽으로 끌어당겨 사용자 맥락 반영을 떨어뜨린다("예시 복제"). 실데이터 필수 빈칸([[2026-07-12-prototype/DECISION|R2]])이 막으려던 것과 같은 실패가 다른 경로로 재현되면 기각. → R22에서는 예시 복제 현상은 관찰되지 않음(기각도 성립하지 않음, 판정 불가일 뿐).
  - **재검이 필요하다 (다음 라운드가 소비할 새 항목)**: 통제군과 예시 유무 **하나만** 다르게 고정할 것 — 둘 다 "실제 문의만 다루고 창작 금지 + 부속 메모(셀프체크·업데이트후보) 없음"인 결합형 표준을 베이스로 삼고, 한쪽에만 완성 예시를 추가해서 비교한다.

- [x] **완성 예시 동봉 — 통제 재검** (위 R22 애매 판정의 재검) — 베이스 조건(창작 금지·부속 메모 없음)을 두 후보 모두 동일하게 고정하고, 예시 유무만 다르게 해서 순효과를 분리한다. 심사에서는 예시와 다른 맥락을 준 시나리오로 돌려 예시 복제 여부도 함께 본다. → 2026-08-01-press-release (R23, 채택·DNA v1.21 승격) — a(결합형 표준)와 c(a+예시)를 예시 유무만 다르게 고정, 라틴 방진 3라운드 전부에서 c가 a를 앞서 순효과 격리 확인. 예시 복제 현상은 관찰되지 않음(기각 조건 불성립).

- [x] **XML 구조 태그** — 4요소를 마크다운 헤딩 대신 XML 태그(`<역할>`·`<맥락>`…)로 감싼다. 근거: Anthropic 프롬프트 엔지니어링 문서의 "Use XML tags to structure your prompts" — 섹션 경계가 명확해져 지시 이행이 올라간다. → 2026-08-02-job-posting (R24, **기각** — 사람 게이트가 자동 판정을 뒤집었다, 아래 참고)
  - **반대 가설(기각 조건)**: 이 템플릿들은 **초보자가 눈으로 읽고 빈칸을 채운 뒤 그대로 붙여넣는** 물건이다. XML은 "내가 뭘 붙여넣는지 모르겠다"는 인상을 줘 anti-slop의 "초보자가 채울 수 없는 전문용어 라벨" 정신과 충돌할 수 있다. 지시 이행이 올라도 **바로 사용 가능성**이 떨어지면 기각.
  - 검증법: 지시 이행도와 바로 사용 가능성 두 축의 **방향이 갈리는지**를 본다. 둘 다 오르면 승격, 상충하면 도메인 조건부로 기록.
  - **검증 결과**: a(결합형 표준)와 c(a와 필드·요구사항 완전 동일, XML 태그 구조만 다름) 통제쌍을 라틴 방진 3회로 비교. c가 총점에서 근소 우세(112 vs 110)했으나, **가설이 직접 겨냥한 지시이행도 축은 3라운드 전부 10 대 10 완전 동점**으로 전혀 움직이지 않았다. 총점 차이는 raw 범위 밖 "성동구" 추가 유무 같은 무관한 축(환각억제)의 실행별 변동에서 나왔고, 어느 심사자도 XML 구조를 승패 요인으로 지목하지 않았다 — [[2026-08-02-job-posting/DECISION|R24 DECISION]]에서 **애매 판정, DNA 미반영**. 반대 가설(바로 사용 가능성 하락)도 성립하지 않았다(두 축 다 유의미하게 갈리지 않음, 사실상 무효과에 가까움). 방법론 관찰: XML 태그는 입력 프롬프트에만 존재하고 결과물에는 흔적을 남기지 않도록 설계했으므로, 결과물 품질만 보는 블라인드 심사로는 이런 "입력 전용 구조 변화"의 순효과를 애초에 관찰하기 어렵다 — 이 가설은 재검 대기열에 다시 넣지 않고 종결한다.
  - **사람 게이트 판정 (2026-08-04) — 기각**: 위 "반대 가설도 성립하지 않았다"는 서술을 축별 합산으로 재확인하니 사실과 달랐다. **바로사용가능성 a 27 vs c 25**(라운드 1에서 9 대 7)로 c가 낮다. 즉 ① 겨냥한 축은 효과 0, ② 기각 조건 축은 **하락**, ③ 총점 2점 우위는 라운드 자신이 노이즈로 규정한 축에서 발생. 세 가지가 겹쳐 기각하고, 승격본을 후보 a로 교체했다([[2026-08-02-job-posting/DECISION|R24 DECISION]]). XML 본문은 라이브러리 33종 중 유일했고 본문은 사용자가 복사해 붙여넣는 물건이라 형식 파편화가 그대로 부담이 된다.
  - **남는 방법론 교훈** (가설과 무관하게 유효): 입력 프롬프트에만 존재하고 결과물에 흔적을 남기지 않는 구조 변경은, 결과물만 보는 블라인드 심사로 순효과를 관찰할 수 없다. **이런 부류의 가설은 애초에 이 루프의 측정 대상이 아니다** — 다음에 비슷한 가설을 큐에 넣기 전에 "결과물에 흔적이 남는가"를 먼저 물어야 한다.
