# 진화 백로그 — 타깃 대기열

자동 라운드(`/prompt-evolve --auto`)가 소비하는 타깃 작업 대기열 + 후보 설계 방향 가설.

## 소비 규칙

0. **선행 가드 (라운드 시작 전 필수)**: 열린 `evolve/*` PR이 있으면 새 라운드를 시작하지 않는다 — 미머지 PR은 백로그를 갱신하지 못해 다음 라운드가 같은 타깃을 중복 집는다 (R14가 R11 미머지분과 같은 타깃 반복한 사고). 아래 질의 결과가 `0`이어야 진행하고, 아니면 "직전 라운드 PR 미처리"만 보고하고 종료.

   ```
   gh pr list --state open --json headRefName --jq '[.[] | select(.headRefName | startswith("evolve/"))] | length'
   ```

   **`gh pr list --head 'evolve/'` 를 쓰지 마라** — `--head`는 접두사가 아니라 정확한 브랜치명을 받는다. `evolve/*` PR 8건이 실재하는 상태에서 `0`을 반환하는 것을 실측 확인했다(2026-07-31). 이 가드는 도입 이후 줄곧 무력했다.
1. 위에서부터 첫 번째 미완료(`- [ ]`) 항목을 꺼내 `$TARGET`으로 사용한다.
2. 라운드 완료 시 해당 항목을 `- [x]`로 바꾸고 뒤에 ` → <run-slug> (R<n>)`을 덧붙인다.
3. 새 타깃은 맨 아래에 추가한다 (우선순위가 높으면 위로).
4. 대기열이 비면 라운드를 돌지 않고 "백로그 소진"만 보고한다 — 임의 타깃 생성 금지.

## 방향 가설 (GENERATE 소비)

라운드의 후보 $N개 중 1개의 설계 방향으로 배정해 검증하는 가설 대기열 (라운드당 1개). 검증 완료 시 `- [x]`로 바꾸고 ` → <run-slug> (R<n>, 순위/채택 여부)`를 덧붙인다. 외부 지식은 여기서 실측을 거쳐야만 DNA에 오를 수 있다 (LEARN 게이트의 실측 근거 요건).

- [x] **요구사항에 이유 병기** — 템플릿의 요구사항 문장마다 "왜"를 붙인다. 근거: Claude 플랫폼 문서 General principles "Add context to improve performance". → 2026-07-15-cold-email-reason-ab (승격, DNA v1.8 + 라이브러리 18종 소급)
  - 1차 검증: [[2026-07-15-cs-reply-reason-ab/DECISION|R7 챔피언 A/B]] — 무승부(39 vs 38, 교차 불일치)로 판정 불충분 (천장 효과: 대조군에 이미 이유 존재). 정성 신호 2건은 가설 지지.
  - 재검: [[2026-07-15-cold-email-reason-ab/DECISION|R1 챔피언 A/B]] — 보정 후 근소 우세 + 설득 핵심 3차원 교차 일치 + 기제 신호 누적 5건 → 휴먼 게이트 승인, 승격.

- [ ] **완성 예시 동봉 (multishot)** — 템플릿 본문에 짧은 **결과물 완성 예시** 1~2개를 내장한다. 근거: Anthropic 프롬프트 엔지니어링 문서의 "Use examples (multishot prompting)" — 예시가 출력 형식·톤의 일관성을 올린다.
  - **현 DNA와의 층위 차이**: DNA는 "모든 필드에 실전 예시 placeholder"를 요구하지만 그건 **입력 가이드**다. 결과물이 어떤 모습이어야 하는지 보여주는 **출력 예시**는 어디에도 없다.
  - **반대 가설(기각 조건)**: 완성 예시가 산출물을 예시 쪽으로 끌어당겨 사용자 맥락 반영을 떨어뜨린다("예시 복제"). 실데이터 필수 빈칸([[2026-07-12-prototype/DECISION|R2]])이 막으려던 것과 같은 실패가 다른 경로로 재현되면 기각.
  - 검증법: 후보 1개에만 완성 예시를 내장하고 나머지는 현행. 심사에서 **예시와 다른 맥락을 준 시나리오**로 돌려 예시 복제 여부를 본다.

- [ ] **XML 구조 태그** — 4요소를 마크다운 헤딩 대신 XML 태그(`<역할>`·`<맥락>`…)로 감싼다. 근거: Anthropic 프롬프트 엔지니어링 문서의 "Use XML tags to structure your prompts" — 섹션 경계가 명확해져 지시 이행이 올라간다.
  - **반대 가설(기각 조건)**: 이 템플릿들은 **초보자가 눈으로 읽고 빈칸을 채운 뒤 그대로 붙여넣는** 물건이다. XML은 "내가 뭘 붙여넣는지 모르겠다"는 인상을 줘 anti-slop의 "초보자가 채울 수 없는 전문용어 라벨" 정신과 충돌할 수 있다. 지시 이행이 올라도 **바로 사용 가능성**이 떨어지면 기각.
  - 검증법: 지시 이행도와 바로 사용 가능성 두 축의 **방향이 갈리는지**를 본다. 둘 다 오르면 승격, 상충하면 도메인 조건부로 기록.
