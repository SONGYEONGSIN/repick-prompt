# 고객 인터뷰 인사이트 분석 — 씨앗 프롬프트

- 카테고리: 분석
- 출처: 사용자 제공 검증 프롬프트 (라이브러리 slug: `interview-insights`)
- 요약: 고객 인터뷰 기록을 넣으면 불편, 동기, 반복 패턴, 개선 기회를 제품팀 관점으로 정리합니다.

## 구조 강점
- **역할** — 결과를 소비할 사람(PM·리서처)을 역할에 박아두면, 그들이 쓰는 프레임(Pain Point, 트리거)으로 정리됩니다.
- **맥락** — 목적('온보딩 이탈 원인')이 분석의 렌즈가 됩니다. 목적 없이 넣으면 뻔한 요약만 나옵니다.
- **분석 기준** — 인용을 요구하면 AI가 지어내기 어려워집니다. 근거 요구는 환각을 줄이는 가장 쉬운 장치입니다.
- **출력 형식** — 분석이 '흥미로운 발견'에서 끝나지 않고 다음 주 실험으로 착지합니다.

## 본문

```
당신은 PM과 UX 리서처를 돕는 분석가입니다.

아래 고객 인터뷰 내용을 바탕으로 핵심 인사이트를 정리해주세요.
- 제품/서비스명: {{product}}
- 인터뷰 목적: {{purpose}}
- 대상 고객: {{target}}
- 인터뷰 기록: {{transcript}}

분석 기준:
1. 고객이 직접 말한 불편과 암묵적으로 드러난 불편을 구분해주세요.
2. 반복적으로 등장하는 패턴을 찾아 빈도와 함께 정리해주세요.
3. 구매/사용을 촉진하는 요인과 방해하는 요인을 나눠주세요.
4. 제품팀이 바로 검토할 수 있는 개선 기회를 우선순위 순으로 제안해주세요.
5. 가능한 경우 근거가 되는 원문 표현을 짧게 인용해주세요.

출력 형식:
- 핵심 인사이트 요약
- 주요 Pain Point
- 동기/트리거
- 반복 패턴
- 개선 기회 우선순위
- 제품팀이 다음 주에 바로 확인할 실험 아이디어 3개
```
