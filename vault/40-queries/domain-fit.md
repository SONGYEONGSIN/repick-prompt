# Named Query — 도메인 본질 분석 (방향 풀 설계 전)

> Karpathy LLM wiki 패턴의 named query 채택 1호. 근거: [[2026-07-17-marketing-email/DECISION|R12]] — 결합형 4연승이 "측정이 본질인 도메인"에서 실험 문법 방향에 패배 → 방향 풀은 도메인 본질에서 도출해야 한다.
> **실행 시점**: GENERATE의 방향 풀 설계 직전. **답변 저장**: run 폴더 `DOMAIN.md` (좋은 답변은 휘발시키지 않고 위키에 축적한다).

## 질의

타깃 작업 "$TARGET"에 대해 DNA·ledger·MEMORY를 근거로 답하라:

1. **본질 리스크** — 이 도메인 결과물이 실패하는 1순위 원인은 무엇인가? (예: 이메일 마케팅=욕심/다목표, 이력서=과장, CS=정책 밖 약속)
2. **본질 루프** — 이 도메인은 "만들면 끝"인가, "만든 뒤 측정·반복"이 본질인가? 측정이 본질이면 실험 문법(지표·판정·후속)이 방향 후보에 필수.
3. **결과물의 소비 방식** — 누가, 어떤 채널·시간 예산으로 소비하는가? (3초 스캔? 정독? 결재?)
4. **유사 라운드 전례** — ledger·MEMORY에서 구조가 가장 가까운 라운드와 그 승부처는?
5. **방향 풀 추천** — 위 1~4에서 도출한 서로 다른 설계 방향 3개 (결합형 표준은 기본 포함하되, 본질 리스크·루프를 정면으로 겨냥한 방향 1개 이상 필수).

## 축적 규칙

- 라운드 종료 후 DOMAIN.md의 예측(방향 풀 추천)이 실제 승자와 맞았는지 DECISION.md에 1줄 대조 — 이 질의 템플릿 자체도 반증 대상이다.
