# 신규 서비스 아이디어 발상

씨앗 — 사용자 제공 검증 프롬프트

## 본문

```
당신은 스타트업 아이디어를 검토하는 제품 전략가입니다.

아래 조건을 바탕으로 신규 서비스 아이디어를 제안해주세요.
- 타깃 고객: {{target}}
- 해결하고 싶은 문제: {{problem}}
- 활용 가능한 자원: {{resources}}
- 원하는 비즈니스 모델: {{business_model}}
- 제외하고 싶은 방향: {{exclude}}

요구사항:
1. 단순 나열 말고 실현 가능성이 있는 아이디어 위주로 제안해주세요. 자원과 제약을 무시한 아이디어는 아무리 많아도 실제로 착수할 수 없어 쓸모가 없기 때문입니다.
2. 각 아이디어마다 고객이 돈을 낼 이유를 분명히 써주세요. 사람들이 좋아하는 것과 돈을 내는 것은 다르고, 지불 의사가 없으면 사업이 아니라 취미로 끝나기 때문입니다.
3. 차별화 포인트와 초기 MVP 범위를 함께 제시해주세요. 차별화 없는 아이디어는 기존 제품에 밀리고, MVP 범위가 없으면 첫 삽을 어디서 뜰지 몰라 실행이 미뤄지기 때문입니다.
4. 리스크와 검증해야 할 가정도 같이 적어주세요. 아이디어의 성패는 숨은 가정에 달려 있고, 그걸 먼저 드러내야 큰돈을 쓰기 전에 값싸게 검증할 수 있기 때문입니다.
5. 가장 유망한 아이디어 1개는 실행 순서까지 더 자세히 설명해주세요. 유망한 아이디어라도 첫 주에 뭘 할지 모르면 결국 실행되지 않고, 순서가 있어야 오늘 바로 움직일 수 있기 때문입니다.

출력 형식:
- 아이디어 7개
- 각 아이디어별 문제/해결 방식/차별화/수익화/MVP/리스크
- 가장 유망한 아이디어 1개 상세안
- 다음 주에 검증할 실험 3개
```

## 해부

### 역할

> 스타트업 아이디어를 검토하는 제품 전략가

'검토하는'이 핵심입니다. 아이디어를 뿜는 역할이 아니라 걸러내는 역할을 주면 실현 가능성 중심으로 답합니다.

### 맥락

> 타깃 / 문제 / 자원 / 비즈니스 모델 / 제외 방향

제약 조건(자원, 제외 방향)이 있어야 뜬구름 아이디어가 걸러집니다. 제약이 창의성을 만듭니다.

### 요구사항

> 돈을 낼 이유 / MVP 범위 / 검증할 가정

아이디어의 품질 기준을 '재미'가 아니라 '지불 의사'로 고정합니다.

### 출력 형식

> 아이디어 7개 / 상세안 1개 / 다음 주 실험 3개

발산(7개) → 수렴(1개) → 행동(실험 3개)의 깔때기 구조로, 읽고 끝나는 게 아니라 실행으로 이어집니다.

## 팁

- 7개 중 끌리는 아이디어가 있으면 "3번 아이디어의 경쟁 서비스를 조사하고 차별화 각도를 다시 잡아줘"로 파고드세요.
- 문제 칸에는 '누가 + 언제 + 얼마나 자주' 겪는 문제인지까지 쓰면 훨씬 정교한 답이 나옵니다.
