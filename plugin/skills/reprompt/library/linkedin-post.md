# 링크드인 게시물 작성

씨앗 — 사용자 제공 검증 프롬프트

## 필드

```json
[
  {
    "key": "topic",
    "label": "주제",
    "type": "text",
    "placeholder": "예: 첫 이직에서 배운 협상의 기술"
  },
  {
    "key": "message",
    "label": "핵심 메시지",
    "type": "text",
    "help": "독자가 이 글에서 딱 하나 기억할 문장.",
    "placeholder": "예: 연봉 협상은 정보 싸움이다"
  },
  {
    "key": "reader",
    "label": "독자",
    "type": "select",
    "options": [
      "스타트업 대표",
      "마케터",

      "채용담당자"
    ]
  },
  {
    "key": "mood",
    "label": "원하는 분위기",
    "type": "select",
    "options": [
      "전문적",

      "친근함"
    ]
  },
  {
    "key": "case",
    "label": "넣고 싶은 사례 또는 데이터",
    "type": "textarea",

    "help": "구체적 숫자·경험이 있으면 글의 신뢰도가 크게 올라갑니다.",

    "label": "CTA",

    ],
    "help": "글을 읽은 사람이 다음에 할 행동."
  }

```

## 본문

```
당신은 B2B 퍼스널 브랜딩 에디터입니다.

아래 정보를 바탕으로 링크드인 게시물을 작성해주세요.
- 주제: {{topic}}
- 핵심 메시지: {{message}}
- 독자: {{reader}}
- 원하는 분위기: {{mood}}
- 넣고 싶은 사례 또는 데이터: {{case}}
- CTA: {{cta}}

요구사항:
1. 첫 2줄 안에 시선을 끄는 훅을 써주세요. 링크드인 피드는 '더보기'로 접히기 전 첫 2줄만 보이고, 그 두 줄에서 펼쳐 읽을지가 갈리기 때문입니다.
2. 문단은 모바일에서 읽기 쉽게 짧게 나눠주세요. 대부분 모바일 피드를 빠르게 넘기며 읽어서, 빽빽한 문단은 그 자리에서 건너뛰어지기 때문입니다.
3. 지나치게 자기과시적으로 쓰지 말고, 경험에서 배운 점이 드러나게 써주세요. 자랑은 방어적으로 읽혀 공유를 막지만, 배운 점은 독자가 자기 일에 대입해 저장하고 나누게 만들기 때문입니다.
4. CTA가 '없음'이 아니면 마지막에 자연스럽게 붙이고, '없음'이면 여운이 남는 마무리 문장으로 끝내주세요. 공감한 독자에게 다음 행동을 분명히 청하지 않으면 그 관심이 그대로 흩어지기 때문입니다.
5. 해시태그는 3개만 제안해주세요. 해시태그가 지나치게 많으면 스팸성 글로 보여 전문가다운 게시물의 인상을 해치기 때문입니다.

출력 형식:
- 훅 3개
- 최종 게시물 1개
- 추천 해시태그 3개
```

## 해부

### 역할

> 당신은 B2B 퍼스널 브랜딩 에디터입니다.

'에디터'라는 역할이 자기과시를 걸러내고 독자 관점의 편집을 하게 만듭니다.

### 맥락

> 주제 / 핵심 메시지 / 독자 / 분위기 / 사례

핵심 메시지를 한 문장으로 먼저 정하면 글 전체가 그 문장을 증명하는 구조가 됩니다.

### 요구사항

> 첫 2줄 훅 / 모바일 문단 / 자기과시 금지

링크드인은 '더보기' 접힘 전 2줄이 승부처입니다. 플랫폼 특성을 요구사항으로 명시하면 매체에 맞는 글이 나옵니다.

### 출력 형식

> 훅 3개 / 최종 게시물 1개 / 해시태그 3개

훅을 복수로 받으면 가장 강한 것을 고를 수 있습니다. 선택지를 받는 것도 프롬프트 기술입니다.

## 팁

- 본인이 실제로 쓴 글 하나를 붙여넣고 "이 문체를 유지해줘"라고 하면 내 목소리가 살아납니다.
- 훅 3개 중 마음에 드는 게 없으면 "더 구체적인 숫자로 시작하는 훅으로"라고 재요청하세요.
