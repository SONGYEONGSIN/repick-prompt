# 회의록 요약 및 액션 아이템 정리

씨앗 — 사용자 제공 검증 프롬프트

## 필드

```json
[
  {
    "key": "purpose",
    "label": "회의 목적",
    "type": "text",
    "placeholder": "예: 3분기 신규 기능 우선순위 결정"
  },
  {
    "key": "attendees",
    "label": "참석자",
    "type": "text",
    "optional": true,
    "help": "이름·역할을 적으면 액션 아이템에 담당자가 매핑됩니다.",
    "placeholder": "예: 김PM, 이디자인, 박개발"
  },
  {
    "key": "content",
    "label": "회의 내용",
    "type": "textarea",
    "help": "녹취록, 메모, 채팅 로그 무엇이든 그대로 붙여넣으세요.",
    "placeholder": "회의록 또는 녹취록 전체를 붙여넣기"
  }
]
```

## 본문

```
당신은 프로젝트 매니저를 돕는 운영 어시스턴트입니다.

아래 회의 내용을 읽고 실무자가 바로 공유할 수 있는 형태로 정리해주세요.
- 회의 목적: {{purpose}}
- 참석자: {{attendees}}
- 회의 내용: {{content}}

정리 기준:
1. 핵심 요약은 5줄 이내로 써주세요. 회의록은 참석하지 않은 사람이 빠르게 훑어보려고 여는데, 길면 아무도 읽지 않아 공유 자체가 무의미해지기 때문입니다.
2. 결정된 사항과 아직 미결인 사항을 분리해주세요. 회의록 사고의 대부분은 '얘기만 나온 것'을 '정해진 것'으로 오해하는 데서 나오기 때문입니다.
3. 액션 아이템은 담당자, 해야 할 일, 마감일이 보이면 함께 정리해주세요. 담당자와 기한이 빠진 할 일은 아무도 자기 일로 여기지 않아 다음 회의까지 그대로 남기 때문입니다.
4. 회의 중 나온 리스크나 우려사항이 있으면 따로 표시해주세요. 흘려 언급된 우려는 본문에 묻히면 놓쳐졌다가 나중에 문제로 터지기 때문입니다.
5. 문장은 간결하게 쓰고, 중복 설명은 제거해주세요. 늘어지는 회의록은 정작 중요한 결정과 할 일을 가려, 읽는 사람이 핵심을 놓치기 때문입니다.

출력 형식:
- 한 줄 요약
- 핵심 논의 3~5개
- 결정 사항
- 액션 아이템 표
- 미결 이슈
- 리스크/주의사항
```

## 해부

### 역할

> 프로젝트 매니저를 돕는 운영 어시스턴트

'실무자가 바로 공유할 수 있는 형태'라는 사용 목적과 역할이 맞물려, 감상문이 아닌 공유용 문서가 나옵니다.

### 맥락

> 회의 목적 + 원문 전체

목적을 먼저 알려주면 AI가 무엇이 '핵심'인지 판단하는 기준이 생깁니다. 같은 회의도 목적에 따라 요약이 달라집니다.

### 정리 기준

> 결정 vs 미결 분리 / 담당자·마감일 / 리스크 별도 표시

회의록 정리의 실패는 대부분 '결정된 것'과 '얘기만 나온 것'이 섞이는 데서 옵니다. 분리를 명시적으로 요구합니다.

### 출력 형식

> 한 줄 요약 → 논의 → 결정 → 액션 표 → 미결 → 리스크

읽는 사람의 시간 순서(바쁘면 첫 줄만, 실무자는 액션 표만)에 맞춘 역피라미드 구조입니다.

## 팁

- 녹취록이 아주 길면 나눠 넣고 마지막에 "지금까지 정리한 것을 하나로 합쳐줘"라고 하세요.
- 정리 결과를 받은 뒤 "이 중 마감일이 없는 액션 아이템에 제안 마감일을 붙여줘"라고 하면 후속 관리가 쉬워집니다.
